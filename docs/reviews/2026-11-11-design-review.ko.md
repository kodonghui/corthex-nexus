# 2026-11-11 설계 검토와 설계 수정

[English](2026-11-11-design-review.md)

이 파일은 NEXUS 설계 전체의 독립 검토와 그것에 답하는 수정의 공개 지도입니다. 이 번역과 영어 원문이 다르면 영어 원문이 원본입니다.

## 검토가 무엇이었나

2026-11-11에 관리자가 더 만들기 전에 NEXUS 설계 전체를 독립적으로 검토해 달라고 요청했습니다. 먼저 설계 자체가 맞는지, 그다음 하네스 규칙을 따랐는지와 만든 것이 어떤지를 보는 검토였습니다. 검토는 다시 디자인 PR의 맨 끝(커밋 `fa4f042`)에서 모든 단계 문서를 읽고, 저장소의 검사와 허브를 돌리고, 만든 화면과 목업을 브라우저로 열어 보고, 운영 서버를 쓰지 않고 읽기만 했습니다. 41건을 찾았습니다: 치명 1, 높음 8, 중간 17, 낮음 11, 관찰 4.

검토는 한국어 사본과 관리자의 기록에 있는 사본을 영어 원본과 견주지 않았고, 운영 서버에 아무것도 쓰지 않았으며 아무것도 보내지 않았습니다. 건마다의 근거가 있는 전문은 관리자의 비공개 기록에 있고, 이 파일은 건마다 한 줄과 설계가 어디서 답하는지를 적습니다.

## 수정이 무엇인가

같은 날 14:49(KST)에 관리자가 설계로 답할 수 있는 것을 모두 고치고 만들기는 뒤에 맡은 쪽에 두라고 요청했습니다. 그래서 2026-11-11의 설계 수정은 단계 문서만 바꿉니다. ② 차례와 다시 디자인의 설계를 포함한 01–12단계이며, 코드는 바꾸지 않습니다:

- 바뀌는 단계는 머리말의 상태 문단과 확인 지점 절에 그렇다고 적고, 관리자에게 달라지는 것 하나에 한 줄씩과 먼저 볼 것 하나를 둡니다.
- 새 줄은 홀로 서면 `active`, 이 수정이 낸 다섯 결정(02단계의 D16–D20) 가운데 하나에 달려 있으면 `open (Dn)`입니다. 열린 결정마다 추천과 실제로 다른 대안이 있고, 관리자가 정할 때까지 일은 추천대로 이어 갑니다.
- 설계만 하고 만들지 않은 요청은 API 계약에 계획으로 들어가, 만든 서버의 검사가 그것을 건너뜁니다.
- 10단계가 이 수정을 맡은 쪽이 적힌 대로 따를 수 있는 작업으로 바꾸고, 12단계가 그 작업을 판정할 사례로 바꿉니다.
- 이 수정 자체의 확인 지점은 아직 통과하지 않았습니다. 확인 지점은 관리자 자신의 말로만 통과합니다.

## 설계만으로는 할 수 없는 것

- 프로필이 없는 세션에서 보내기: REQ-275가 허브를 세션의 환경에서 일하게 하고, 그 환경의 값(서버 주소와 보내기 목록)은 관리자가 넣거나 관리자의 말로 넣습니다. 에이전트가 스스로 보내기를 켜지 않는다는 하네스 규칙은 그대로입니다.
- 실제 프로젝트 둘을 다시 보내기와 다시 디자인을 만든 모습으로 보여 주기: 둘 다 관리자의 서버에 있는 것이나 서버가 돌리는 것을 바꾸므로 관리자의 말을 기다립니다(22번).
- 옛 Worker와 그 D1 데이터베이스 지우기: 2026-11-04의 결정이 전환 뒤 14일 동안 보존하고 지우기 전에 묻게 합니다. 무료 요금제에서 온 한도는 그 뒤에 다시 정합니다(19번).
- 하네스 자신의 규칙(에이전트가 AI 할 일을 얼마나 자주 읽는지, 확인 요청에 무엇을 담는지, 단계가 지나간 것을 어떻게 알리는지): 하네스 저장소에 있고 거기서 따로 PR로 바꾸며, 10단계가 그 PR을 가리킵니다.
