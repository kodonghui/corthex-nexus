# NEXUS v3: 요구사항 (PRD)

[English](requirements.md)

이 문서는 [requirements.md](requirements.md)의 한국어 사본입니다. 원본은 영어입니다.

상태: 2026-11-23 통과. 범위와 문구를 동결했습니다. 바꾸려면 기능 변경 절차를 따릅니다. v3가 프로젝트 문서를 새로 시작했으므로 요구사항 ID는 REQ-001부터입니다. 보관한 v2의 ID는 그 태그에 남아 있습니다.

입력: 01단계 도메인 설계([nexus.ko.md](../01-domain/nexus.ko.md)), 컨텍스트 CTX-037~043과 용어 TERM-189~226, 그리고 "02단계에서 다시 봄"으로 둔 핫스팟. 그 1절에 적힌 관리자의 요청과 다시 만들기 결정.

## 1. 릴리스

| 우선순위 | 뜻 | 담는 것 |
| --- | --- | --- |
| Must | 첫 릴리스 | Git에서 그린 01단계(DDD 보드), 03단계(사용자 흐름), 05단계(ERD), 07단계(사이트맵), 08단계(화면 상태), 09단계(목업) 그림, 나머지 단계의 항목 표, 댓글과 AI 제안, 이름 바꾸기와 선 잇기, 확정, 할 일, 접근, 휴대폰에서 보기와 댓글, 매일 백업 |
| Should | 첫 릴리스를 써 본 뒤의 v3 | 자유 캔버스의 이벤트 스토밍 워크숍, 연결, 라이트·다크 테마 |
| Could | 시간이 날 때 | Miro 보드 가져오기 |

첫 릴리스는 한 바퀴를 끝까지 증명합니다. Git의 단계 문서가 그려지고, 사용자가 댓글을 달고, 에이전트가 제안하고, 변경이 pull request로 Git에 들어가고, 사용자가 그림을 확정합니다.

## 4. 충돌, 중복, 열린 질문

- REQ-061, REQ-070~072, REQ-074~077, REQ-080은 관리자의 말에 근거가 없는 추론 목표입니다. 버전 동결에서 남길지 정합니다.

## 6. 체크포인트

2026-11-23에 범위 동결과 버전 동결을 한 번에 여쭙고, 여기서 정한 01단계 핫스팟마다 질문을 하나씩 두었습니다. 관리자가 체크포인트를 맡긴 대리인을 거쳐 추천안을 모두 승인했습니다. 답은 프로젝트 기록에 있습니다.

- 범위 동결: 첫 릴리스는 Must 요구사항입니다. Should와 Could는 그다음입니다. 아래 2026-11-23 기능 변경으로 03·07·08·09단계 그림이 Must가 되었습니다.
- 버전 동결: 요구사항 80개의 문구, 추론 목표 포함. 바꾸려면 기능 변경 절차를 따릅니다.
- 01단계 핫스팟 3~9와 14: 3절의 답대로.
- 이 단계가 없애거나 미루거나 바꾸는 승인된 항목: 없음. 첫 릴리스에서 빠지는 워크숍과 다른 Should·Could 항목은 범위 동결로 승인했습니다.
- 운영 중인 v2 서버의 데이터를 지우는 일은 이 체크포인트에 들지 않으며, v3가 v2를 대신할 때 따로 여쭙니다.
- 리뷰 수정: PR 96 리뷰 뒤 4절에 워크숍 릴리스의 열린 질문을, 5절에 로깅이 간 곳을 더했습니다. 2026-11-23 따로 체크포인트를 통과했고, 바뀐 요구사항은 없습니다.

### 2026-11-23 기능 변경

관리자가 사용자 흐름, 화면 상태, 목업을 첫 릴리스부터 그리기로 정했고, 그 원본은 hub가 보냅니다. 이 변경이 건드리는 승인 항목은 하나씩 여쭸고, 관리자가 체크포인트용으로 정한 대리인을 통해 승인했습니다. 답은 프로젝트 기록에 있습니다. 여기서는: 릴리스 표가 03·07·08·09단계 그림을 첫 릴리스에 넣고, REQ-007·REQ-008(Should)과 REQ-009·REQ-010(Could)이 Must가 됩니다. 문구는 그대로입니다. 워크숍, 연결, 테마, Miro 가져오기는 Should나 Could로 남습니다. 이 단계 몫은 2026-11-23에 같은 대리인을 통해 따로 체크포인트를 통과했습니다.
