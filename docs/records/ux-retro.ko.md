## 측정 방법

최상위 기준은 할머니가 화면만 보고 이해하고 쓸 수 있는지입니다. 변경마다 과제와 페르소나, 클릭과 키 입력 수, 첫 로딩과 화면 전환 시간, 완료 여부와 헤맨 횟수를 같은 조건으로 전후 기록하고 할머니 과제 완료 여부를 적습니다. 모의 평가의 인상은 가설이며 실제 사용자 증언으로 취급하지 않습니다. 근거 있는 세 시나리오는 휴대폰과 쉬운 설명이 필요한 사람, 전문 용어를 모르고 화면 밖 설명 없이 버튼 이름으로 행동을 판단하는 할머니, 360px 휴대폰만 쓰는 사람입니다. 줌, 실행 취소, Esc와 드래그를 익숙한 도구와 비교하되 실제 동작을 먼저 확인합니다. 닐슨의 휴리스틱 10개를 점검합니다. 같은 과제를 반복하기 전에는 개선을 검증했다고 하지 않으며, 수치가 나아지지 않으면 원인을 조사하거나 변경을 되돌립니다.

AI 걷기는 실패 신호로만 쓰고 사람이 과제를 완료한다는 통과 증거로 쓰지 않습니다. 사람 검증은 따로 기록합니다. 관련 변경의 전후에 다음 13개를 확인합니다. ① 재방문 주요 내용 2.5초 이내, 반응 0.2초 이내, 1초 초과 대기의 진행 표시 ② 화면 맞춤·버튼·핀치·Ctrl+휠 ③ 키보드와 버튼 실행 취소 ④ 끌기 대안 ⑤ 확정 대상과 누르기 전 결과 ⑥ 수락·반영·확정·기록·통과의 현재와 다음 단계 ⑦ 행동별 일관된 단어와 풀이 ⑧ 빈 단계의 다음 행동 ⑨ 휴대폰 과제 또는 그 자리의 이유와 대안 ⑩ 화면 찾기의 첫 클릭 ⑪ 본문 16px·대비 4.5:1·주요 버튼 44px ⑫ 메뉴의 모든 포커스 위치에서 Esc ⑬ 답글과 새 댓글의 대상 표시. 측정하지 않은 항목은 추정하지 않습니다. 이 수치는 제안된 평가 기준이며 승인된 요구사항을 바꾸지 않습니다.

## 기준 측정, 2026-11-27

격리된 테스트 스냅숏에서는 너비 976px의 보기 영역에 11,231 × 76px 보드가 표시됐습니다. 전체 화면 맞춤은 없었고 기존 구현에는 그림 이동 실행 취소가 없었습니다. 변경 후 같은 과제를 측정하기 전이라 초기 기준 측정은 미완료입니다. 테스트 데이터와 수치는 합성이며 비공개 프로젝트 관찰은 프로젝트 기록에 둡니다.

목표만 주는 모의 시험은 문제 가능성을 찾는 데 쓰며 할머니가 과제를 완료했다는 근거로 쓰지 않습니다. 변경마다 격리 데이터에서 같은 과제를 반복하고 사람의 검증은 따로 기록합니다.

그림의 읽기 쉬움과 제품 메뉴 구조를 살펴볼 필요가 있습니다. 고정된 허브가 검증한 사이트맵 그림을 테스트 스냅숏으로 임시 서버에 보내자 화면 5개, 연결선 4개, 선 교차 0개, 이름 5개와 경로 5개가 그려졌고 긴 경로 두 개는 말줄임됐습니다. 이 그림의 노드가 많다는 주장은 근거가 없습니다. 360px 목표 기반 모의 시험에서 프로젝트 메뉴에서 도메인 보드까지 5회 클릭했습니다. 불편의 원인은 아직 확인되지 않았습니다. 우선 다음 행동과 프로젝트 탐색을 명확히 하고 트리·목록 시안은 원인으로 단정하지 않고 검토합니다.

이후 main 브랜치의 실제 저장소 스냅숏을 임시 서버에 보내 1440 × 1000px에서 같은 화면 5개, 연결선 4개, 선 교차 0개를 확인했고 경로 두 개는 말줄임됐습니다. AI 걷기는 불편 가능성을 찾는 신호이며 할머니의 과제 완료를 입증하지 못합니다. 5회 클릭한 메뉴 탐색이 불편한지는 다음 행동을 더 명확히 하는 우선순위를 정할 별도 가설입니다.

모듈의 순차 요청이 로딩을 늦추는 문제 → 모듈 사전 로딩 지시 네 개를 시험 → 요청당 150ms 인공 지연 환경에서 생성 모듈 하나가 404여서 유효한 전후 과제 시간을 얻지 못함 → 효과를 검증하지 못해 후보를 되돌림 → 다음에는 완전한 격리 데이터로 같은 과제를 반복합니다. 변경 후 할머니 과제 완료 여부: 미시험이며 평가할 변경은 남아 있지 않습니다.

재방문 때 정적 JS와 CSS를 다시 받는 문제 → 정적 모듈 전체에 내용 기반 비공개 브라우저 캐시 경로 적용 → 같은 임시 서버·동등한 스냅숏의 두 번째 재방문에서 그림 API 완료까지 추정 전송량 485,981→12,821바이트, 완료 시간 166.8→63.4ms → 이 로컬 1쌍에서는 전송량이 줄었지만 실제 네트워크와 사람의 과제 완료는 미검증 → 승인 후 실제 경로와 릴리스 전환을 다시 측정합니다. 할머니 과제 완료 여부: 미시험. AI 관찰은 실패 신호이지 통과 증거가 아닙니다.

큰 그림 전체를 볼 수 없었고, 처음 승인된 최저 25%에서도 테스트 보드 11,231 × 76px은 화면보다 넓었음 → 승인된 범위를 1~200%로 정정하고 화면 맞춤과 10% 아래의 작은 버튼 단계를 추가함 → 1440 × 1000에서는 가로 넘침이 100%의 10,249px에서 8.7%의 0px로, 360 × 800에서는 10,944px에서 2.5%의 0px로 바뀜 → 그림 전체가 들어가는 수치는 나아졌지만 맞춘 그림의 글은 너무 작아 읽기 어려우므로 과제 완료를 입증하지 못함 → 다음은 실제 사람의 과제, 실제 터치 핀치와 전체·상세를 읽을 수 있게 오가는 방법을 시험함. 저장된 위치를 바꾸지 않은 격리된 합성 스냅숏의 측정임. 1~200% 정정은 2026-11-27 위임된 체크포인트를 통과함. 버튼 10→5→2.5→1%와 역방향을 확인했으며, 변경 전에는 최저 25% 때문에 작은 세 배율을 쓸 수 없었음. 페르소나: 사용자의 축소 요구와 휴대폰 전용; 할머니 과제 완료는 미시험. AI 걷기는 실패 신호이며 사람의 통과가 아님.

설명 없이 목표만 준 할머니 모의 과제(360 × 800, 같은 격리 보드): 맞춤 뒤 더하기 11회, 보이는 조각 선택 1회와 스크롤 1회를 했고, 맞춤을 포함해 총 클릭 13회, 키 입력 0회, 헤맴 1회, 관찰·기록 포함 67초였음. 100%에서도 그림 글은 잘렸고 고른 요소 패널에서 기술 식별자만 보여 뜻 있는 내용 읽기 완료는 확인되지 않았음. PC에서 요소 더블클릭은 이름 입력에 초점을 두었고 빈 곳 더블클릭은 확대하지 않았음. 실제 터치 핀치는 시험하지 못함. 전체 맞춤 수치만으로 충분하지 않으므로 다음은 전체 보기에서 읽을 수 있는 상세를 보는 방법을 개선해 같은 과제를 반복하고 사람에게도 시험함. AI 모의 결과는 실패 가능성의 신호이지 할머니의 결과나 통과가 아님.

100% 아래에서 두 번 누른 지점을 확대하도록 바꾼 뒤 새 목표 전용 걷기에서도 더하기를 11번 눌렀음: 클릭 13회, 키 1회, 헤맴 2회, 관찰 포함 80초였고 그림 글은 계속 잘렸으며 패널의 기술 식별자만 읽혔음. 새 동작을 발견하지 못해 측정한 과제는 나아지지 않았음. 다음으로 읽기 크기로 돌아가는 명시적 버튼을 시험하고 같은 과제를 반복함. 두 360px 걷기는 마우스 포인터 브라우저의 좁은 화면이지 실제 터치 휴대폰이 아니므로 휴대폰 전용 동작과 핀치는 미검증임.

축소된 보기에서 100%로 돌아가는 버튼을 눈에 보이게 추가함 → 세 번째 새 목표 전용 360 × 800 미세 포인터 걷기에서 맞춤, 새 버튼, 요소 선택으로 클릭 3회와 키 0회, 스크롤 1회를 썼고 이전 13회에서 줄었음. 관찰·기록 포함 68.2초, 헤맴 2회였음 → 클릭 수는 나아졌지만 전체 보기가 빈칸처럼 보이고 그림 글은 여전히 잘려 과제 전체는 끝내지 못함 → 다음은 전체 보기의 읽기 쉬움을 개선하고 실제 터치와 사람을 시험함. 선택 패널에서만 기술 식별자를 읽었음. 100% 이상에서는 기존 더블클릭 이름 바꾸기와 F2를 유지하고, 100% 아래의 더블클릭은 누른 지점을 확대함. 할머니 과제 완료는 미확인: AI 걷기는 실패 신호이며 사람의 통과가 아님.

확대할 때 지점의 움직임을 줄이려고 100%에서 읽기 크기 버튼을 숨기는 대신 꺼 둬 봄 → 목표 전용 걷기는 여전히 클릭 3회와 스크롤 1회였고, 얕은 합성 그림에서 두 번 누르기 두 차례 동안 대상 중심이 가로 약 4px, 세로 31px 움직였음 → 움직임 수치가 나아지지 않아 버튼 표시 변경은 되돌림. 앞서 추가한 읽기 버튼은 유지하고 스크롤 한계에서는 지점이 움직일 수 있음을 명세함. 후속 걷기는 관찰 포함 37초였고 선택 패널의 기술 식별자만 읽었음. 실제 내용 이해와 터치는 미확인임.

코드 리뷰에서 낮은 배율의 작은 휠 움직임이 반올림으로 사라지고 터치 끌기가 막힌 것을 발견함 → 배율 정밀도를 유지하고 한 손가락 끌기는 살리되 두 손가락 확대가 시작되면 끌기를 취소함 → 자동 검사에서 작은 휠 입력 10회와 터치 포인터 끌기를 확인함; 실제 터치 기기는 미시험 → 회귀 검사는 나아졌으나 할머니 과제 완료는 확인하지 못했고 사람의 사용성 통과라고 하지 않음.

두 번째 리뷰에서 페이지를 아래로 내린 상태의 맞춤이 지나치게 작아지고 중단된 끌기가 줌을 막을 수 있음을 발견함 → 스크롤 위치와 무관하게 높이를 계산하고 중단된 끌기를 정리하며 휠 단위를 반영함; 움직일 수 있는 상자 밖에서는 터치 스크롤을 유지함 → 자동 회귀 검사로 내려간 화면의 맞춤과 끊긴 끌기를 확인함; 실제 핀치는 미시험 → 다음은 터치 기기에서 전체 동작을 시험함. 할머니 과제 완료는 미시험.

격리 사이트맵의 1440 × 1000 시험에서 맞춤 두 번 모두 114.7%로 그림 전체가 보였고 작은 Ctrl+휠 20회가 양방향 배율을 바꿨음. 페이지 바깥 스크롤 범위가 없어 화면 하단 맞춤은 자동 회귀 검사만 했고 실제 터치도 시험하지 못함.
