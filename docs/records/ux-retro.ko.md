## 측정 방법

최상위 기준은 할머니가 화면만 보고 이해하고 쓸 수 있는지입니다. 변경마다 과제와 페르소나, 클릭과 키 입력 수, 첫 로딩과 화면 전환 시간, 완료 여부와 헤맨 횟수를 같은 조건으로 전후 기록하고 할머니 과제 완료 여부를 적습니다. 모의 평가의 인상은 가설이며 실제 사용자 증언으로 취급하지 않습니다. 근거 있는 세 시나리오는 휴대폰과 쉬운 설명이 필요한 사람, 전문 용어를 모르고 화면 밖 설명 없이 버튼 이름으로 행동을 판단하는 할머니, 360px 휴대폰만 쓰는 사람입니다. 줌, 실행 취소, Esc와 드래그를 익숙한 도구와 비교하되 실제 동작을 먼저 확인합니다. 닐슨의 휴리스틱 10개를 점검합니다. 같은 과제를 반복하기 전에는 개선을 검증했다고 하지 않으며, 수치가 나아지지 않으면 원인을 조사하거나 변경을 되돌립니다.

AI 걷기는 실패 신호로만 쓰고 사람이 과제를 완료한다는 통과 증거로 쓰지 않습니다. 사람 검증은 따로 기록합니다. 관련 변경의 전후에 다음 13개를 확인합니다. ① 재방문 주요 내용 2.5초 이내, 반응 0.2초 이내, 1초 초과 대기의 진행 표시 ② 화면 맞춤·버튼·핀치·Ctrl+휠 ③ 키보드와 버튼 실행 취소 ④ 끌기 대안 ⑤ 확정 대상과 누르기 전 결과 ⑥ 수락·반영·확정·기록·통과의 현재와 다음 단계 ⑦ 행동별 일관된 단어와 풀이 ⑧ 빈 단계의 다음 행동 ⑨ 휴대폰 과제 또는 그 자리의 이유와 대안 ⑩ 화면 찾기의 첫 클릭 ⑪ 본문 16px·대비 4.5:1·주요 버튼 44px ⑫ 메뉴의 모든 포커스 위치에서 Esc ⑬ 답글과 새 댓글의 대상 표시. 측정하지 않은 항목은 추정하지 않습니다. 이 수치는 제안된 평가 기준이며 승인된 요구사항을 바꾸지 않습니다.

## 기준 측정, 2026-11-27

격리된 테스트 스냅숏에서는 너비 976px의 보기 영역에 11,231 × 76px 보드가 표시됐습니다. 전체 화면 맞춤은 없었고 기존 구현에는 그림 이동 실행 취소가 없었습니다. 변경 후 같은 과제를 측정하기 전이라 초기 기준 측정은 미완료입니다. 테스트 데이터와 수치는 합성이며 비공개 프로젝트 관찰은 프로젝트 기록에 둡니다.

목표만 주는 모의 시험은 문제 가능성을 찾는 데 쓰며 할머니가 과제를 완료했다는 근거로 쓰지 않습니다. 변경마다 격리 데이터에서 같은 과제를 반복하고 사람의 검증은 따로 기록합니다.

그림의 읽기 쉬움과 제품 메뉴 구조를 살펴볼 필요가 있습니다. 고정된 허브가 검증한 사이트맵 그림을 테스트 스냅숏으로 임시 서버에 보내자 화면 5개, 연결선 4개, 선 교차 0개, 이름 5개와 경로 5개가 그려졌고 긴 경로 두 개는 말줄임됐습니다. 이 그림의 노드가 많다는 주장은 근거가 없습니다. 360px 목표 기반 모의 시험에서 프로젝트 메뉴에서 도메인 보드까지 5회 클릭했습니다. 불편의 원인은 아직 확인되지 않았습니다. 우선 다음 행동과 프로젝트 탐색을 명확히 하고 트리·목록 시안은 원인으로 단정하지 않고 검토합니다.

이후 main 브랜치의 실제 저장소 스냅숏을 임시 서버에 보내 1440 × 1000px에서 같은 화면 5개, 연결선 4개, 선 교차 0개를 확인했고 경로 두 개는 말줄임됐습니다. AI 걷기는 불편 가능성을 찾는 신호이며 할머니의 과제 완료를 입증하지 못합니다. 5회 클릭한 메뉴 탐색이 불편한지는 다음 행동을 더 명확히 하는 우선순위를 정할 별도 가설입니다.

모듈의 순차 요청이 로딩을 늦추는 문제 → 모듈 사전 로딩 지시 네 개를 시험 → 요청당 150ms 인공 지연 환경에서 생성 모듈 하나가 404여서 유효한 전후 과제 시간을 얻지 못함 → 효과를 검증하지 못해 후보를 되돌림 → 다음에는 완전한 격리 데이터로 같은 과제를 반복합니다. 변경 후 할머니 과제 완료 여부: 미시험이며 평가할 변경은 남아 있지 않습니다.

재방문 때 정적 JS와 CSS를 다시 받는 문제 → 정적 모듈 전체에 내용 기반 비공개 브라우저 캐시 경로 적용 → 같은 임시 서버·동등한 스냅숏의 두 번째 재방문에서 그림 API 완료까지 추정 전송량 485,981→12,821바이트, 완료 시간 166.8→63.4ms → 이 로컬 1쌍에서는 전송량이 줄었지만 실제 네트워크와 사람의 과제 완료는 미검증 → 승인 후 실제 경로와 릴리스 전환을 다시 측정합니다. 할머니 과제 완료 여부: 미시험. AI 관찰은 실패 신호이지 통과 증거가 아닙니다.

그림에서 옮긴 상자를 되돌릴 수 없었음 → 탭별 위치 기록과 버튼, Ctrl+Z / Ctrl+Shift+Z를 추가함 → 격리된 1440 × 1000 사이트맵에서 화살표 한 번으로 저장 좌표가 78→86, 되돌리기 한 번으로 78, 다시 실행 한 번으로 86이 됐고 글 입력 되돌리기는 위치 요청을 보내지 않았음. 두 탭 충돌에서는 첫 탭의 되돌리기가 409로 거절돼 둘째 탭의 (94,120)이 유지됨 → 측정한 키 조작은 작동하고 다른 현재 위치를 덮지 않지만 다른 곳에서 옮겼다가 같은 좌표로 돌아오면 좌표 비교만으로 알 수 없음 → 다음은 실제 사용자 흐름과 다른 편집 종류를 시험함. 페르소나: 사용자의 되돌리기 요청; 실제 할머니 과제 완료는 미시험. 이 AI의 정해진 절차 걷기는 실패 신호이지 사람의 사용성 통과 증거가 아님.

리뷰에서 저장 결과를 모를 때 원래 위치가 사라지거나 화면을 바꾼 뒤 기록이 잠길 수 있음을 발견함 → 저장·재시도 중 추가 이동을 기다리고, 화면을 떠나면 불확실한 기록을 지운 뒤 돌아왔을 때 알리며, 요소가 없으면 다시 읽음 → 연결 실패와 그림 전환을 회귀 검사함; 자동 배치였던 상자는 보이던 좌표의 고정 위치로 돌아가며 자동 배치 자체는 복원되지 않음 → 다음은 자동 배치 복원에 별도 계약 변경이 필요한지 결정함. 사람과 할머니 과제는 미시험.

첫 격리 브라우저 재시험에서 실행 취소 응답 유실 뒤 단계 이동이 페이지 전체 이동으로 일어나 다시 옮길 수는 있었지만 기록을 지웠다는 약속된 안내가 보이지 않았음 → 결과를 모르는 저장을 탭에 표시해 새 페이지에서도 안내하게 함; 기록이나 좌표는 저장하지 않음 → 회귀 검사와 브라우저 재시험이 뒤따름. 탭 저장소가 막히면 페이지 전체 이동 뒤 안내를 유지할 수 없으므로 다음은 실제 사용자와 확인함.

표시를 추가한 뒤 같은 격리 응답 유실·단계 왕복 시험에서는 없던 경고가 보였고(0→1) 옛 기록은 꺼졌으며 새 화살표 이동 한 번이 저장됐음. 위치 요청 3회가 테스트 서버에서 처리됐음. 정해진 AI 절차라 할머니의 과제 성공을 뜻하지 않음.

두 번째 리뷰에서 원래 자동 배치였던 상자를 되돌려도 고정 위치가 남아 다른 상자까지 되돌렸을 때 원래 배열이 복원되지 않음을 확인함 → API-274에 원자적 조건부 초기화를 더하고 코드에 앞서 06 계약 정정을 기록함 → 자동 배치 상자 두 개의 원래 배열 복원과 다시 실행, 충돌하는 초기화, 같은 요청 키 재전송을 검사함; 앞서 적은 고정 위치 한계는 이 수정으로 대체됨. 실제 사용자와 할머니 과제는 미시험. 이후 리뷰 후보는 이번 PR 범위를 늘리지 않고 다음 PR로 넘김.
