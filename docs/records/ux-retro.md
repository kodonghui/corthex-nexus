## Measurement protocol

The primary criterion is whether a grandmother can understand and use the product from the screen alone. For each change, record the task, persona, clicks and keystrokes, first-load and navigation time, completion and hesitations before and after under the same conditions, including whether the grandmother task was completed. Treat simulated impressions as hypotheses, not user testimony. Use three grounded scenarios: a person using a phone who needs clear language; a grandmother who knows no specialist terms, sees no explanation outside the screen, and judges actions by button labels; and a person using only a 360 px phone. Compare zoom, undo, Escape and dragging with familiar tools after checking their actual behavior. Review all ten Nielsen heuristics. A change is not validated until the same tasks are repeated; investigate or revert a change that fails to improve its measure.

AI walkthroughs are failure signals, never proof that a person can complete a task; record human validation separately. Before and after each relevant change, check: (1) repeat-load content within 2.5 seconds, response within 0.2 seconds and progress for waits over 1 second; (2) fit, buttons, pinch and Control-wheel; (3) keyboard and button undo; (4) alternatives to dragging; (5) confirmation target and consequence; (6) current and next step through acceptance, reflection, confirmation and recording; (7) consistent explained action words; (8) empty-stage next action; (9) phone task or a local explanation and alternative; (10) finding a named screen and first click; (11) 16 px body text, 4.5:1 contrast and 44 px main targets; (12) Escape from any menu focus; and (13) named recipients for replies and new comments. Measure rather than assume; targets are proposed evaluation criteria, not changes to approved requirements.

## Baseline, 2026-11-27

An isolated test snapshot showed an 11,231 × 76 px board in a 976 px wide view. Full fitting was not available and the original implementation had no diagram undo. The initial baseline is incomplete until the same tasks are measured after changes. The test data and measurements are synthetic; private project observations remain in the project records.

Goal-only simulations are used to find possible problems, not to claim a grandmother completed a task. Repeat the same tasks in isolated data after each change and record human validation separately.

Two areas merit investigation: diagram readability and product navigation. A temporary local server and test snapshot using the pinned hub's verified sitemap picture rendered five screens, four connectors, no line crossings, five names and five paths; two long paths were ellipsized. This does not support a claim that this particular drawing has many nodes. In the 360 px goal-only simulation, project menu to domain board took five clicks. The cause of any difficulty is not established; prioritise making the next action and project navigation clearer, and review the tree/list mockups as options rather than claiming a cause.

A later push of the actual main-branch repository snapshot to a temporary local server confirmed the same five screens, four connectors and zero crossings at 1440 × 1000 px; two paths were ellipsized. The AI walk flags possible difficulty and does not establish whether a grandmother can complete a task. Whether the five-click navigation is difficult remains a separate hypothesis for prioritising clearer next actions.

The sequential module chain was a loading concern → tried four module preload hints → a synthetic 150 ms delay comparison failed to load one generated module (404), so a valid before/after task time is unavailable → not validated, reverted the candidate → next use a complete isolated fixture and repeat the same task. Grandmother task completion after this change: not tested; no change remains to assess.

Repeat loading downloaded all static JS and CSS → gave the static module graph content-derived private browser-cache paths → in a temporary server with an equivalent snapshot the second warm sitemap navigation transferred an estimated 485,981 bytes before and 12,821 after, with diagram API completion at 166.8 ms and 63.4 ms respectively → the transfer measure improved in this one local pair, while real-network performance and human task completion remain unverified → next repeat on the deployed route after approval and test release transitions. Grandmother task completion: not tested; the AI observation is a failure signal, not a pass.

A large diagram could not be viewed as a whole; the originally approved 25% minimum still left the 11,231 × 76 px test board wider than the view → changed the approved range to 1–200%, added fit and smaller button steps below 10% → at 1440 × 1000, horizontal overflow went from 10,249 px at 100% to zero at 8.7%; at 360 × 800 it went from 10,944 px to zero at 2.5% → the geometric fit improved, but the fitted picture is too small to read and does not establish task completion → next test a real person's task, actual touch pinch and a readable way to move between details and overview. This was checked in an isolated synthetic snapshot, without editing saved positions. The 1–200% correction passed the delegated checkpoint on 2026-11-27. The 10→5→2.5→1% and reverse button steps were confirmed; before this change the 25% minimum prevented all three smaller values. Personas: the maintainer's reported zoom-out need and the phone-only scenario; the grandmother task was not tested. An AI walk is a failure signal, not a human pass.

Goal-only grandmother simulation, 360 × 800 on the same isolated board: after fit, the agent clicked plus 11 times, selected a visible fragment once and scrolled once; the session recorded 13 clicks, zero keystrokes, one hesitation and 67 seconds including observation. Text in the picture stayed truncated at 100%; a technical identifier was visible in the selected panel, so a meaningful reading task remains unverified. On desktop, double-clicking an element focused its rename field and double-clicking blank space did not zoom. Actual touch pinch was unavailable. The overview result alone is insufficient: next improve and repeat the path from the overview to readable detail, then test with a person. This AI simulation indicates possible failure; it is not a grandmother's result or a pass.

After adding point-centred double-click below 100%, a fresh goal-only walk still used plus 11 times: 13 clicks, one key, two hesitations and 80 seconds including observation; the picture text remained truncated and only a technical identifier was read in the panel. The new gesture was not discovered, so this does not improve the measured task. Next try an explicit return-to-reading-size button and repeat the same task. Both 360 px walks used a fine-pointer browser viewport, not a real touch phone; its phone-specific behavior and pinch remain unverified.

Added a visible button to return the zoomed-out view to 100% → in a third fresh goal-only 360 × 800 fine-pointer walk, the task used fit, the new button and one selection: three clicks, zero keys and one scroll, versus 13 clicks before; observation and recording took 68.2 seconds and there were two hesitations → the click count improved, but the overview looked blank and the picture text was still truncated, so the whole task was not completed → next address overview readability and test real touch and a person. A technical identifier was read only in the selection panel. Double-click and F2 preserve their previous rename behavior at 100% and above; below 100% double-click now zooms that point. Grandmother task completion remains unverified: this is an AI failure signal, not a human pass.

A follow-up tried keeping the reading-size button disabled instead of hiding it at 100% to reduce movement during zoom → the goal-only walk still used three clicks and one scroll, and the target's centre moved about 4 px horizontally and 31 px vertically across two double-clicks on the shallow synthetic picture → no improvement in the movement measure, so that visibility change was reverted. The earlier reading button remains; the point can shift at a scroll boundary. The later walk took 37 seconds, including observation, and read only a technical identifier from the selection panel; real comprehension and touch remain unverified.

Code review identified that small trackpad wheel events at low zoom rounded away and touch dragging was blocked → retained scale precision, preserved one-finger dragging and cancelled it when a two-finger pinch begins → automated checks cover ten small wheel events and a touch-pointer drag; an actual touch device remains untested → the regression tests improved, but grandmother task completion is unverified and no human usability pass is claimed.
