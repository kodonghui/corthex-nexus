# NEXUS: 목업

[English](README.md)

CORTHEX 자신의 프로젝트에서 NEXUS 0.2의 09단계입니다: [design/nexus/](../../../design/nexus/base.tokens.json)의 디자인 토큰, 그리고 새 화면 다섯 개(SCR-105\~SCR-109)에 대한 방향 후보 두 가지를 휴대폰 320픽셀부터 그려 한 페이지 [candidates.html](candidates.html)에 담았습니다. 상태: 2026-11-03 초안이며, 확인 지점이 아직 열려 있는 03\~08단계의 추천을 따라 그렸습니다. 이 단계 자신의 첫 확인 지점, 곧 방향 하나를 고르는 일은 관리자를 기다리며, 그 전에는 더 그리지 않습니다. 이 번역과 영어 원문이 다르면 영어 원문이 원본입니다.

입력: [08단계](../../08-screens/nexus/README.ko.md)의 화면 정의, 특히 [SCR-105](../../08-screens/nexus/SCR-105-picture-view.ko.md)\~[SCR-109](../../08-screens/nexus/SCR-109-stage-overview.ko.md)와 그 상태, 320과 1440픽셀의 배치, 메시지의 최종 문구, 그리고 [09단계를 위한 메모](../../08-screens/nexus/README.ko.md#09단계-목업); 지금 도는 1차의 허브 페이지 [hub.html](../../../plugins/corthex-nexus/skills/corthex-hub/assets/hub.html), 토큰은 그 색, 글꼴, 간격, 카드를 가져옵니다; 그리고 [01단계](../../01-domain/nexus.ko.md)의 이벤트 스토밍 보드, 틀 안에서 예시 그림으로 그렸습니다. 브랜드 자료나 마음에 드는 참고는 주어지지 않았습니다. NEXUS에는 따로 로고가 없으므로, 두 후보 모두 1차의 생김새를 그대로 두고 구조와 표시의 꼴이 다릅니다.

이 단계의 기본 사람 화면은 Figma나 Claude Design입니다. 여기서는 스크립트가 토큰으로 그린 한 페이지 [candidates.html](candidates.html)이며, 모든 틀을 밝은·어두운 테마와 영어·한국어로 볼 수 있고, 브라우저에서 줄바꿈, 대비, 누르는 곳의 크기, 넘침을 잴 수 있습니다. 이 프로젝트에는 Figma가 연결되어 있지 않고, 토큰으로 그린 페이지는 모든 값에 토큰 이름을 남깁니다. 저장소가 공개이므로 사람은 이것을 링크가 프로젝트의 기록에 있는 비공개 게시 페이지로 봅니다. `.corthex/project.json`이 이 선택을 적어 둡니다.

## 토큰

Design Tokens Community Group의 2025.10 형식이며, 모드는 Resolver Module 2025.10을 따릅니다. 원본은 이 파일들이고, 페이지와 나중의 코드는 여기서 토큰을 가져갑니다.

| 파일 | 담은 것 |
| --- | --- |
| [base.tokens.json](../../../design/nexus/base.tokens.json) | 모든 테마가 함께 쓰는 토큰 47개: `font`(글꼴 묶음, 크기 다섯, 굵기 셋, 줄 높이 셋), `space`(2\~32픽셀), `radius`, `border`, `size`(누르는 곳, 표시, 입력 칸, 옆 패널, 단계 현황의 단), `opacity`, `layout`(화면 높이에 대한 몫), `breakpoint`, `duration`, `easing` |
| [theme/light.tokens.json](../../../design/nexus/theme/light.tokens.json) | 밝은 테마의 색과 그림자 27개 |
| [theme/dark.tokens.json](../../../design/nexus/theme/dark.tokens.json) | 어두운 테마의 27개, 이름은 같음 |
| [tokens.resolver.json](../../../design/nexus/tokens.resolver.json) | 기본을 먼저, 그다음 테마: 기본값은 `light`, 또는 `dark` |

- 1차 허브 페이지에서 온 것: 한국어 글꼴을 포함한 기기 글꼴, 15픽셀 본문, 페이지와 카드의 색, 강조색, 완료 단계의 초록, 그리고 6·8·12픽셀 모서리와 알약 모양.
- 0.2에서 새로 생긴 것: 입력 칸, 칩, 확인란의 테두리인 `color.control-line`(1차의 선은 더 옅어서, 바탕과 표면에 대해 3:1이 필요함, WCAG 1.4.11); 표시와, 표시를 그림의 색과 떼어 놓는 테두리인 `color.mark.*`; `color.scrim`과 `color.picture-ground`; 바탕색이 딸린 `color.warn`과 `color.info`; 그림자 둘; 손가락으로 고르는 모든 것의 최소 너비와 높이인 `size.target` 44픽셀; 표시, 입력 칸, 패널의 크기; 그리고 휴대폰 높이에서 그림과 시트가 차지하는 몫.
- 페이지 안에서 토큰은 경로로 이름 붙인 사용자 정의 속성이 됩니다. 예: `--nx-color-mark-ink`. 그림 안의 그림을 빼면 목업의 스타일은 이 이름 말고는 어떤 색이나 길이도 쓰지 않으며, `breakpoint.side-panel`을 빼고 모든 토큰을 씁니다. 틀은 정해진 폭으로 그리고, 보기가 만들어지면 그 미디어 쿼리에서 이 토큰을 씁니다.
- 후보의 토큰: `size.pin`은 A의 것, `size.tab`과 `layout.sheet-peek`는 B의 것입니다. 고르지 않은 쪽은 그 방향과 함께 지웁니다.

## 후보

`corthex-uxui` 스킬대로 다섯 갈래에서 생각을 하나씩 그려 보고, 둘을 보입니다.

1. 제품의 재료 세계, 곧 메모가 붙은 이벤트 스토밍 보드: 메모에 붙인 이름표 같은 표시. B로 보입니다.
2. 대화보다 기록의 느낌, 차분하고 사용자가 이미 아는 허브 페이지와 같은 생김새. A로 보입니다.
3. 쓰는 사람, 곧 주로 책상에서 읽고 휴대폰으로 답하는 관리자 한 명: 둘 다 휴대폰부터 그려서 두 후보에 모두 담았습니다.
4. 흔한 답을 뒤집은 것, 곧 항목을 누르기 전에는 아무것도 보이지 않는 그림: 버렸습니다. 08단계는 열린 대화가 한눈에 보이도록 그림 위에 개수를 둡니다.
5. 낯선 형식, 곧 그림이 메시지로 오가는 프로젝트 하나의 대화: 버렸습니다. 쓴 것마다 그림의 어디에 있는지가 사라지는데, 그것이 그림 보기의 요점입니다.

### A · 허브와 같은 쪽 (추천)

그림 보기와 단계 현황이 1차 허브 페이지처럼 읽힙니다. 같은 윗줄, 카드, 줄 목록을 씁니다. 그림은 페이지의 16픽셀 여백 안 카드에 들어가며, 휴대폰에서 폭은 286픽셀입니다. 항목 모서리에 종류마다 작은 핀이 붙고, 그리는 크기는 24픽셀, 누르는 곳은 44픽셀입니다. 의견은 검은 동그라미, 제안은 파란 네모, 어긋남은 호박색 마름모이며, 어긋남이 최신 그림을 기다리면 속이 빈 마름모입니다. 받았지만 아직 반영 전인 제안은 그 항목을 파란 점선으로 두르고 ✓ 핀을 답니다. 따로, 항목을 목록으로 보기, 표시의 설명은 그림 아래 줄입니다. 패널은 어두워진 그림 위로 아래에서 내용 높이만큼, 최대 85%까지 올라오며, 1,440픽셀에서는 그림 옆에 열립니다.

- 좋은 점: NEXUS 0.2가 1차에서 그대로 두는 허브 페이지와 생김새가 같습니다. 모서리 핀이라 꽉 찬 보드를 덜 가립니다. 종류마다 모양이 달라 색만으로 구별하지 않습니다. 08단계의 배치를 그대로 따릅니다.
- 대가: 처음에는 모양을 표시의 설명으로 익혀야 하고, 기다리거나 받은 항목의 글은 표시의 설명, 목록, 패널에만 나옵니다. 휴대폰에서 그림이 더 좁고, 긴 패널은 그림을 가립니다.

### B · 그림이 먼저

그림이 폭 전체, 휴대폰에서 320픽셀을 쓰고, 맨 위는 아이콘과 두 줄 제목이 있는 막대 하나입니다. 휴대폰에서는 문서 판이 칩이 되어 그림 위로 옮겨 갑니다. 쓴 것이 있는 항목에는 윗변, 곧 이름 위에 이름표가 앉습니다. 의견과 제안은 각각 아이콘과 개수가 있는 검은 이름표 칸에, 어긋남은 호박색 이름표에 나오고, 받은 제안에는 "받음, 아직 반영 전"이라고 적힌 파란 이름표가 붙습니다. 틀 밖으로 나갈 이름표는 대신 항목의 오른쪽 끝에 맞춥니다. 그림 아래 서랍에 따로, 항목 목록, 표시 설명이 있습니다. 표시에서 열면 패널은 그림을 어둡게 하지 않고 먼저 높이의 55%까지 올라오며, 항목이 계속 보이도록 그림을 옮깁니다. 다른 패널에서 열면 85%까지 올라옵니다. 대화는 말풍선으로 보이고, 단계 현황은 남은 것을 필터가 있는 목록 하나에 모읍니다.

- 좋은 점: 휴대폰에서 그림이 약 12% 넓습니다. 이름표가 무엇을 세는지 보여 줍니다. 절반 높이 패널 위로 항목이 계속 보입니다.
- 대가: 꽉 찬 보드에서는 이름표가 항목 위 줄, 예컨대 컨텍스트 제목을 가리고, 글이 있는 이름표는 휴대폰에서 이웃 항목 위로 길게 걸칩니다. 허브 페이지와 생김새가 다르고, 08단계의 SCR-105 320픽셀 배치를 바꿉니다.

### 무엇이 다른가

| | A · 허브와 같은 쪽 | B · 그림이 먼저 |
| --- | --- | --- |
| 윗줄 | 허브 페이지와 단계 현황은 글 링크, 제목과 그 아래 문서 판 줄로 1차 허브와 같음 | 아이콘 단추와 두 줄 제목; 320픽셀에서 문서 판은 그림 위의 칩 |
| 그림 | 여백 안의 카드, 휴대폰에서 폭 286픽셀 | 폭 전체, 휴대폰에서 320픽셀 |
| 표시 | 항목 모서리에 종류마다 24픽셀 핀, 핀마다 누르는 곳 44 × 44 | 항목 윗변에 아이콘과 개수가 있는 24픽셀 이름표, 칸마다 누르는 곳 44 × 44 |
| 받음, 아직 반영 전 | 파란 점선 테두리와 ✓ 핀 | 파란 테두리와 글이 적힌 파란 이름표 |
| 그림 전체 | 컨텍스트마다 표시가 개수를 단 32픽셀 동그라미로 합쳐짐 | 컨텍스트마다 표시가 "표시 {n}개" 알약으로 합쳐짐 |
| 그림 아래 | 따로는 한 줄, 항목을 목록으로 보기는 단추, 그다음 표시의 설명 | 따로, 항목, 표시 설명 세 탭의 서랍 |
| 320픽셀의 패널 | 내용 높이만큼, 최대 85%, 어두워진 그림 위; 줄 목록 | 표시에서 열면 먼저 55%, 어둡게 하지 않음; 다른 패널에서 열면 85%; 말풍선 |
| 단계 현황 | 허브 카드: 기록된 상태, 남은 것 목록 셋, 통과시키기, 점검 | 기록 띠, 필터 칩이 있는 남은 것 목록 하나, 통과시키기, 점검 |
| 08단계 변경 | 없음 | SCR-105의 320픽셀: 문서 판을 그림 위로, 윗줄은 아이콘만 |

### 둘이 함께 지키는 것

- 그림을 처음 열면 표시가 가장 많은 컨텍스트를, 휴대폰에서 보드의 글이 약 10픽셀 높이가 되는 확대로 보여 줍니다. 1,440픽셀에서는 그림 전체가 들어갑니다.
- 표시는 어느 확대에서도 크기가 같습니다. 휴대폰에서 그림 전체를 보면 컨텍스트마다 표시가 개수를 단 하나로 합쳐지고, 그것을 누르면 확대합니다. 하나를 세는 표시는 그 패널을, 여럿을 세는 표시는 항목의 패널을 엽니다.
- 항목 목록은 표시가 있는 항목을 먼저, 그다음 나머지를 두고, ID 없는 부분은 그렇다고 적습니다.
- 한국어는 낱말 사이에서 줄을 바꾸고, 날짜는 중간에서 끊지 않으며, 긴 ID는 페이지를 넓히는 대신 줄을 바꿉니다. 움직임 줄이기를 켜면 시트는 움직이지 않고 서서히 나타납니다.

## 틀

후보마다 틀 14개이며, 두 후보의 상태는 같고, 각 틀을 밝은·어두운 테마와 영어·한국어로 그렸습니다. 예시 자료는 이 틀을 위해 지어낸 것입니다: 01단계의 보드, 의견 다섯, 제안 둘, 어긋남 둘, 커밋, 추적 ID. NEXUS 자체의 말은 08단계의 것입니다.

| 화면 | 그린 것 | 아직 그리지 않은 것 |
| --- | --- | --- |
| SCR-105 그림 보기 | 320픽셀의 normal, 처음 연 모습과 그림 전체; 1440의 normal; 320의 stale과 code-failed | loading, large, empty, error, permission |
| SCR-106 항목 | 320과 1440의 normal; 320의 error(`comment_limit`, 쓴 글은 남김) | empty, loading, permission, gone |
| SCR-107 의견 | 320의 normal | loading, stale, error, permission, gone |
| SCR-108 제안 | 320의 normal, 열린 제안과 받은 제안 | loading, stale, error, permission, gone |
| SCR-109 단계 현황 | 320의 normal과 stale, 1440의 normal | loading, empty, error, permission |

그리지 않은 상태는 방향을 고른 뒤 그 방향으로 그리며, 허브 페이지에는 SCR-101과 SCR-104에 0.2가 더하는 것을 함께 그립니다.

## 새 문구

틀에 필요하지만 08단계가 적지 않은 말이며, 영어와 한국어로 적습니다. 방향을 고르면 08단계의 메시지에 더합니다.

| 자리 | 영어 | 한국어 |
| --- | --- | --- |
| 확대 단추 | Zoom out · Zoom in · Whole picture | 축소 · 확대 · 그림 전체 |
| 합친 표시 | "1 mark" 또는 "{n} marks"(B), 이름은 "{n} marks in {context}: zoom in" | "표시 {n}개", 이름은 "{context}의 표시 {n}개: 확대하기" |
| 표시의 설명 | Legend(B의 탭), 이름은 "Legend of the marks" | 표시 설명, 이름은 "표시의 설명" |
| 항목 목록 | With marks ({n}) · The rest ({n}) · Part without an ID | 표시가 있는 것 ({n}) · 나머지 ({n}) · ID 없는 부분 |
| 항목 패널 | Term · Proposals ({n}) · Comments ({n}) · Closed ({n}) · {n} replies | 용어 · 제안 ({n}) · 의견 ({n}) · 닫힌 의견 ({n}) · 답글 {n}개 |
| 제안 패널 | Answers · Made on commit {commit} | 답하는 의견 · 커밋 {commit}에서 낸 제안 |
| 단계 현황 | Updated {time} · from the repository · Words (optional) · All {n} · Reflections {n} | 갱신 {time} · 저장소에서 · 남길 말 (선택) · 모두 {n} · 반영 대기 {n} |

## 추천

A, 허브와 같은 쪽. NEXUS 0.2는 1차 디자인을 그대로 둔 허브 페이지 옆에 이 화면들을 더하므로, A로 하면 한 제품처럼 보이고 모서리 핀이 꽉 찬 DDD 보드를 읽기 쉽게 둡니다. B를 고를 가장 큰 이유는 휴대폰입니다. 그림이 더 넓고, 표시가 무엇을 세는지 말해 주며, 패널이 열려도 항목이 보입니다. 휴대폰이 가장 중요하다면 B가 낫습니다. A도 나중에 B의 절반 높이 패널을 생김새를 바꾸지 않고 들일 수 있습니다.

## 돌린 검사

2026-11-03에 토큰, 페이지, 그 틀 56개에 대해:

- 토큰: 기본 토큰 47개와 테마마다 27개가 저마다 `$value` 하나와 형식(자신의 것 또는 묶음의 것)을 가집니다. 색은 sRGB 객체이고 `hex`가 성분과 맞으며, 치수는 `px`나 `rem` 객체입니다. 두 테마는 같은 이름 27개를 가지며 그중 어느 것도 기본 파일에 없습니다. 선택 문서는 세 파일을 모두 적습니다.
- 목업의 스타일: 토큰 이름 밖의 색이나 길이가 없고, 0, 50% 같은 온전한 몫, 컨테이너 단위로 쓴 그림 높이만 있습니다. `breakpoint.side-panel`을 빼고 모든 토큰을 씁니다.
- 대비: 틀이 그리는 쌍마다 토큰에서 계산했으며 테마마다 37쌍입니다. 글은 4.5:1 이상, 입력 칸 테두리, 초점 테두리, 외곽선, 표시는 그 뒤에 대해 3:1 이상입니다. 밝은 테마의 입력 칸 테두리는 페이지 바탕에서 3:1이 되도록 한 번 진하게 고쳤습니다.
- `corthex-uxui`의 페이지 검사를 틀마다 따로, 320 × 640이나 1440 × 900에서, 두 테마로: 112번. 가로 스크롤, 끊긴 낱말, 빠진 이름표, 24픽셀보다 작은 누르는 곳이 없습니다. 검사가 알린 것은 그림 안의 그림이 틀에서 잘리는 것, 곧 틀보다 큰 그림이 틀 안에서 움직이는 방식(08단계 규칙 1)과, 검사가 볼 수 없는 도형 위에 앉은 마름모 표시의 숫자이며, 이것은 손으로 계산했습니다. 44픽셀 목표는 44 높이 줄 안의 24픽셀 확인란과 문장 안의 풀 리퀘스트 번호 말고는 모두 맞습니다.
- Chromium에서 페이지를 320, 390, 1,280, 1,440픽셀로, 밝은·어두운 테마와 두 언어로 16번: 가로 스크롤 없음, 틀 가장자리를 넘는 요소 없음, 콘솔 오류 없음. 페이지 검사는 그림 안의 그림과, 정보로만 세는 한국어 본문의 짧은 끝 줄 네 개만 알립니다.
- 이미지로 본 것: 두 후보의 320픽셀 틀 전부를 영어·밝은 테마와 한국어·어두운 테마로; 1,440픽셀 틀 세 개는 A를 영어·밝은 테마로, B를 한국어·어두운 테마로. 고친 틀은 다시 보았습니다.
- 이 저장소에 대한 허브의 스냅샷은 `design/nexus/`를 이 단계의 원본으로 찾고, 검사 결과를 더하지 않습니다.
- 이 파일들과 함께 저장소의 검사가 통과합니다: `python -m unittest discover -s tests`, 마켓플레이스와 그 플러그인 세 개의 `claude plugin validate --strict`, `node --test nexus/test/*.test.js`, `git diff --check`.
