## 2. 덮은 범위

Must 요구사항은 모든 화면에 걸친 세 개만 빼고 모두 흐름에 나옵니다. 그 셋과 같은 성격의 Should 두 개는 아래처럼 뒤 단계로 넘깁니다. 요구사항 80개 중 75개가 흐름 하나 이상에 나옵니다. 흐름의 릴리스는 그 요구사항 중 가장 높은 것이고, FL-013만 예외입니다. FL-013의 Must 요구사항 하나는 그 흐름이 그리는 Should 기능의 제약입니다.

| 요구사항 | 릴리스 | 흐름에 없는 까닭 |
| --- | --- | --- |
| REQ-069 | Must | 화면 언어는 모든 화면에 걸쳐 있어 08단계에서 점검합니다. |
| REQ-072 | Must | 브라우저는 12단계의 브라우저 점검으로 확인합니다. |
| REQ-073 | Must | 컴포넌트와 모서리는 09단계에서 정합니다. |
| REQ-074 | Should | 대비와 키보드 사용은 08·12단계 화면에서 점검합니다. |
| REQ-075 | Should | 테마는 09단계에서 정합니다. |

## 3. 흐름이 더한 것

- FL-011은 요구사항에 없는 단계 하나를 그렸습니다. 매일 백업이 실패하면 사용자에게 알리는 단계입니다. 원문에 없음으로 표시했고, 04단계에서 정합니다.
- FL-003과 FL-004는 FL-005가 시작하는 곳에서 끝나서, Git 반영은 한 번만 그렸습니다.

## 4. 체크포인트

흐름마다 주 경로와 실패 경로를 검토합니다. 이 단계가 없애거나 미루거나 바꾸는 승인된 항목: 없음.
