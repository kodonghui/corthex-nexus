# SCR-143 Projects

[한국어](SCR-143.ko.md)

Path: `/p`. Flows: FL-001, FL-002, FL-009, FL-010.

Purpose: The owner sees every project space with its progress and opens one, and issues and revokes agent credentials (SPEC-049, SPEC-050).

## Data

| Data | Source |
| --- | --- |
| Header: "My turn N", the number of to-do entries | API-263 |
| Header: the project menu | API-262 |
| Project spaces: title, last revision and send time, stages passed out of 13, the to-do count | API-262 |
| Agent credentials: name, issued, last used, revoked | API-279 |

## Actions

| Action | Operation | Result | Failure |
| --- | --- | --- | --- |
| Open a project | - | SCR-144 opens | Gone meanwhile → SCR-144 shows it is gone |
| Issue a credential with a name | API-280 | The secret shows once, with a copy button and the hub command to set it (secret state) | Empty or over 64 characters, or a name in use → the message by the name, kept |
| Revoke a credential | API-281 | After one question, the row shows "revoked" with the time; its next request is refused | Gone meanwhile → "not in NEXUS" and the list read again |

## States

| State | What the owner sees and can do | From responses |
| --- | --- | --- |
| SCR-143#normal | Projects as rows, newest send first, each with "N of 13 stages passed" and its to-do count; a row opens SCR-144, which has each stage's state and the tool links. Under them the credentials table with a revoke button per row and an issue form. After a deletion on SCR-144, "Deleted demo" shows on top once. On a phone: projects and credentials read-only; issue and revoke are not offered, with "Do this on a PC". | API-262#200, API-263#200, API-279#200, API-280#200, API-281#200 |
| SCR-143#loading | Grey rows for projects and credentials in their places; the issue form is off. | - |
| SCR-143#empty | No project: "A project appears here when an agent sends it for the first time: issue a credential below, set it in the hub and push with --first." No credential: "No agent can send yet." | API-262#200, API-279#200 |
| SCR-143#error | A failed read: a message and a retry per table, so the other table still shows. A refused issue: the message by the name field, the name kept. | API-262#default, API-263#default, API-279#default, API-280#400, API-280#409, API-280#413, API-280#415, API-280#default, API-281#400, API-281#404, API-281#409, API-281#413, API-281#415, API-281#default |
| SCR-143#permission | 401: the gate, then back here. 403: only the not-owner message; cross-site: a reload. | API-262#401, API-262#403, API-263#401, API-263#403, API-279#401, API-279#403, API-280#401, API-280#403, API-281#401, API-281#403 |
| SCR-143#stale | "Read at 10:42"; read again when the tab comes back into view. | - |
| SCR-143#secret | The new credential's secret in a box with a copy button, "It shows only now", and `corthex-hub` setup words. Leaving or reloading the page hides it for good (SPEC-049). A phone never shows it, since issuing is on a PC; its 360-pixel frame is a narrow PC window. | API-280#201 |

## Kinds of cases

| Kind | What the screen shows |
| --- | --- |
| Access | permission state |
| Input | the name's message by the field, the name kept |
| Repeats | issue and revoke are off while they run; a repeated issue shows the same credential without its secret |
| Data exposure | the secret shows once and is never loaded again |
| Screen states | every state at 360 and 1440 pixels |
