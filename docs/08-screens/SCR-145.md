# SCR-145 Stage workbench

[한국어](SCR-145.ko.md)

Path: `/p/{project}/{part}/{stage}`. Flows: FL-001, FL-002, FL-003, FL-004, FL-005, FL-006, FL-007, FL-008, FL-012, FL-013.

Purpose: The owner reads a stage's diagram or item table and works on it: moves, comments, answers AI proposals, renames and connects, and confirms; on stage 01 during a workshop, edits sticky notes (SPEC-003 to SPEC-035, SPEC-038, SPEC-039).

## Data

| Data | Source |

## Actions

| Action | Operation | Result | Failure |
| --- | --- | --- | --- |
| Move an element (drag, or arrows with Shift for long steps) | API-274 | The element stays where it was put; the document is unchanged (SPEC-012) | Gone from the document → "no longer in the diagram" and a reload |
| Copy an element | - | "ID name" is on the clipboard and "Copied" shows (SPEC-011) | The browser refuses → the text shows selected to copy by hand |
| Rename (double click or F2) or connect two elements | API-272 | The element shows the change with a "waiting for reflection" mark (SPEC-021, SPEC-022) | Empty or over 200 characters → the message by the name; to itself → refused; the document changed → stale |
| Comment on the diagram, an element or a row | API-267 | The thread opens in the panel with the comment, waiting on an agent | Over the limit → the message by the box, the text kept |
| Reply in a thread | API-268 | The reply is added in order | Closed meanwhile → "This thread is closed. Start a new comment.", the text kept |
| Close a thread | API-269 | The thread shows closed and leaves both to-dos | Gone → a reload |
| Accept an AI proposal | API-270 | Asked once, then the proposal shows as "waiting for reflection" (SPEC-019) | Already decided or the document changed → stale: "ask for a new proposal" |
| Reject an AI proposal | API-271 | Asked once, then the overlay is gone and the thread stays open (SPEC-020) | Already decided → stale |
| Cancel a direct edit | API-273 | The diagram shows the element as before (SPEC-023) | Already reflected → stale |
| Confirm the diagram | API-275 | Asked once, then "Confirmed. The stage passes when the agent records it." (confirmed state) | Waiting changes → the waiting state; the document changed → stale; not drawn → the not-drawn state |
| Cancel the confirmation | API-276 | "Cancelled. It stays in your to-do until you confirm again." | Gone → a reload |
| Open a workshop (stage 01) | API-284 | The workshop state opens with step 0 | One is open already → that one opens |
| Add, move, rename, connect or remove sticky notes (workshop) | API-286, API-287, API-288, API-289, API-290 | The board shows the change at once; the workshop is the source (SPEC-038) | The workshop closed meanwhile → stale |
| Confirm a step (workshop) | API-291 | The step shows confirmed; writing it into the domain document goes to the agent (SPEC-039) | A step without notes → "Add notes before confirming" |
| Import a Miro board (workshop) | API-292 | The notes come in with their text, colour and place (SPEC-041) | The workshop closed → stale |

## Kinds of cases

| Kind | What the screen shows |
| --- | --- |
| Access | permission state |
| Input | names and comments: the message by the field, the text kept |
| Target | 404 for the diagram, an element, a thread or a change |
| State changes | stale: already decided, closed thread, closed workshop |
| Repeats | every button is off while it runs; accepting or confirming twice gives the same result |
| Concurrency | the document changed since the page opened → stale; two tabs moving one element → the last move wins (SPEC-012) |
| Limits | a comment over the limit or a body too large: the limit by the box |
| Data exposure | an element's trace ID, such as TBL-146, stays out of the screen text and shows when copied; an element without a name shows by it (SPEC-010) |
| AI answers | an AI proposal shows its kind, text, reason and the other way, dashed until accepted and reflected |
| Screen states | every state at 360 and 1440 pixels |
