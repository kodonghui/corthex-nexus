## 2. 모든 화면이 같이 따르는 것

- 헤더. 모든 화면에 11-21 목업의 헤더(NEXUS, 프로젝트 메뉴, "내 차례 N", 어두운 화면 스위치)가 있습니다. 수나 메뉴를 읽지 못하면 그것만 빼고 화면의 나머지는 동작합니다.
- 메시지. 화면은 계약(06단계)의 오류 코드 메시지를 한국어로 보여 주고, "문제가 생겼어요" 아래에는 요청의 `traceId`를 둡니다. 더 보여 주는 곳은 화면 정의에 적습니다.
- 반복. 요청이 도는 동안 버튼은 꺼지고 결과는 하나만 보입니다. 새 쓰기마다 새 요청 키를 싣습니다. 시간 초과나 연결 끊김 뒤 다시 시도할 때는 같은 키를 보내서, 이미 된 쓰기는 두 번 되지 않고 처음 결과가 옵니다(명세 규칙 3). 키는 사용자가 입력을 바꿀 때만 바뀝니다.
- 오래된 데이터. 화면은 데이터를 읽은 때를 보여 주고, 탭이 다시 보이면 다시 읽습니다. 데이터가 바뀌었다는 409는 사용자가 쓴 글을 남기고 새로 고침을 줍니다.
- 휴대폰. 휴대폰(1056픽셀보다 좁은 터치 화면)에서는 모든 화면이 휴대폰 배치입니다. 한 칸으로 놓고, 작업 패널은 그림 아래 시트(스레드와 댓글 칸)가 됩니다. 옮기기, 직접 편집(이름 바꾸기, 잇기, 편집 취소, 워크숍의 스티커·스텝·Miro 가져오기), 제안 답하기, 확정과 확정 취소, 자격, 도구 링크, 삭제는 PC에서 하라는 안내와 함께 보이지 않습니다(SPEC-051). 댓글과 답글은 됩니다. PC에서 창을 좁히면 패널이 그림 아래로 가고 모든 동작은 그대로입니다. 상태마다 360픽셀 프레임이 휴대폰 배치입니다. 다만 PC 동작으로만 오는 상태(SCR-143#secret, SCR-144#delete, SCR-146#confirmed, SCR-146#not-drawn)의 360픽셀 프레임은 좁은 PC 창입니다.
- 너비. 상태마다 360픽셀과 1440픽셀(휴대폰과 목업의 너비)로 그립니다. 긴 이름은 단어 단위로 줄을 바꾸고(한국어도), 작업 패널을 화면 밖으로 밀지 않습니다.
- 데이터 노출. 화면은 소유자 오퍼레이션으로 사용자의 데이터만 읽습니다. 에이전트 자격의 비밀값은 발급한 화면에서 한 번만 보이고 다시는 보이지 않습니다.

## 3. 응답과 상태

계약에 있는 오퍼레이션의 모든 응답은 상태 하나로 이어집니다. 한 코드가 여러 상태로 갈 때는 상태 표가 `API-275#409 (not-drawn)`처럼 예시를 적습니다. 기본은 아래와 같고, 다른 곳은 화면 정의가 적습니다. 계약에는 429와 503이 없습니다. stale 상태는 시간에서도 옵니다. 화면은 데이터를 읽은 때를 보여 줍니다.

| 응답 | 상태 | 기본으로 보이는 것 |
| --- | --- | --- |
| 200, 201 | normal | 데이터, 또는 그 자리에 보이는 동작의 결과 |
| 200 with nothing in it | empty | 여기에 무엇이 나올지와 어떻게 생기는지 |
| 400, 413 | error | 관련 입력 옆에 메시지, 입력은 그대로 |
| 401 | permission | "다시 로그인하세요". 게이트로 갔다가 이 화면으로 돌아오고, 보내지 못한 댓글은 남김(SPEC-048) |
| 403 | permission | not-owner: "이 NEXUS의 소유자만 열 수 있어요"만 보여 줌. cross-site: "이 변경은 NEXUS 화면에서만 할 수 있어요"와 새로 고침 |
| 404 | error | 더 이상 없다는 것과, 그것이 있던 목록으로 가는 링크. 예시별로: tool-link-not-found와 workshop-not-found는 normal(링크가 없어짐, 열린 워크숍 없음) |
| 409 | stale | 바뀌었다는 것: 새로 고친 뒤 다시. 예시별로: request-key-reused와 name-taken은 error, waiting-reflection은 waiting, not-drawn은 not-drawn, workshop-open과 step-empty는 workshop(화면에 그 상태가 있을 때, 없으면 stale) |
| 415, default, a timeout or no network | error | 짧은 메시지와 다시 시도. 화면의 나머지는 그대로 동작 |

### 2026-11-23 기능 변경

관리자가 사용자 흐름, 화면 상태, 목업을 첫 릴리스부터 그리기로 정했고, 그 원본은 hub가 보냅니다. 이 변경이 건드리는 승인 항목은 하나씩 여쭸고, 관리자가 체크포인트용으로 정한 대리인을 통해 승인했습니다. 답은 프로젝트 기록에 있습니다. 여기서는: SCR-145의 데이터에 목업 페이지(API-293)가 더해지고, normal 상태가 03·08·09단계 그림의 모습을, not-drawn 상태가 종류별 실패 글을 적습니다. 상태 수는 그대로입니다. 이 단계 몫은 2026-11-23에 같은 대리인을 통해 따로 체크포인트를 통과했습니다.

#### PR 104 리뷰 뒤

승인된 항목이 바뀌었고, 하나씩 여쭈어 같은 대리인을 통해 승인했습니다. 여기서는: SCR-145와 SCR-146의 주소가 선택 쿼리 ?diagram=을 받고, SCR-145의 데이터에 그 단계의 그림 목록이, 동작에 "단계의 다른 그림 열기"가 더해집니다. normal 상태가 그림 목록, 요소인 토큰, 프레임의 상태 확인과 다른 페이지로 옮겨 갈 때를 적습니다. 상태 수는 그대로입니다. 이 몫은 2026-11-23에 같은 대리인을 통해 따로 체크포인트를 통과했습니다.

#### PR 104 두 번째 리뷰 뒤

승인된 항목이 더 바뀌었고, 하나씩 여쭈어 같은 대리인을 통해 승인했습니다. 여기서는: SCR-145와 SCR-146의 쿼리가 이미 있는 ?d=입니다. #### PR 104 여덟 번째 리뷰 뒤

#### PR 104 아홉 번째 리뷰 뒤

### 지운 그림의 제안 거절

TASK-444를 만들다가 지운 그림의 AI 제안이 소유자 할 일에서 빠질 수 없는 것을 찾았습니다. 승인된 글은 2026-11-23 기능 변경의 "SCR-145에서 지운 그림이 스레드를 보려고만 열리고 새 댓글, 옮기기, 직접 편집, 제안 답하기, 확정 버튼이 없으며"(SPEC-027)와 PR 104 아홉 번째 리뷰 뒤의 "목록에 남은 지운 그림이면 스레드를 보려고만 엽니다"입니다. SPEC-027이 지운 그림에서 막는 것은 제안 수락이지 제안 거절이 아닙니다. 그리고 소유자 할 일은 지운 그림의 제안을 계속 소유자에게 남겨 둡니다(서버 README의 "프로젝트 목록과 할 일"). 그래서 그런 제안은 에이전트가 거두거나 그림이 돌아올 때까지 기다렸습니다. 이제 API-271은 API-257이 제안 거두기를 받듯이 그곳의 거절을 받습니다(WBS 메모 7). 승인된 항목 1개가 바뀌고, 따로 여쭙니다. SCR-145#normal은 지운 그림이 스레드와 AI 제안을 보려고만 열리고, 제안에는 거절만 있고 수락은 없다고 적습니다. SCR-145#error도 목록에 남은 지운 그림을 스레드와 제안 거절만 있게 엽니다. SPEC-027이 수락을 막으므로 수락 버튼은 계속 숨깁니다. 상태 수는 그대로이고, TASK-460이 이를 그립니다. 이 몫은 2026-11-24에 같은 대리인을 통해 따로 체크포인트를 통과했어요.

### 2026-11-24 기능 변경

지운 그림은 자기를 기다리는 것을 지킵니다. 열린 스레드, 답을 기다리는 AI 제안, 반영을 기다리는 직접 편집 중 하나가 있는 동안 목록에 남고 열립니다(기능 명세 6절). 지운 그림에는 확정 버튼이 없어서, 확정하려 할 때 가는 SCR-145의 waiting 상태가 거기서는 나오지 않습니다. 그래서 기다리는 직접 편집을 확정 버튼 자리에 나열합니다. 승인된 항목 2개가 바뀌고, 하나씩 여쭙니다.

- SCR-145#normal: "열린 스레드가 있는 지운 그림은 맨 뒤에 지움 표시로 나오고, 스레드와 AI 제안을 보려고만 열림. 스레드 읽기·답하기·닫기와 제안 거절만 있고, 제안 수락, 새 댓글, 옮기기, 직접 편집, 확정 버튼은 없음(SPEC-027)."이 "열린 스레드, 답을 기다리는 AI 제안, 반영을 기다리는 직접 편집 중 하나가 있는 지운 그림은 맨 뒤에 지움 표시로 나오고, 그것들을 다루려고만 열림. 스레드 읽기·답하기·닫기와 제안 거절이 있고, "이 그림" 칸은 확정 버튼 자리에 반영을 기다리는 직접 편집을 편집 취소와 함께 나열함(휴대폰에서는 편집 취소 없이 목록만). 제안 수락, 새 댓글, 옮기기, 직접 편집, 확정 버튼, 확정 취소는 없음(SPEC-027)."이 됩니다. 전에는 확정 취소를 적지 않았습니다. 지운 그림의 살아 있는 확정은 해가 없어서(WBS 메모 4) 화면은 확정 취소를 보이지 않습니다. API-276은 그것을 받습니다(TASK-446).
- SCR-145#error: "목록에 남은 지운 그림이면 스레드와 제안 거절만 있게 엶(SPEC-027)"이 "목록에 남은 지운 그림이면 스레드, 제안 거절, 기다리는 직접 편집의 편집 취소만 있게 엶(SPEC-027)"이 됩니다.

SCR-146은 그대로입니다. 지운 그림은 바뀐 곳만 보이고 확정 버튼은 없습니다. SCR-144에는 지운 그림에 대한 글이 없고, 프로젝트 화면(TASK-457)은 그림 목록을 보이지 않습니다. 상태 수는 그대로이고, TASK-458과 TASK-460이 그립니다. 이 몫은 따로 체크포인트를 기다려요.
