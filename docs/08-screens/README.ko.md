# NEXUS v3: 화면 상태

[English](README.md)

상태: 08단계 체크포인트를 기다리는 초안입니다.

입력: 사이트맵(07단계, 화면 5개), 기능 명세(04단계), API 계약(06단계의 응답과 오류 코드), 그리고 07단계처럼 출발점으로 삼은 2026-11-21 클릭 목업(프로젝트 기록에 있음). 화면마다 정의 파일 하나를 두고, 상태는 `SCR-142#empty`처럼 적습니다.

## 2. 모든 화면이 같이 따르는 것

- 헤더. 모든 화면에 11-21 목업의 헤더(NEXUS, 프로젝트 메뉴, "내 차례 N", 어두운 화면 스위치)가 있습니다. 수나 메뉴를 읽지 못하면 그것만 빼고 화면의 나머지는 동작합니다.
- 메시지. 화면은 계약(06단계)의 오류 코드 메시지를 한국어로 보여 주고, "문제가 생겼어요" 아래에는 추적 ID를 둡니다. 더 보여 주는 곳은 화면 정의에 적습니다.
- 반복. 요청이 도는 동안 버튼은 꺼지고 결과는 하나만 보입니다. 쓰기마다 새 요청 키를 싣고, 오류 뒤 다시 시도하면 새 키를 만듭니다.
- 오래된 데이터. 화면은 데이터를 읽은 때를 보여 주고, 탭이 다시 보이면 다시 읽습니다. 데이터가 바뀌었다는 409는 사용자가 쓴 글을 남기고 새로 고침을 줍니다.
- 휴대폰. 휴대폰(1056픽셀보다 좁은 터치 화면)에서는 모든 화면이 휴대폰 배치입니다. 한 칸으로 놓고, 작업 패널은 그림 아래 시트(스레드와 댓글 칸)가 됩니다. 옮기기, 직접 편집, 제안 답하기, 확정, 자격, 도구 링크, 삭제는 PC에서 하라는 안내와 함께 보이지 않습니다(SPEC-051). 댓글과 답글은 됩니다. PC에서 창을 좁히면 패널이 그림 아래로 가고 모든 동작은 그대로입니다. 상태마다 360픽셀 프레임이 휴대폰 배치입니다.
- 너비. 상태마다 360픽셀과 1440픽셀(휴대폰과 목업의 너비)로 그립니다. 긴 이름은 단어 단위로 줄을 바꾸고(한국어도), 작업 패널을 화면 밖으로 밀지 않습니다.
- 데이터 노출. 화면은 소유자 오퍼레이션으로 사용자의 데이터만 읽습니다. 에이전트 자격의 비밀값은 발급한 화면에서 한 번만 보이고 다시는 보이지 않습니다.

## 3. 응답과 상태

계약에 있는 오퍼레이션의 모든 응답은 상태로 이어집니다. 기본은 아래와 같고, 다른 곳은 화면 정의가 적습니다. 계약에는 429와 503이 없습니다.

| 응답 | 상태 | 기본으로 보이는 것 |
| --- | --- | --- |
| 200, 201 | normal | 데이터, 또는 그 자리에 보이는 동작의 결과 |
| 200 with nothing in it | empty | 여기에 무엇이 나올지와 어떻게 생기는지 |
| 400, 413 | error | 관련 입력 옆에 메시지, 입력은 그대로 |
| 401 | permission | "다시 로그인하세요". 게이트로 갔다가 이 화면으로 돌아오고, 보내지 못한 댓글은 남김(SPEC-048) |
| 403 | permission | not-owner: "이 NEXUS의 소유자만 열 수 있어요"만 보여 줌. cross-site: "이 변경은 NEXUS 화면에서만 할 수 있어요"와 새로 고침 |
| 404 | error | 더 이상 없다는 것과, 그것이 있던 목록으로 가는 링크 |
| 409 | stale | 바뀌었다는 것: 새로 고친 뒤 다시. 화면마다 다른 곳은 그 화면이 적음(반영 대기, 그려지지 않음, 워크숍) |
| 415, default, a timeout or no network | error | 짧은 메시지와 다시 시도. 화면의 나머지는 그대로 동작 |

## 4. 11-21 목업에서

07단계처럼 목업의 작업대에서 출발했습니다. 작업 패널의 세 칸(이 그림의 상태, AI 제안, 고른 요소)이 SCR-145의 normal 상태이고, 목업의 "확정한 뒤 바뀐 곳" 목록이 SCR-146이 됩니다. 화면 글은 한국어이고, 목업 문구는 이렇게 이어집니다:

| 목업 | v3 | 까닭 |
| --- | --- | --- |
| 이 그림의 상태 · 확정 전 / 확정함 | 그대로 | - |
| AI가 만든 제안이에요. 반영하기 전에는 그림에도, 문서에도 들어가지 않아요. | AI가 만든 제안이에요. 수락하고 에이전트가 반영하기 전에는 문서에 들어가지 않아요. | 반영은 수락 뒤 에이전트의 PR로(07단계 다른 점 5) |
| 반영했어요. 보드에 실선 스티커로 들어갔어요. | 수락했어요. 에이전트가 문서에 넣으면 실선이 돼요. | 07단계 다른 점 5 |
| 거절했어요. | 거절했어요. 스레드는 열려 있어요. | 스레드는 열린 채(SPEC-020) |
| 되돌리기 / AI 이름으로 되돌리기 | 편집 취소(직접 편집만) | 07단계 다른 점 6 |
| 확정한 뒤 바뀐 곳이 N개 있어요. 다시 확정하면 도메인 문서에 반영돼요. | 확정한 뒤 바뀐 곳이 N개 있어요. 다시 확정하면 에이전트가 기록해요. | 07단계 다른 점 7 |
| 확정을 풀었어요. 도메인 문서는 마지막으로 확정한 내용 그대로예요. | 확정을 취소했어요. 다시 확정할 때까지 할 일에 남아요. | SPEC-030 |
| 남은 AI 제안은 확정에 들어가지 않아요. | 그대로 | - |
| 모두 처리함 | 그대로 | - |
| AI가 그린 초안이에요. 스티커를 끌어 옮기고, 두 번 눌러 이름을 바꿔 보세요. | Git 문서에서 그린 그림이에요. 끌어 옮기고, 두 번 눌러 이름을 바꿔 보세요. | 그림의 원본은 Git(SPEC-001) |

## 6. 체크포인트

화면 정의를 구현 전에 승인합니다. 이 단계가 없애거나 미루거나 바꾸는 승인된 항목은 없습니다. 승인된 행을 좁게 읽은 곳 1개는 따로 물었고, 답이 없으면 그 행은 승인된 대로 남습니다.

| 항목 | 승인된 글 | 이 단계가 읽은 것 | 까닭 |
| --- | --- | --- | --- |
| SPEC-051 | 확정, 제안 답, 직접 편집, 옮기기 → 내놓지 않고 PC를 쓰라고 알림. | 휴대폰에서는 에이전트 자격 발급·폐기, 도구 링크 잇기, 프로젝트 공간 삭제도 내놓지 않음. | 01단계 핫스팟 5의 답이 휴대폰은 "보기와 댓글만"이었고(REQ-068), SPEC-051은 동작 넷을 적고 이 셋은 적지 않았습니다. 비밀값은 한 번만 보이고(SPEC-049) 삭제는 되돌릴 수 없어서 둘 다 PC에 둡니다. |
