# SCR-113 문서 단계

[English](SCR-113-document-stage.md)

목적: 프로젝트의 작업 공간에서 사용자는 그림이 없는 단계, 곧 02의 요구사항이나 12의 QA 사례를 봅니다: 기록된 상태, 마지막 확인 지점, 커밋, 수를 단 단계 머리와, 대화가 있는 것, 사용자를 기다리는 것, 남은 것으로 좁히는 항목 목록. 항목을 골라 읽고 그것에 대해 대화하고, 단계 기록에서 확인 지점을 통과시킵니다. 같은 목록이 그림 단계의 목록 탭입니다. (FL-118, FL-119)

경로 `01-domain`, `05-erd`, `07-sitemap`을 뺀 열 단계의 `/p/{project}/{part}/{stage}`, 그리고 그 세 단계의 `#view=list`. NEXUS 서버에만 있고(API-154), 작업 공간(SCR-111)의 가운데에 있습니다. 볼 수 있는 사람: Cloudflare Access가 들여보낸 누구나. 2026-11-06 다시 디자인에서 계획한 화면입니다(SPEC-147, SPEC-148). 단계 자세히 보기(SCR-104)와 단계 현황(SCR-109)을 담고, 현황의 "남은 것"은 거르기가 됩니다. [모든 화면](README.ko.md#모든-화면)과 [다시 디자인](README.ko.md#다시-디자인의-화면)의 규칙을 따릅니다.

## 자료

| 자료 | 출처 |
| --- | --- |
| 머리: 단계의 번호와 이름, 기록된 상태, 마지막 확인 지점과 그 날짜, 단계가 보여 주는 커밋과 그 때, 그리고 02의 우선순위별 요구사항이나 12의 결과별 사례 같은 그 수(REQ-226) | API-158(`head`), 먼저 페이지의 자료에서 |
| 단계 기록: 기록된 상태, 다음 행동, 확인 지점, 점검과 찾은 것, 그리고 기록을 기다리는 NEXUS에서 통과시킨 확인 지점(SPEC-138) | API-158(`record`) |
| 프로젝트가 그 단계를 읽는지, 읽지 않으면 글 원본의 상태에서 나온 그 까닭 | API-158(`head.reads`) |
| 항목, 200개씩: 하나하나 ID, 원본 그대로의 제목이나 문장, 요구사항의 우선순위와 상태 같은 주요 필드, 의견 수, 내 차례면 그 표시, 열린 어긋남과 반영 대기의 표시. 컨텍스트별로 묶고 컨텍스트가 없는 항목은 끝에 두거나, 원본의 차례대로(REQ-227) | API-158(`items`, `after`, `group`), 처음 200개는 페이지의 자료에서 |
| 거르기(모두, 대화 있음, 내 차례, 남은 것)와 단계 안에서 찾는 말 | 열려 있는 동안 페이지에 둠. `filter`와 `q`로 보냄(API-158). 첫 페이지의 AI 할 일(SCR-110)에서 온 `#filter=left` 주소는 그림 단계에서도 남은 것으로 거른 목록을 엽니다 |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 거르기 고르기: 모두, 대화 있음, 내 차례, 남은 것 | 목록이 의견이 있는 항목, 사용자를 기다리는 것이 있는 항목, 열린 어긋남·의견·반영 대기가 있는 항목으로 좁혀지고, 몇 개인지 보입니다(REQ-176) | SCR-113#no-match, SCR-113#error |
| 이 단계에서 찾기, 한 글자부터 | 목록이 ID나 제목에 모든 낱말을 대소문자 가리지 않고 담은 항목으로 좁혀집니다 | SCR-113#no-match |
| 컨텍스트별, 또는 원문 순서 | 목록을 항목의 컨텍스트별로 묶거나 원본의 차례대로 늘어놓습니다 | 없음 |
| 목록 끝까지 내리기 | 다음 항목 200개. 그동안 마지막 행에 "더 불러오는 중…" | 마지막 행에 "더 불러오지 못했습니다."와 다시 시도 |
| 항목을 고르거나 `#item=` 주소 열기 | 단계 옆의 항목 SCR-115와 그 항목으로 좁힌 대화. 그 행은 고른 것으로 보입니다 | 단계에 없는 ID: SCR-115#gone |
| 항목의 의견 수 고르기 | 그 항목으로 좁힌 대화(SCR-114) | 없음 |
| 단계 기록, 통과, 철회 | SCR-112와 같음(SPEC-138, SPEC-139) | SCR-113#stale, SCR-113#error, SCR-113#permission |
| 다시 불러오기 | 같은 주소의 페이지를 서버에서 다시 받음 | SCR-111#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이어지는 응답 |
| --- | --- | --- |
| SCR-113#loading | 서버가 페이지의 자료로 그린 머리와 처음 200개 항목이 SCR-113#normal의 배치대로 보입니다. 거르기, 찾기, 기록의 쓰기는 보기의 코드를 기다리며 막혀 보입니다([규칙 15](README.ko.md#다시-디자인의-화면)). 더 불러오기: 마지막 행에 "더 불러오는 중…" | API-154#200, API-104#200 |
| SCR-113#normal | 머리: 단계의 번호와 이름, 모양과 말로 쓴 상태, "마지막 확인 지점 {date}"나 "아직 확인 지점 없음", "커밋 {commit} · {time}", 그 수, 단계 기록. 그 아래 저마다 수를 단 거르기, 이 단계에서 찾기, 묶기. 목록: 묶음마다 그 컨텍스트의 ID와 이름, 수를 단 제목. 항목마다 한 행에 ID, 원본 그대로 그 언어로 쓴 글, 이름은 페이지의 언어로 쓴 주요 필드, 의견 수, 그리고 화면 낭독기를 위한 말을 단 표시: 내 차례, 어긋남, 반영 대기. 고른 행은 강조색 막대로. 더 남은 동안 끝에 "{total}개 중 {n}개" | API-154#200, API-158#200, `changed: true`인 API-128#201과 API-129#200 |
| SCR-113#empty | 프로젝트가 읽는데 아직 항목이 없는 단계: 목록 자리에 "이 단계에는 아직 항목이 없습니다." 머리, 기록, 단계 전체에 대한 대화는 남습니다 | 항목이 없는 API-158#200 |
| SCR-113#not-read | 프로젝트가 읽지 않는 단계: 머리가 글 원본의 상태에서 나온 그 까닭을 말하고, 목록 자리에 "이 프로젝트는 이 단계를 읽지 않습니다: {why}. 그래도 확인 지점은 통과시킬 수 있습니다."와 단계 기록(SPEC-147, SPEC-148) | `head.reads`가 거짓인 API-158#200 |
| SCR-113#no-match | 맞는 것이 없는 거르기나 찾기: "이 단계에는 내 답을 기다리는 것이 없습니다.", "이 단계에 남은 것이 없습니다.", "이 단계에는 아직 대화가 있는 항목이 없습니다.", "이 단계에서 “{q}”에 맞는 항목이 없습니다."와, 거르기와 찾기를 지우는 모두 보기 | `filter`나 `q`에 맞는 항목이 없는 API-158#200 |
| SCR-113#stale | 어느 기록도 적지 않은 NEXUS에서 통과시킨 확인 지점, 그사이 기록됐거나 이미 철회된 확인 지점: 머리와 기록에서 SCR-112#stale과 같음. 목록을 다시 읽다 찾은 새로 올라온 것: SCR-111#stale의 막대, 목록은 다시 불러올 때까지 그린 것을 지킵니다 | API-158#200, API-129#409(`checkpoint_recorded`), `changed: false`인 API-129#200 |
| SCR-113#error | 페이지의 요청: SCR-111#error. 실패한 거르기, 찾기, 다음 200개: 목록은 남고 "새로 읽지 못했습니다. 보이는 내용이 최신이 아닐 수 있습니다."와 다시 시도, 또는 마지막 행에 "더 불러오지 못했습니다." 통과·철회: SCR-112#error와 같음. 연결 없음, 30초 안에 답 없음, `429`나 `503`: 규칙 8 | API-158#404(`project_not_found`, `space_not_found`, `part_not_found`, `not_found`), API-158#default(`internal`, `method_not_allowed`), 그리고 SCR-112#error의 API-128과 API-129 응답 |
| SCR-113#permission | 다시 읽기: 막대에 코드의 메시지. 통과·철회: SCR-112#permission과 같음. 끝난 로그인: [규칙 7](README.ko.md#모든-화면), 쓴 말은 남습니다 | API-158#403(`access_missing`, `access_other_app`), API-128#403, API-129#403(`user_only`, `access_missing`, `access_other_app`), `opaqueredirect` 응답이나 `401` |

단계의 모든 상태가 해당하고, 목록 자신의 상태 두 개가 더해집니다: 프로젝트가 읽지 않는 단계의 not-read와, 맞는 것이 없는 거르기나 찾기의 no-match.

## 경우의 수

| 종류 | 사용자가 보는 것 |
| --- | --- |
| 접근 | Access 자신의 로그인 페이지나 거절이 페이지보다 먼저 옵니다. Worker의 `403`과 끝난 로그인: SCR-113#permission. 통과와 철회에는 사람 본인의 로그인이 필요합니다: `user_only` |
| 입력 | 이 단계에서 찾기, 200자까지, `q`로 보냅니다. 확인 지점의 남길 말, 2,000자까지(규칙 5) |
| 대상 | 서버에 없는 부분이나 프로젝트: SCR-111#error. 공간이 없는 프로젝트는 SCR-111의 대상이 말하듯 목록을 보이고, 대화 자리에 `space_not_found`의 메시지를 둡니다. 단계에 없는 항목을 가리키는 주소: SCR-115#gone. 프로젝트가 읽지 않는 단계: SCR-113#not-read |
| 상태 변화 | 기록을 기다리거나 그사이 기록된 확인 지점, 새로 올라온 것: SCR-113#stale |
| 되풀이 | 통과와 철회는 도는 동안 막힙니다. 같은 거르기를 두 번 골라도 한 번 읽습니다 |
| 동시성 | 다른 탭이나 AI가 쓴 것은 목록을 다시 읽을 때 수와 표시에 보입니다(규칙 6) |
| 상한 | 한 번에 항목 200개, 내리면 더, "{total}개 중 {n}개"와 함께. 999를 넘는 수는 `999+`. NEXUS의 12단계는 사례 717개로, 네 번 읽어 다 옵니다 |
| 바깥 서비스 | 없음: 코드, 스타일, 글꼴은 서버에서만 옵니다(REQ-147) |
| 자료 노출 | 스냅샷의 항목을 글로만(REQ-098). "사용자"나 "AI" 말고는 신원이 없습니다(규칙 11) |
| 빈 응답과 스트림 | 항목 없음: SCR-113#empty. 읽지 않음: SCR-113#not-read. 맞는 것 없음: SCR-113#no-match. 스트림은 없습니다 |
| 화면 상태 | 모든 상태를 390과 1440픽셀에서 두 테마로, [redesign.html](../../09-mockup/nexus/redesign.html#scr-113)에 |
| AI 응답 | 없음: NEXUS는 AI 모델을 부르지 않습니다(REQ-121) |

| --- | --- | --- |
| 머리 | 탭 아래: 상태, 마지막 확인 지점, 커밋을 줄을 바꾸는 한 줄에, 수를 둘째 줄에, 그리고 단계 기록 | 한 줄: 번호와 이름, 상태, 마지막 확인 지점, 커밋, 그 오른쪽 끝에 수와 단계 기록 |
| 거르기와 찾기 | 거르기 넷을 줄을 바꾸는 한 줄에, 그다음 너비 가득 찾기, 묶기는 메뉴에 | 한 줄: 거르기, 너비 280픽셀의 찾기, 묶기 |
| 목록 | 항목마다 쌓아서: 첫 줄에 ID와 표시, 그 아래 글, 마지막 줄에 줄을 바꾸는 필드. 행은 높이 44픽셀 이상 | 항목마다 한 행의 열: ID 112픽셀, 글, 필드, 의견, 표시. 글이 한 줄에 들면 행은 높이 36픽셀 |
| 묶음 제목 | 너비 가득 한 줄에 컨텍스트의 ID, 이름, 수 | 같은 줄을 묶음의 행 위에 |
| 단계 기록 | 높이의 85퍼센트까지 올라오는 시트 | 대화 자리인 너비 400픽셀의 옆에 |
