# SCR-114 대화

[English](SCR-114-talk.md)

목적: 사용자는 프로젝트 작업 공간의 어느 단계 옆에서든 그 단계의 의견과 제안을 차례별로 읽습니다: 사용자를 기다리는 것을 먼저, 그다음 AI를 기다리는 것과 세션이 그것을 맡았는지, 그리고 접힌 닫힌 것. 고른 항목으로 대화를 좁히고, 항목이나 단계 전체에 의견을 남기며, 답글을 달고, 의견을 정하고, 답이 났다고 표시하고, 제안을 받거나 버립니다. (FL-117, FL-119)

경로 `/p/{project}/{part}/{stage}#talk={comment}`, 또는 그것이 없는 단계의 페이지. NEXUS 서버에만 있고(API-154), 작업 공간(SCR-111)의 옆에 있습니다. 볼 수 있는 사람: Cloudflare Access가 들여보낸 누구나. 2026-11-06 다시 디자인에서 계획한 화면입니다(SPEC-150, SPEC-151, 그리고 SPEC-126, SPEC-127, SPEC-131, SPEC-133). 의견(SCR-107)과 제안(SCR-108)을 받아들이고, 그 주소는 여기로 이어집니다(SPEC-154). [모든 화면](README.ko.md#모든-화면)과 [다시 디자인](README.ko.md#다시-디자인의-화면)의 규칙을 따릅니다.

## 자료

| 자료 | 출처 |
| --- | --- |
| 부분의 단계 대화: 열린 제안과 의견, 사용자를 기다리는 것을 먼저. 하나하나 그 항목과 인용 또는 단계 전체, 쓴 이의 종류와 때, 마지막 답글, 무엇을 묻는지, 언제부터 기다리는지, 그리고 세션이 그것을 맡은 동안에는 AI가 맡은 때. 스냅샷에 그 항목이 더는 없는 의견은 따로. 그리고 닫힌 것의 수 | API-152, 먼저 페이지의 자료에서 |
| 한 항목으로 좁힌 대화 | 항목을 고른 동안(SCR-115) `item`을 단 API-152 |
| 닫힌 대화, 새것부터 50개씩 | `closed=1`을 단 API-152 |
| 연 의견의 답글 | API-114 |
| 제안의 변경, 까닭, 단계 원본의 글, 그리고 그 반영 | API-115, 대화가 더는 늘어놓지 않는 반영은 API-116 |
| 열 줄 | `#` 뒤의 페이지 주소: 의견이나 제안의 ID를 단 `talk=`. 0.2의 `comment=`와 `proposal=`도 같게 읽습니다(SPEC-154) |
| 보내지 않은 글: 의견이나 답글의 글과 그 쓰기 ID | 부분, 단계, 항목이나 의견마다 브라우저의 저장소(규칙 5) |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 의견을 쓰고 남기기 | 항목을 고른 동안에는 의견이 그 항목에 남고, 사용자가 그림의 한 부분을 골랐으면 그 인용이 붙습니다. 아무것도 고르지 않았으면 단계 전체에 남습니다(SPEC-151, API-118). 의견은 사용자의 것으로 표시되어 AI 차례 아래에 보이고, 대화를 다시 읽습니다 | 글을 그대로 둔 SCR-114#error나 SCR-114#permission |
| 줄 열기 | 그 아래에 답글이, 제안이면 그 변경, 까닭, 단계 원본의 글이 그 자신의 상자에(SCR-108의 내용) 보입니다 | SCR-114#gone, SCR-114#error |
| 답글 달기, "이것으로 정함"과 함께 또는 없이 | 의견 아래에 답글. 정하면 의견은 AI의 기록을 기다립니다(SPEC-127, SPEC-132). 닫힌 의견에서는 "답글 달고 다시 열기"가 의견을 다시 엽니다(REQ-203) | 위와 같음 |
| 답이 났다고 표시 | 의견이 답이 나서 닫히고 닫힌 대화로 접힙니다(SPEC-127, API-120) | 위와 같음 |
| 제안을 받기나 버리기, 그 반영 버리기 | SCR-108에서처럼: 받으면 항목에 "받음, 아직 반영 전"이 보이고, 버리면 그 의견은 열린 채로 남습니다(SPEC-131, SPEC-133) | SCR-114#stale, SCR-114#error, SCR-114#permission |
| 그림이나 목록에서 항목 고르기, 또는 줄의 항목 열기 | 대화가 그 항목으로 좁혀지고, 돌아가는 "단계의 대화 모두"가 붙습니다(REQ-230). 항목은 옆에 SCR-115로 보입니다 | 없음 |
| 닫힌 대화 보기 | 닫힌 의견과 제안을 50개씩, "더 보기"와 함께 | SCR-114#error |
| 연 줄에서 닫기, Escape, 브라우저의 뒤로 단추 | 줄이 접히고 주소에서 `talk=`가 빠집니다 | 없음 |

## 경우의 수

| 종류 | 사용자가 보는 것 |
| --- | --- |
| 접근 | Worker의 `403`과 끝난 로그인: SCR-114#permission. 받기와 버리기에는 사람 본인의 로그인이 필요합니다: 서비스 토큰에는 `user_only`. AI는 허브를 거쳐 씁니다(FL-109) |
| 입력 | 의견이나 답글은 4,000자까지이고, 서버가 받을 때까지 그 칸과 브라우저의 저장소에 쓰기 ID와 함께 남습니다. 90퍼센트부터 남은 글자 수가 보입니다. 빈 글이나 공백뿐인 글은 보내지 않습니다(규칙 5) |
| 대상 | 서버에 없는 의견이나 제안: SCR-114#gone. 올리기가 그 항목을 지운 의견: 열린 채로 따로 보입니다(REQ-162). 13개 밖의 단계 키: `400`. 스냅샷에 없는 부분: `404`(SPEC-151) |
| 상태 변화 | 다른 탭에서 닫힌 의견, 더는 열려 있지 않은 제안, 바뀐 반영: SCR-114#stale. 세션이 맡은 줄: "{time}에 AI가 맡음", 그래도 사용자의 답글은 받습니다(SPEC-136) |
| 되풀이 | 쓰기가 도는 동안 그 단추는 막히고 "보내는 중…"이라고 말합니다. 답을 잃은 뒤의 다시 시도는 같은 쓰기 ID를 보내므로 결과는 하나입니다(SPEC-126) |
| 동시성 | AI의 답글과 다른 탭의 쓰기는 대화가 다시 읽을 때 보입니다: 쓰기 뒤와 페이지가 다시 보일 때(규칙 6) |
| 상한 | 프로젝트에 의견 2,000개(REQ-116), 넘으면 `comment_limit`. 의견의 답글은 그 한도까지, 그다음은 새 의견. 닫힌 대화는 50개씩. 999를 넘는 수는 `999+` |
| 바깥 서비스 | 없음: 대화의 요청은 서버에만 갑니다(REQ-147) |
| 자료 노출 | 의견, 답글, 단계 원본의 글은 글로만(REQ-098, REQ-148). "사용자"나 "AI" 말고는 신원이 없습니다(규칙 11, REQ-163) |
| 빈 응답과 스트림 | 대화 없음: SCR-114#empty. 스트림은 없습니다: 대화는 스스로 새로 바뀌지 않습니다(SPEC-150) |
| 화면 상태 | 모든 상태를 390과 1440픽셀에서 두 테마로, [redesign.html](../../09-mockup/nexus/redesign.html#scr-114)에 |
| AI 응답 | 없음: NEXUS는 AI 모델을 부르지 않습니다(REQ-121). AI는 다음 작업 때 답하고, 대화는 그것을 칸 옆과 AI 차례의 줄마다 말합니다(01단계의 핫스팟 6) |
