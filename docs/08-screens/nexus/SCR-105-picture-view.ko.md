# SCR-105 그림 보기

[English](SCR-105-picture-view.md)

목적: 사용자는 휴대폰이나 PC에서 한 부분의 한 단계 그림, 곧 DDD 보드, ERD, 사이트맵을 그 문서 판, 그리고 그 항목 위의 열린 의견, 제안, 어긋남과 함께 보고, 거기서 항목, 의견, 제안을 엽니다. (FL-106, FL-110, FL-115)

경로 `/pictures/{project}/{part}/{stage}`. NEXUS 서버에만 있고(API-102), 단계 자세히 보기(SCR-104)와 단계 현황(SCR-109)이 잇습니다. 볼 수 있는 사람: Cloudflare Access가 들여보낸 누구나. NEXUS 0.2에서 새로 생깁니다(SPEC-119). [모든 화면](README.ko.md#모든-화면)의 규칙을 따릅니다.

## 자료

| 자료 | 출처 |
| --- | --- |
| 페이지: 프로젝트, 부분, 단계, 그리고 `view-data`에 API-111의 답이나 문제 `picture_not_found` | API-102(`corthex-view-page/0.2`) |
| 보기의 코드: 핵심 파일과 그림 종류의 읽기 전용 편집기, DDD 보드와 사이트맵에는 Excalidraw, ERD에는 ERD Editor(02단계의 D11) | API-104 |
| 그림 자료, 그 문서 판인 커밋과 커밋 시각, 그린 때, 최신인지와 그 까닭 | API-111(`picture`), 처음에는 페이지의 자료에서 |
| 열린 의견을 최근에 움직인 것부터, 저마다 답글 수와 마지막 답글과 함께, 그리고 닫힌 의견의 ID | API-111(`comments`, `closed_comments`) |
| 열린 제안을 그 단계 원본의 글 없이, 그리고 닫히지 않은 반영 | API-111(`proposals`, `reflections`) |
| 그림에 걸린 부분의 열린 어긋남, 최신 그림을 기다리는 것은 표시와 함께 | API-111(`discrepancies`) |
| 그림에 이제 없는 항목에 달린 의견, 제안, 어긋남, 그리고 그림이 이제 그리지 않는 부분을 인용한 그림 자체의 의견 | 보기가 API-111의 항목과 그림의 항목에서 찾음(SPEC-119) |
| 열 패널 | 페이지 주소의 `#` 뒤: `item=`, `comment=`, `proposal=` |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 항목 고르기, 또는 `#item=`이 붙은 주소 열기 | 항목 패널 SCR-106 | 그림에 없는 ID: SCR-106#gone |
| ID 없이 그린 부분 고르기 | 그 부분의 이름을 단, 그림 자체에 대한 항목 패널 SCR-106([고른 것 12](README.ko.md#이-단계가-고른-것)) | 없음 |
| 의견 표시 고르기, 또는 `#comment=` 열기 | 의견 패널 SCR-107 | SCR-107#gone |
| 제안 표시 고르기, 또는 `#proposal=` 열기 | 제안 패널 SCR-108 | SCR-108#gone |
| 그림 옮기기, 크게 작게 하기 | 그림이 자기 틀 안에서 움직이고, 페이지는 옆으로 밀리지 않음(REQ-146) | 없음 |
| 항목을 목록으로 보기 | 그림의 모든 항목과 ID 없이 그린 부분을 그 이름으로, 표시와 함께 목록으로, 거기서 패널이 열림. 화면 낭독기도 같은 목록을 읽음 | 없음 |
| 새 판 보기 | 새 자료로 다시 그린 그림 | 읽기 실패: SCR-105#error |
| 단계 현황이나 허브 페이지 열기 | 그 부분과 단계의 SCR-109, 또는 SCR-101 | 그 페이지 자신의 거절 |
| 다시 불러오기 | 서버에서 다시 받은 페이지 | SCR-105#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이어지는 응답 |
| --- | --- | --- |
| SCR-105#loading | 위 막대에 프로젝트, 부분, 단계, 그리고 그림 틀에 "그림을 그리는 중…"이 적힌 회색 자리. 표시와 패널은 그림이 그려지기를 기다립니다. 보기의 코드가 돌기 전에는 페이지가 고정 문구 "그림 보기를 불러오는 중입니다. 나타나지 않으면 페이지를 다시 불러와 주세요."와 다시 불러오는 링크만 보입니다 | API-102#200, API-104#200 |
| SCR-105#normal | 위 막대: 허브 페이지, 프로젝트·부분·단계, 단계 현황. 그 아래 문서 판 "커밋 {commit}, {time}". 읽기 전용으로 매번 같은 방식으로 배치한 그림(SPEC-119)이 자기 틀 안에서 움직입니다. 열린 의견, 제안, 어긋남이 있는 항목마다 그 수를 단 표시, 그림 자체의 열린 의견이 이름을 인용한 ID 없는 부분에는 그 의견 수를 단 표시, 그리고 반영이 닫히지 않은 받은 제안의 항목에는 "받음, 아직 반영 전"(SPEC-131). 그림 아래에, 1,024픽셀부터는 옆에: "따로: 항목이 없어진 의견 ({n})", 항목을 목록으로 보기, 표시의 설명 | API-102#200, API-111#200 |
| SCR-105#large | SCR-105#normal과 같고, 틀 위에 "이 그림은 요소가 {n}개로 커서 그리는 데 시간이 더 걸릴 수 있습니다."가 붙습니다. 3초 목표 없이 그립니다(SPEC-119) | 요소가 300개를 넘는 API-111#200 |
| SCR-105#empty | 그림 없음: `why`에 따른 `picture_not_found`의 메시지, 곧 아직 그리지 않음, 크기 때문에 빠짐, 원본이 다른 저장소에 있음([메시지](README.ko.md#메시지)), 그리고 단계 현황과 허브 페이지로 가는 링크 | 문제 `picture_not_found`를 담은 API-102#200, API-111#404(`picture_not_found`) |
| SCR-105#stale | 최신이 아닌 그림: 틀 위에 이 그림이 보이는 커밋과 `not_current`에 따른 까닭, 곧 최신 원본이 스냅샷에 담을 수 있는 크기보다 큼, 저장소에서 사라짐, 다른 저장소에 있음을 알리는 안내. 그림은 그대로 쓸 수 있습니다. 최신 그림을 기다리는 어긋남: 그 표시가 그렇다고 알립니다(`waiting`). 쓰기나 다시 읽기 뒤 그린 것보다 새 커밋의 그림: 그린 그림은 그대로 두고 "서버에 이 그림의 새 판이 있습니다."와 보기([고른 것 6](README.ko.md#이-단계가-고른-것)) | API-111#200 |
| SCR-105#error | 페이지의 요청: [규칙 9](README.ko.md#모든-화면)의 메시지 페이지에 코드의 메시지, 추적 ID, 허브 페이지 링크. `internal`이면 다시 불러오기. 페이지의 문제가 `picture_not_found`가 아닌 다른 것이면 그 메시지를 같은 방식으로. 다시 읽기(규칙 6): 그린 그림은 그대로 두고 그림 위 막대에 같은 메시지, 또는 "새로 읽지 못했습니다"와 다시 시도. 연결 없음, 30초 안에 답 없음, `429`나 `503`: 규칙 8 | API-102#404(`project_not_found`, `space_not_found`, `part_not_found`, `not_found`), API-102#default(`internal`, `method_not_allowed`), API-111#404(`project_not_found`, `space_not_found`, `part_not_found`, `not_found`), API-111#default(`internal`, `method_not_allowed`) |
| SCR-105#code-failed | 편집기의 코드를 불러오지 못하거나 코드가 실패함: "여기서는 그림을 그리지 못해 항목을 목록으로 보여 드립니다."와 표시를 단 항목 목록. 패널은 거기서 그대로 열립니다(SPEC-119). 핵심 파일을 불러오지 못함: 페이지의 고정 문구와 그 링크만 남습니다. 브라우저는 코드 파일을 왜 불러오지 못했는지 페이지에 알려 주지 않으므로, API-104의 모든 실패가 여기로 옵니다 | API-104#403(`access_missing`, `access_other_app`), API-104#404(`not_found`), API-104#default(`internal`, `method_not_allowed`) |
| SCR-105#permission | 페이지의 요청: 코드의 메시지를 담은 메시지 페이지. 다시 읽기: 그림 위 막대에 코드의 메시지. 보기가 열린 동안 끝난 로그인: [규칙 7](README.ko.md#모든-화면)의 다시 로그인, 패널에 쓴 것은 그대로 | API-102#403(`access_missing`, `access_other_app`), API-111#403(`access_missing`, `access_other_app`), `opaqueredirect` 응답이나 `401` |

단계의 모든 상태가 해당하고, 화면 자신의 상태 large와 code-failed 두 개가 더해집니다. ② 차례는 1,024픽셀 이상의 PC에서 고치기를 더합니다(SPEC-134, FL-115). NEXUS 0.2는 그림을 읽기 전용으로 그리고 고치기 단추가 없습니다.

## 경우의 수

| 종류 | 사용자가 보는 것 |
| --- | --- |
| 접근 | Access 자신의 로그인 페이지나 거절이 페이지보다 먼저 옵니다. Worker의 `403`과 끝난 로그인: SCR-105#permission |
| 입력 | 보기 자신에는 닿지 않습니다: 입력은 그 패널이 받습니다(SCR-106\~SCR-108) |
| 대상 | 서버에 없는 프로젝트, 공간, 부분, 단계: SCR-105#error. 그림 없음: SCR-105#empty. 그림에 없는 항목, 의견, 제안을 가리키는 주소: SCR-106#gone, SCR-107#gone, SCR-108#gone |
| 상태 변화 | 최신이 아닌 그림, 기다리는 어긋남, 쓰기 뒤의 새 그림: SCR-105#stale. 아직 반영 전인 받은 제안: SCR-105#normal의 그 표시 |
| 되풀이 | 새 판 보기와 다시 불러오기는 도는 동안 막힙니다 |
| 동시성 | 다른 탭이나 에이전트가 쓴 것은 보기가 다시 읽을 때(규칙 6)나 다시 불러온 뒤 보입니다 |
| 상한 | 요소가 300개를 넘음: SCR-105#large. 목록은 저마다 500개, 어긋남은 1,000개에서 멈추고 "612개 중 500개"처럼 전체 수를 보입니다 |
| 바깥 서비스 | 없음: 보기는 코드, 스타일, 글꼴을 서버에서만 불러오고(REQ-147) 요청도 서버에만 보냅니다 |
| 자료 노출 | 그림과 그 항목뿐입니다. 제안의 단계 원본 글은 그 패널에서만 보이고(API-115), 쓴 쪽의 종류 말고는 신원이 없습니다 |
| 빈 응답과 스트림 | 그림 없음: SCR-105#empty. 걸린 것이 없는 그림은 표시도 "따로"도 보이지 않습니다. 스트림은 없습니다 |
| 화면 상태 | 모든 상태를 320과 1440픽셀에서, [와이어프레임](wireframes.html#scr-105)에. 09단계에서 A 방향으로 그린 것은 [목업](../../09-mockup/nexus/mockup.html#scr-105)에 |
| AI 응답 | 없음: NEXUS는 AI 모델을 부르지 않습니다(REQ-121) |

## 배치

| 영역 | 320픽셀에서 | 1440픽셀에서 |
| --- | --- | --- |
| 위 막대 | 허브 페이지, 그다음 줄에 줄을 바꾸는 프로젝트·부분·단계, 그리고 단계 현황 | 한 줄에 허브 페이지, 프로젝트·부분·단계, 문서 판, 단계 현황 |
| 안내 | 상태마다의 안내를 위 막대 아래에 너비 가득 막대로 | 같은 막대를 그림 위에 |

| 따로 보기와 목록 | 틀 아래에 "따로 ({n})", 항목을 목록으로 보기, 표시의 설명 | 패널이 열리지 않은 동안 너비 400픽셀의 옆 패널에 |
| 패널 | 그림 위로 높이의 85퍼센트까지 올라오는 아래쪽 시트 | 그림 옆, 너비 400픽셀의 옆 패널 |
