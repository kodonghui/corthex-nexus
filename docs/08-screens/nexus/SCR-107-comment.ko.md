# SCR-107 의견

[English](SCR-107-comment.md)

목적: 사용자는 의견 하나를 그 모든 답글, 결정, 그것에 답한 제안과 함께 읽고, 답글을 달거나 의견을 정하거나 답이 났다고 표시하거나 다시 엽니다. (FL-107, FL-109)

경로 `/pictures/{project}/{part}/{stage}#comment={comment}`. 그림 보기(SCR-105)의 패널이고 NEXUS 서버에만 있으며, 그 표시, 항목 패널, 단계 현황, 세션 속 링크에서 열립니다. 볼 수 있는 사람: Cloudflare Access가 들여보낸 누구나. NEXUS 0.2에서 새로 생깁니다(SPEC-127, SPEC-132). [모든 화면](README.ko.md#모든-화면)의 규칙을 따릅니다. 07단계의 변경 2로 FL-107도 그 답글을 여기서 보입니다.

## 자료

| 자료 | 출처 |
| --- | --- |
| 의견: 그 항목과 인용, 그것이 적은 어긋남, 그것을 단 커밋, 쓴 쪽의 종류, 글, 시각, 열렸는지 닫혔는지와 닫힌 까닭, 누구를 기다리는지, 사용자가 정했는지, 마지막 제안을 버렸는지 | 먼저 API-111(`comments`), 그다음 API-114 |
| 그 모든 답글을 차례대로 200개까지, 저마다 쓴 쪽의 종류, 글, 시각, 그리고 그것으로 의견을 정하는지 | API-114(`replies`) |
| 그 결정, 저마다 링크와 글 | API-114(`decisions`) |
| 그것에 답한 제안과 그 상태 | API-114(`proposals`) |
| 쓰고 있는 답글, 그것으로 의견을 정하는지, 그 쓰기 ID | 답글 칸과, 그 의견의 브라우저 저장소([규칙 5](README.ko.md#모든-화면)) |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 답글 달기 | "사용자"가 쓴 답글이 끝에 붙고, 의견은 에이전트를 기다립니다(SPEC-127) | 저장되지 않음: 글은 그대로 두고 SCR-107#error나 SCR-107#permission |
| "이것으로 정함"을 고르고 의견을 정하는 답글 달기 | 의견은 열린 채로 "사용자가 정함, 에이전트의 기록을 기다림"(SPEC-127, SPEC-132) | 위와 같음 |
| 닫힌 의견에 "답글 달고 다시 열기" | 의견이 다시 열리고 에이전트를 기다립니다 | 위와 같음 |
| 열린 의견에 답이 났다고 표시 | 의견이 답이 나서 닫힙니다(REQ-166) | 그사이 닫힘: SCR-107#stale. 그 밖에는 SCR-107#error |
| 제안이나 결정의 링크 열기 | 제안 패널 SCR-108, 또는 결정을 적은 곳 | SCR-108#gone |
| `reply_limit` 뒤 새 의견 남기기 | 답글의 글을 칸으로 옮긴 항목 패널 SCR-106 | SCR-106과 같음 |
| 닫기, Escape, 브라우저의 뒤로 단추 | `#comment=`이 빠진 주소의 그림 | 없음 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이어지는 응답 |
| --- | --- | --- |
| SCR-107#loading | 그림의 자료가 담은 의견, 곧 그 글, 쓴 쪽, 상태, 마지막 답글, 닫힌 의견이면 그 항목과 닫힌 까닭이 보이고, 다른 답글 자리에 회색 줄이 있습니다. 답글 칸은 쓸 수 있고, 답글 달기와 답이 났다고 표시는 의견을 기다립니다 | API-114를 보낸 뒤, 그 답이 오기 전 |
| SCR-107#normal | 제목으로 항목의 ID와 의견의 상태가 포커스를 받고 닫기가 함께 있습니다: "에이전트를 기다림", "사용자를 기다림", "사용자가 정함, 에이전트의 기록을 기다림", "제안을 버림", "답이 나서 닫힘", "결정으로 닫힘". 그 아래 의견, 차례대로의 답글(의견을 정한 답글에는 "정함"), 링크를 단 결정, 그것에 답한 제안과 저마다의 상태와 열기, 그리고 "이것으로 정함", 답글 달기(닫힌 의견에서는 "답글 달고 다시 열기"), 열린 의견에서는 답이 났다고 표시가 달린 답글 칸. 답글이 없으면 "아직 답글이 없습니다." 프로젝트의 다른 그림에 단 의견은 그 그림으로 가는 링크와 함께 보입니다 | API-114#200, API-119#201, `changed: true`인 API-120#200 |
| SCR-107#stale | 쓰기의 답이나 다시 읽은 의견이 그사이 바뀐 것을 보일 때: 답이 났다고 표시 뒤의 "이 의견은 이미 닫혀 있었습니다.", 그리고 패널을 연 뒤 새로 붙은 에이전트의 답글에 새 것이라는 표시. 패널은 이제 지금의 의견을 보입니다 | `changed: false`인 API-120#200 |
| SCR-107#error | 읽기: "이 의견을 불러오지 못했습니다."와 다시 시도, 그리고 그림의 자료가 담은 의견. 쓰기: 칸 위에 메시지, 글은 그대로 두고 같은 쓰기 ID로 보내는 다시 보내기: 가리킨 칸 옆의 `invalid_request`, 서버 자체 주소의 이 페이지로 가는 링크를 단 `cross_site`, 새 의견 남기기를 단 `reply_limit`의 "이 의견에 달 수 있는 답글(200개)이 다 찼습니다. 새 의견으로 남겨 주세요.", `space_full`, 다시 보내기가 새 쓰기 ID를 만드는 `write_id_reused`, 칸 옆에 한도를 보이는 `text_too_long`과 `body_too_large`, 그리고 `json_required`, `internal`, `method_not_allowed`. `comment_closed`와 `claimed`는 에이전트의 쓰기만 거절하므로 패널에 오지 않습니다. 연결 없음, 30초 안에 답 없음, `429`나 `503`: 규칙 8 | API-114#default(`internal`, `method_not_allowed`), API-119#400(`invalid_request`), API-119#403(`cross_site`), API-119#409(`reply_limit`, `space_full`, `write_id_reused`, `comment_closed`, `claimed`), API-119#413(`text_too_long`, `body_too_large`), API-119#415(`json_required`), API-119#default(`internal`, `method_not_allowed`), API-120#400(`invalid_request`), API-120#403(`cross_site`), API-120#409(`write_id_reused`, `claimed`), API-120#default(`internal`, `method_not_allowed`) |
| SCR-107#permission | 글은 그대로 두고 코드의 메시지: `access_missing`, `access_other_app`, `no_kind`. `user_only`는 에이전트의 로그인으로 온 의견을 정하는 답글을 거절합니다. 끝난 로그인: [규칙 7](README.ko.md#모든-화면) | API-114#403(`access_missing`, `access_other_app`), API-119#403(`access_missing`, `access_other_app`, `no_kind`, `user_only`), API-120#403(`access_missing`, `access_other_app`, `no_kind`), `opaqueredirect` 응답이나 `401` |
| SCR-107#gone | "이 의견은 서버에 없습니다."와 그림으로 돌아가는 링크, 그리고 그림을 다시 읽습니다. 쓰고 있던 답글은 옮겨 적을 수 있게 칸에 남습니다 | API-114#404(`comment_not_found`, `project_not_found`), API-119#404(`comment_not_found`, `project_not_found`, `space_not_found`), API-120#404(`comment_not_found`, `project_not_found`, `space_not_found`) |

해당하지 않는 것:

- 비어 있음: 의견은 언제나 그 글을 담고, 답글이 없는 의견은 SCR-107#normal에서 "아직 답글이 없습니다."라고 보입니다.

## 경우의 수

| 종류 | 사용자가 보는 것 |
| --- | --- |
| 접근 | 어느 로그인이든 답글을 달고 답이 났다고 표시할 수 있습니다(API-119, API-120). `no_kind`, `user_only`, 끝난 로그인: SCR-107#permission |
| 입력 | 빈 글이나 공백뿐인 글: 답글 달기가 기다립니다. 4,000자를 넘음: 칸이 남은 글자 수를 세며 답글 달기가 기다리고, 서버의 `413`은 칸 옆에 보입니다. 글은 그대로 있습니다 |
| 대상 | 서버에 없는 의견, 또는 그것을 가리키는 주소: SCR-107#gone |
| 상태 변화 | 그사이 닫힘: SCR-107#stale. 닫힌 의견에 단 답글은 의견을 다시 열고, 단추가 보내기 전에 그렇다고 알립니다 |
| 되풀이 | 답글 달기와 답이 났다고 표시는 도는 동안 막힙니다. 답을 잃은 뒤의 다시 보내기는 같은 쓰기 ID를 실어 답글이 하나만 남습니다 |
| 동시성 | 에이전트의 답글과 결정은 패널이 다시 읽을 때 보입니다. 사용자와 에이전트가 한꺼번에 표시하면 두 번째 쪽은 `changed: false`를 받습니다, SCR-107#stale(SPEC-127) |
| 상한 | 답글 4,000자, 의견마다 답글 200개: `reply_limit`은 글을 새 의견으로 옮깁니다. 공간의 8 MiB: `space_full` |
| 바깥 서비스 | 결정의 링크는 그것을 적은 곳으로 따로 열립니다. 패널의 나머지는 그대로입니다 |
| 자료 노출 | 그 의견에 걸린 것뿐이고, 저마다 쓴 쪽의 종류를 보이며 이름이나 이메일 주소는 절대 보이지 않습니다(REQ-163) |
| 빈 응답과 스트림 | 답글 없음: SCR-107#normal의 "아직 답글이 없습니다." 스트림은 없습니다 |
| 화면 상태 | 모든 상태를 320과 1440픽셀에서, [와이어프레임](wireframes.html#scr-107)에. 09단계에서 A 방향으로 그린 것은 [목업](../../09-mockup/nexus/mockup.html#scr-107)에 |
| AI 응답 | 없음: NEXUS는 AI 모델을 부르지 않습니다(REQ-121). 에이전트의 답글은 허브를 거쳐 쓴 글입니다 |

| 영역 | 320픽셀에서 | 1440픽셀에서 |
