# SCR-130 프로젝트 자료

[English](SCR-130-project-data.md)

목적: 프로젝트의 작업 공간에서 사용자는 서버가 그 프로젝트에 대해 가졌고 Git에는 없는 것을 종류마다 그 수와 함께 보고, 프로젝트가 마지막으로 올라온 때와 AI가 AI 할 일을 마지막으로 읽은 때를 봅니다. 그것을 자기 사본으로 파일 하나에 받고, 지우기가 무엇을 지우는지 본 뒤 프로젝트의 이름을 입력해 서버에서 프로젝트를 지웁니다. (FL-114, FL-118, FL-127)

경로 `/p/{project}#data`는 패널을 연 채 프로젝트의 지금 단계로 이끌고, 프로젝트의 어느 단계 페이지에서든 `#data`로 열립니다. NEXUS 서버에만 있고(API-154), 작업 공간(SCR-111)에서 단계 위에 뜨는 패널이며 1,024픽셀보다 좁을 때는 시트입니다. 볼 수 있는 사람: Cloudflare Access가 들여보낸 누구나. 내보내기와 지우기는 사용자 자신의 일이어서 사람 본인의 로그인으로만 합니다. 2026-11-11의 설계 수정이 계획한 화면이고(SPEC-201\~SPEC-203, 그리고 SPEC-188), 그 확인 지점은 2026-11-12에 통과했습니다([검토 지도](../../reviews/2026-11-11-design-review.ko.md), 발견 15). TASK-312가 2026-11-14에 만들었습니다. 그 말은 [redesign-words.ko.md](redesign-words.ko.md)에 있습니다. [모든 화면](README.ko.md#모든-화면), [다시 디자인](README.ko.md#다시-디자인의-화면), [설계 수정](README.ko.md#설계-수정의-화면)의 규칙을 따릅니다.

## 자료

| 자료 | 출처 |
| --- | --- |
| 패널의 머리: 프로젝트의 이름 | 패널을 담은 페이지(API-154), 페이지의 자료에서 |
| 서버가 그 프로젝트에 대해 가진 것: 저장한 스냅샷의 `title`, `repository`, `commit`, `revision`, 기기가 그것을 만든 때 `generated_at`, 서버가 그것을 저장한 때 `pushed_at`. 그리고 프로젝트에 공간이 있는지 `space` | API-177. 패널을 열 때, 내보낸 뒤, 지우기 확인을 열 때, 페이지가 다시 보일 때 읽음 |
| AI가 프로젝트의 AI 할 일을 마지막으로 읽은 때 `read_at`(처음 읽기 전에는 null)과 그 읽기의 세션 이름표 `read_session`. 이름표는 이 화면만 보입니다(SPEC-188). 그리고 가장 오래 안 읽힌 것이 언제부터 기다리는지 `unread_since`. 페이지가 여기서 오래 기다린다는 표시를 알아냅니다([규칙 20](README.ko.md#설계-수정의-화면)) | API-177 |
| 공간에 있고 Git에는 없는 것의 수: 의견, 답글, 기록된 결정, 제안, 반영, NEXUS에서 통과시킨 확인 지점 | API-177(`removal.deletes`). 내보내기의 머리와 같은 방식으로 행을 세므로 둘이 다를 수 없습니다 |
| 지우기가 지우는 것: 그림과 어긋남을 포함한 스냅샷, 그리고 공간. 그리고 열린 의견, 열린 제안, 반영 대기, 아직 기록하지 않은 확인 지점을 저마다 20개까지 ID로, 전체 수와 함께 | API-177(`removal.deletes`, `removal.open`). 같은 순간 허브의 시험 실행(API-110)이 주는 답 |
| 내보내기: JSON 파일 하나와 그 이름 | API-178, `fetch`로 요청. 이름은 응답의 `Content-Disposition`에서 |
| 지우기를 확인하려고 사용자가 입력하는 이름 | 페이지에만 둠: 보내지 않고, 브라우저 저장소에 두지 않으며, 확인을 닫으면 잊습니다 |
| 패널이 열려 있는지 | 페이지 주소의 `#` 뒤: 다른 열쇠가 있으면 그 옆의 `data`(07단계, [주소](../../07-sitemap/nexus.ko.md#주소)) |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 작업 공간 머리의 "프로젝트 자료", 또는 `#data`가 있는 주소 | 패널이 단계 위에 열리고 자료를 읽습니다. 주소에 `data`가 붙고, 포커스는 패널의 제목으로 갑니다. 1,024픽셀 아래에서는 "프로젝트 자료"가 단계 시트 안에 있어, 그 안에서 고른 단계 때처럼 패널이 열리면서 시트가 닫히고, 브라우저 기록에서 시트의 자리를 패널의 주소가 차지합니다 | SCR-130#error, SCR-130#permission, SCR-130#gone |
| 내보내기 | 페이지가 파일을 요청해 브라우저에 넘기고, 브라우저는 응답이 준 이름 `nexus-{project}-{date}.json`으로 저장합니다. 패널은 브라우저가 어느 파일을 받았는지 알리고 자료를 다시 읽습니다(SPEC-201, SPEC-203) | SCR-130#error, SCR-130#permission, SCR-130#gone. 파일은 저장되지 않습니다 |
| 이 프로젝트 지우기 | 패널 안, 자료의 자리에 지우기 확인이 열리고, 열리면서 패널이 자료를 다시 읽습니다: 지우기가 지우는 것, 먼저 내보내라는 권유, 지운 프로젝트가 돌아오는 길, 프로젝트 이름을 넣는 칸(SPEC-202). 확인은 자료를 얼마나 스크롤했든 포커스를 받는 제목부터 보입니다 | SCR-130#error, SCR-130#permission, SCR-130#gone |
| 프로젝트 이름 입력 | 입력한 것이 양 끝의 빈칸을 뺀 뒤 프로젝트의 이름과 글자 그대로 같으면 "이 서버에서 {project} 지우기" 단추가 켜집니다(SCR-130#removal-ready). 다른 글이면 꺼진 채입니다 | 없음 |
| 확인 안의 먼저 내보내기 | 내보내기와 같음. 확인과 입력한 이름은 남습니다 | 내보내기와 같음 |
| 이 서버에서 {project} 지우기 | 서버가 스냅샷과 공간을 함께 지웁니다(API-108). 페이지는 프로젝트의 이름을 첫 화면에 남기고 `/`로 가며, 첫 화면이 프로젝트를 지웠다고 한 번 알립니다(SCR-110#removed) | SCR-130#stale, SCR-130#error, SCR-130#permission, SCR-130#gone. 아무것도 지워지지 않습니다 |
| 확인 안의 취소 | 확인이 닫히고, 입력한 이름을 잊고, 패널이 프로젝트 자료를 다시 보입니다. 포커스는 "이 프로젝트 지우기"로 돌아가고, 패널은 그것이 보이게 스크롤합니다 | 없음 |
| 닫기, Esc, 브라우저의 뒤로 단추 | 패널이 닫히고, 주소가 `data`를 잃고 나머지는 지키며, 단계가 있던 그대로 보이고, 포커스는 "프로젝트 자료"로, 1,024픽셀 아래에서는 단계 시트를 다시 여는 위 막대의 단계 이름으로 돌아갑니다. 시트가 저절로 다시 열리지는 않습니다. 열려 있던 확인도 함께 닫히고 입력한 이름을 잊습니다 | 없음 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이어지는 응답 |
| --- | --- | --- |
| SCR-130#loading | 패널의 머리, 곧 "프로젝트 자료"와 프로젝트의 이름, 닫기가 바로 보이고, 그 아래는 자료가 올 때까지 SCR-130#normal의 배치대로 회색 줄이며, 화면 낭독기에는 "프로젝트 자료를 불러오는 중…". 내보내기와 "이 프로젝트 지우기"는 막혀 보입니다. 내보내기가 도는 동안 그 단추는 "파일을 만드는 중…"이라 하며 막히고, 패널의 나머지는 그대로입니다 | API-154#200, API-104#200, 그리고 도는 동안의 API-177과 API-178 |
| SCR-130#normal | 머리: "프로젝트 자료", 프로젝트의 이름, 닫기. 먼저 고리의 두 때를 저마다 브라우저의 시간대로 쓴 날짜와 시각, 그리고 얼마나 지났는지로([규칙 19](README.ko.md#설계-수정의-화면)): "마지막 올림"과 커밋의 첫 7자인 "커밋 {commit}" 또는 "커밋 없음". "AI의 마지막 읽음"과 "세션 {label}" 또는 "세션 이름표 없음", 아직 읽지 않았으면 때의 자리에 "아직 읽지 않음". 안 읽힌 것이 24시간 넘게 기다리는 동안에는 모양과 말로 된 표시 "24시간 넘게 읽지 않음"과 그 뜻을 적은 한 줄(규칙 20). 그다음 "이 서버에만 있고 Git에는 없는 것": 종류마다 그 수를 단 행, 곧 의견, 답글, 기록된 결정, 제안, 반영, NEXUS에서 통과시킨 확인 지점. 그다음 사용자 자신의 두 가지 일을 저마다 무엇을 하는지 한 줄과 함께: 내보내기, "이 프로젝트의 의견, 제안, 반영, 확인 지점을 담은 JSON 파일 하나입니다. 내가 가지는 사본이며, 서버는 사본을 남기지 않고 NEXUS는 내보낸 파일을 다시 읽어 들이지 않습니다." 그리고 "이 프로젝트 지우기", "이 서버에서 이 프로젝트의 스냅샷과 공간을 지웁니다. 원본은 Git에 남고, 기기의 파일도 남습니다." 내보낸 뒤에는 두 일 위에 "브라우저가 {file} 파일을 받았습니다." | `space`가 참인 API-177#200, API-178#200 |
| SCR-130#empty | 스냅샷은 있고 공간이 없는 프로젝트: 마지막 올림은 SCR-130#normal과 같고, 마지막 읽음 자리에는 "아직 AI 할 일 없음". 모든 수는 0이고 "이 프로젝트에는 아직 공간이 없습니다. Git에 없는 것이 여기에는 없습니다." 내보내기는 그래도 파일을 주며 그 머리가 담은 것이 없다고 적고, "이 프로젝트 지우기"는 스냅샷을 지웁니다 | `space`가 거짓인 API-177#200 |
| SCR-130#removal | 패널 안의 지우기 확인: 제목 "이 서버에서 {project} 지우기". "지워지는 것:" 다음에, 다시 올리면 다시 생기는 스냅샷과 그 그림과 어긋남의 수, 그리고 공간과 Git에 없는 것의 수. 그 아래 열린 의견, 열린 제안, 반영 대기, 아직 기록하지 않은 확인 지점을 저마다 20개까지 ID로, 더 열려 있으면 "{total}개 중 {n}개"와 함께. "먼저 내보내기". "지운 프로젝트는 세션에서 내가 동의해 처음부터 다시 올릴 때만, 빈 공간으로 돌아옵니다." 칸 "확인하려면 프로젝트 이름을 입력해 주세요: {project}". 그리고 단추 취소와, 꺼져 있는 "이 서버에서 {project} 지우기". 화면 낭독기에는 "이름이 아직 맞지 않습니다." 공간이 없는 프로젝트는 스냅샷만 늘어놓습니다 | 확인을 열 때 읽은 API-177#200 |
| SCR-130#removal-ready | SCR-130#removal에서 프로젝트의 이름을 입력한 상태: "이 서버에서 {project} 지우기"가 켜집니다. 지우는 동안 그 단추는 "지우는 중…"이라 하고, 그 단추와 취소가 막힙니다. 서버의 답은 첫 화면으로 이어지고, 첫 화면이 프로젝트를 지웠다고 알립니다(SCR-110#removed) | 이름에는 응답이 없고 페이지가 견줍니다. API-108#200은 SCR-110#removed로 이어집니다 |
| SCR-130#stale | 그사이 AI가 의견을 쓴 것처럼, 확인이 열려 있는 동안 지우기가 지우는 것이 바뀜: 패널이 다시 읽은 답의 `removal`이 확인이 보여 준 것과 다르면, 목록이 지금 모습으로 보이고 그 위에 "이 창이 열려 있는 동안 지워지는 것이 바뀌었습니다. 다시 확인해 주세요." 입력한 이름은 비워지고 단추는 다시 꺼져서, 사용자는 페이지가 지금 보여 주는 것을 확인합니다. 패널이 열려 있는 동안 새로 올라온 것: SCR-111#stale의 막대, 패널은 새로 올라온 것의 때와 커밋을 보입니다 | 패널이 보여 준 것과 `removal`, `revision`, `pushed_at`이 다른 API-177#200 |
| SCR-130#error | 자료 읽기: 패널에 코드의 메시지와 추적 ID, 다시 시도. 머리와 닫기는 남습니다: `internal`과 `method_not_allowed`. 내보내기: "파일을 만들지 못했습니다."와 코드의 메시지, 다시 시도. 아무것도 저장되지 않습니다: `internal`과 `method_not_allowed`, 그리고 오는 길에 잘렸거나 그 파일이 아닌 응답. 지우기: 단추 위에 코드의 메시지와 다시 시도, 입력한 이름은 남습니다: `internal`과 `method_not_allowed`. 내보내기와 지우기의 `cross_site`: 그 메시지와 서버 자체 주소의 페이지로 가는 링크. 연결 없음, 30초 안에 답 없음, `429`나 `503`: 규칙 8, 아무것도 저장되거나 지워지지 않습니다 | API-177#default(`internal`, `method_not_allowed`), API-178#403과 API-108#403(`cross_site`), API-178#default와 API-108#default(`internal`, `method_not_allowed`) |
| SCR-130#permission | 자료 읽기: 패널에 코드의 메시지: `access_missing`과 `access_other_app`. 사람 본인의 로그인 없이 보낸 내보내기나 지우기: 그 일 옆에 "본인이 직접 로그인해야 할 수 있습니다." 아무것도 저장되거나 지워지지 않습니다(SPEC-116, REQ-293). 지우기의 `no_kind`: "이 로그인으로는 여기에 쓸 수 없습니다. Access 정책을 확인해 주세요." `access_missing`과 `access_other_app`도 같은 방식. 끝난 로그인: [규칙 7](README.ko.md#모든-화면), 패널을 연 채 같은 주소로 돌아오는 "다시 로그인". 입력한 이름은 남지 않습니다 | API-177#403(`access_missing`, `access_other_app`), API-178#403(`user_only`, `access_missing`, `access_other_app`), API-108#403(`user_only`, `no_kind`, `access_missing`, `access_other_app`), `opaqueredirect` 응답이나 `401` |
| SCR-130#gone | 다른 탭에서 지웠거나 지우기를 두 번 보낸 것처럼, 서버에 그 프로젝트가 더는 없음: 패널에 "이 프로젝트는 서버에 없습니다."와, 그것을 알아낸 일에 따라 "내보낼 것이 없습니다."나 "지울 것이 없습니다.", 그리고 모든 프로젝트 `/`로 가는 링크. 두 일은 꺼집니다 | API-177#404, API-178#404, API-108#404(`project_not_found`) |

단계의 모든 상태가 해당하고, 패널 자신의 상태 세 개가 더해집니다: 이름을 입력하기 전과 뒤의 확인인 removal과 removal-ready, 그리고 0.2의 패널과 같은 gone([고른 것 2](README.ko.md#이-단계가-고른-것)). 패널은 열 때, 내보낸 뒤, 확인을 열 때, 페이지가 다시 보일 때 자료를 읽고, 스스로 새로 고치지 않습니다.

| 종류 | 사용자가 보는 것 |
| --- | --- |
| 접근 | Access 자신의 로그인 페이지나 거절이 페이지보다 먼저 옵니다. 서버의 `403`과 끝난 로그인: SCR-130#permission. 자료는 어느 로그인으로도 읽고, 내보내기와 지우기에는 사람 본인의 로그인이 필요합니다: 서비스 토큰은 `user_only`를 받으므로 어느 세션도, 보내기 작업도, 허브도 프로젝트를 내보내거나 지우지 못합니다(SPEC-116, REQ-293) |
| 입력 | 지우기를 확인하려고 입력하는 프로젝트의 이름: 글로만, 양 끝의 빈칸을 뺀 뒤 프로젝트의 이름과 글자 그대로 견주므로 대소문자만 달라도 단추는 꺼진 채입니다(SPEC-202). 칸은 자판의 자동 대문자, 고침, 추천을 끄고, 붙여 넣은 이름을 받습니다. 이름은 보내지도, 남기지도, 다시 보이지도 않습니다 |
| 대상 | 서버에 없는 프로젝트: 페이지 자신의 요청이 SCR-111#error이고 모든 프로젝트로 가는 링크가 있습니다(SPEC-203). 패널이 열려 있는 동안 지워진 프로젝트: SCR-130#gone. 공간이 없는 프로젝트: SCR-130#empty |
| 상태 변화 | 확인이 열려 있는 동안 바뀐 지워지는 것, 또는 새로 올라온 것: SCR-130#stale |
| 되풀이 | 내보내기와 지우기 단추는 도는 동안 막힙니다. 두 번 보낸 지우기는 두 번째에 프로젝트를 찾지 못합니다: SCR-130#gone. 서버가 한 번 지우고 두 번째 요청은 `404`이므로 쓰기 ID를 받지 않습니다. 사이에 바뀐 것이 없는 두 내보내기는 때만 다르고 같은 것을 담습니다(SPEC-201) |
| 동시성 | 다른 탭이나 AI가 쓴 것은 패널이 다시 읽을 때 수에 보입니다(규칙 6). 지우기는 그 순간 서버가 가진 것을 지웁니다. 확인은 패널이 마지막으로 읽었을 때 가졌던 것을 보여 주고, 그것이 바뀌면 SCR-130#stale이 알립니다 |
| 상한 | 확인은 종류마다 ID 20개를 "{total}개 중 {n}개"와 함께 늘어놓습니다. 999를 넘는 수는 `999+`. 내보내기에는 자기 상한이 없고 공간의 상한이 그것을 묶습니다(REQ-116). 긴 이름이나 ID는 패널을 넓히지 않고 끊깁니다(규칙 1) |
| 바깥 서비스 | 없음: 패널의 요청은 서버로만 가고(REQ-147), 브라우저가 파일을 사용자 자신의 기기에 저장합니다 |
| 자료 노출 | 수, ID, 두 때. 사람을 가리키지 않는 마지막 읽음의 세션 이름표(SPEC-128)는 여기에만 보입니다. "사용자"나 "AI" 말고는 신원이 없습니다(규칙 11). 내보내기는 의견과 답글의 글을 담습니다: 사람 본인의 로그인으로, `no-store`로, 사용자 자신의 브라우저로만 서버를 떠납니다(SPEC-201) |
| 빈 응답과 스트림 | 공간 없음: SCR-130#empty. 스트림은 없습니다: 페이지가 내보내기를 통째로 받은 뒤 브라우저에 넘기므로, 잘린 응답은 아무것도 저장하지 않습니다 |
| 화면 상태 | 모든 상태를 390과 1,440픽셀에서 회색으로, [revision-wireframes.html](revision-wireframes.html#scr-130)에. 09단계가 설계 수정의 확인 지점 뒤에 다시 디자인의 모습으로 두 테마에서 그린 것은 [revision.html](../../09-mockup/nexus/revision.html#scr-130)에 |
| AI 응답 | 없음: NEXUS는 AI 모델을 부르지 않습니다(REQ-121) |

| 영역 | 1,024픽셀보다 좁을 때, 390에서 그림 | 1,024픽셀부터, 1,440에서 그림 |
| --- | --- | --- |
| 패널 | 탭 위에 뜨는 시트, 높이의 85퍼센트까지, 안에서 스크롤합니다. 뒤의 페이지는 시트가 닫히기를 기다립니다 | 단계의 열 위에, 열의 위쪽부터, 열의 너비만큼이되 640픽셀까지이고 그 가운데에 놓입니다. 페이지의 나머지는 가림막 뒤에서 패널이 닫히기를 기다리고, 패널은 안에서 스크롤합니다 |
| 두 때 | 저마다 한 덩이: 이름, 그다음 날짜와 시각과 얼마나 지났는지, 그다음 커밋이나 세션 이름표. 오래 기다린다는 표시는 따로 한 줄에 | 저마다 한 행: 176픽셀 열에 이름, 그 옆에 날짜와 시각과 얼마나 지났는지, 그 뒤에 커밋이나 세션 이름표. 표시는 마지막 읽음 아래에 |
| 수 | 종류마다 한 행, 이름은 왼쪽에 수는 오른쪽에 | 같음 |
| 두 일 | 저마다 한 덩이: 그 한 줄, 그다음 너비 가득한 높이 44픽셀의 단추 | 저마다 한 행: 한 줄은 왼쪽에, 단추는 오른쪽에 |
| 지우기 확인 | 시트 안, 자료의 자리에: 지워지는 것, 그다음 ID 목록마다 줄을 바꾸는 한 문단, 그 "{total}개 중 {n}개"는 한 줄에. 칸과 두 단추는 자판 위, 시트의 바닥에 머물고 단추는 저마다 너비 가득, 긴 이름은 지우기 단추 안에서 줄을 바꾸고 단추는 글자의 위아래에 여백을 두고 커집니다 | 패널 안, 자료의 자리에: 목록을 둘씩 나란히, "{total}개 중 {n}개"는 저마다 한 줄에. 칸과 두 단추는 패널의 바닥에, 취소가 지우기 단추의 왼쪽에, 지우기 단추는 긴 이름에 같은 식으로 커집니다 |
