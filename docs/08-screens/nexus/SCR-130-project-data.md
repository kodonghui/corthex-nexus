# SCR-130 Project data

[한국어](SCR-130-project-data.ko.md)

Purpose: in a project's workspace the user sees what the server holds of the project and Git does not, each kind with its count, when the project was last pushed and when the agent last read its agent to-do; saves their own copy of it as one file; and removes the project from the server after seeing what the removal deletes and typing the project's name. (FL-114, FL-118, FL-127)

Path `/p/{project}#data`, which leads to the project's current stage with the panel open, and `#data` on any stage's page of the project, on the NEXUS server only (API-154): a panel of the workspace (SCR-111) over the stage, and a sheet under 1,024 pixels. Who can see it: anyone Cloudflare Access lets in; the export and the removal are the user's own acts, under a person's own sign-in. Planned by the design revision of 2026-11-11 (SPEC-201 to SPEC-203, with SPEC-188), whose checkpoint passed on 2026-11-12 ([the review's map](../../reviews/2026-11-11-design-review.md), finding 15); no task has built it. Its words are in [revision-words.md](revision-words.md). The rules of [every screen](README.md#every-screen) apply, with those of [the redesign](README.md#the-redesigns-screens) and of [the design revision](README.md#the-design-revisions-screens).

## Data

| Data | Source |
| --- | --- |
| The panel's head: the project's name | The page that holds the panel (API-154), from the page's data |
| What the server holds of the project: the stored snapshot's `title`, `repository`, `commit` and `revision`, when the device made it, `generated_at`, and when the server stored it, `pushed_at`; and whether the project has a space, `space` | API-177, read when the panel opens, after an export, when the removal's confirmation opens and when the page comes back into view |
| The agent's last read of the project's agent to-do, `read_at`, null before the first read, with the session's label of that read, `read_session`, which only this screen shows (SPEC-188); and since when the oldest entry waits unread, `unread_since`, from which the page works out the mark of a long wait ([rule 20](README.md#the-design-revisions-screens)) | API-177 |
| The counts of what the space holds and Git does not: comments, replies, recorded decisions, proposals, reflections and checkpoints passed in NEXUS | API-177 (`removal.deletes`), which counts the rows as the export's head does, so the two cannot differ |
| What a removal deletes: the snapshot, with its pictures and discrepancies, and the space; and by ID the open comments, the open proposals, the pending reflections and the checkpoints not yet recorded, up to 20 of each with their totals | API-177 (`removal.deletes`, `removal.open`), the answer of the hub's dry run (API-110) at the same moment |
| The export: one JSON file, and its name | API-178, asked with `fetch`; the name from the reply's `Content-Disposition` |
| The name that the user types to confirm a removal | The page only: it is never sent, never kept in the browser's storage, and forgotten when the confirmation closes |
| Whether the panel is open | The page's address after `#`: `data`, beside whatever else it holds (stage 07, [Addresses](../../07-sitemap/nexus.md#addresses)) |

## Actions

| Action | Result | Failure |
| --- | --- | --- |
| "Project data" in the workspace's head, or an address with `#data` | The panel opens over the stage and reads its data; the address gains `data`, and the focus moves to the panel's heading | SCR-130#error, SCR-130#permission or SCR-130#gone |
| Export | The page asks for the file and hands it to the browser, which saves it under the name that the reply gives, `nexus-{project}-{date}.json`; the panel says which file the browser has, and reads its data again (SPEC-201, SPEC-203) | SCR-130#error, SCR-130#permission or SCR-130#gone, and no file is saved |
| Remove this project | The removal's confirmation opens in the panel, in the data's place, and the panel reads its data again as it opens: what the removal deletes, the offer to export first, how a removed project comes back, and the field for the project's name (SPEC-202) | SCR-130#error, SCR-130#permission or SCR-130#gone |
| Type the project's name | When what the user typed is the project's name, compared exactly once the spaces at its ends are left out, the button "Remove {project} from this server" works (SCR-130#removal-ready); any other text leaves it off | none |
| Export first, in the confirmation | As Export; the confirmation and the typed name stay | As Export |
| Remove {project} from this server | The server deletes the snapshot and the space together (API-108); the page leaves the project's name for the first page and leads to `/`, which says once that the project was removed (SCR-110#removed) | SCR-130#stale, SCR-130#error, SCR-130#permission or SCR-130#gone, and nothing is removed |
| Cancel, in the confirmation | The confirmation closes, the typed name is forgotten, and the panel shows the project's data again; the focus returns to "Remove this project" | none |
| Close, Escape or the browser's back button | The panel closes, the address loses `data` and keeps the rest, the stage shows as it was, and the focus returns to "Project data"; an open confirmation closes with it, and its typed name is forgotten | none |

## States

| State | What the user sees and can do | From responses |
| --- | --- | --- |
| SCR-130#loading | The panel's head at once, "Project data" with the project's name and Close, and under it grey lines in the layout of SCR-130#normal until the data arrives, with "Loading the project's data…" for screen readers; Export and "Remove this project" show disabled. While an export runs, its button says "Preparing the file…" and is disabled, and the rest of the panel stays as it is | API-154#200, API-104#200, and API-177 and API-178 while they run |
| SCR-130#normal | The head: "Project data", the project's name and Close. First the two times of the loop, each as a date and time in the browser's time zone with how long ago ([rule 19](README.md#the-design-revisions-screens)): "Last push", with "Commit {commit}", the commit's first 7 characters, or "No commit"; and "Last read by the agent", with "Session {label}" or "No session label", or in the time's place "Not read yet"; while an entry has waited unread for more than 24 hours, the mark "Unread for more than 24 hours", a shape and words, with its line on what that means (rule 20). Then "On this server, and not in Git": a row for each kind with its count, comments, replies, recorded decisions, proposals, reflections and checkpoints passed in NEXUS. Then the user's two acts, each with one line on what it does: Export, "One JSON file with this project's comments, proposals, reflections and checkpoints. It is your own copy: the server keeps none, and NEXUS reads no export back in."; and "Remove this project", "Deletes this project's snapshot and space from this server. Its sources stay in Git, and the files on your devices stay." After an export, above the acts: "Your browser has the file {file}." | API-177#200 with `space` true, API-178#200 |
| SCR-130#empty | A project with a snapshot and no space: the last push as in SCR-130#normal; in the last read's place, "No agent to-do yet"; every count 0, with "This project has no space yet: nothing here is missing from Git."; Export still gives a file, whose head says that it holds no entries, and "Remove this project" deletes the snapshot | API-177#200 with `space` false |
| SCR-130#removal | The removal's confirmation, in the panel: the heading "Remove {project} from this server"; "This deletes:", then the snapshot, with the counts of its pictures and discrepancies, which a push makes again, and the space, with the counts of what Git does not hold; under them, by ID, the open comments, the open proposals, the pending reflections and the checkpoints not yet recorded, up to 20 of each, with "{n} of {total}" where more are open; "Export first"; "A removed project comes back only by a first push that you agree to in a session, with an empty space."; the field "Type the project's name to confirm: {project}"; and the buttons Cancel and "Remove {project} from this server", which is off, with "The name does not match yet." for screen readers. A project without a space lists the snapshot only | API-177#200, read as the confirmation opens |
| SCR-130#removal-ready | As SCR-130#removal, with the project's name typed: "Remove {project} from this server" works. While the removal runs it says "Removing…", and it and Cancel are disabled. The server's answer leads on to the first page, which says that the project was removed (SCR-110#removed) | none for the name, which the page compares; API-108#200 leads on to SCR-110#removed |
| SCR-130#stale | What the removal deletes changed while its confirmation was open, as when the agent wrote a comment meanwhile: when the panel reads again and the answer's `removal` differs from what the confirmation showed, the lists show as they are now, with "What this removal deletes changed while this was open. Check it again." above them; the typed name is emptied, and the button is off again, so that the user confirms what the page now shows. A newer push while the panel is open: SCR-111#stale's bar, and the panel shows the newer push's time and commit | API-177#200 with another `removal`, `revision` or `pushed_at` than the panel showed |
| SCR-130#error | Reading the data: the code's message in the panel, with the trace ID and Try again, while the head and Close stay: `internal` and `method_not_allowed`. The export: "No file was made." with the code's message and Try again, and nothing is saved: `internal` and `method_not_allowed`, and a reply that is cut on its way or is not the file. The removal: the code's message above the buttons, with Try again and the typed name kept: `internal` and `method_not_allowed`. `cross_site`, for the export and for the removal: its message, with a link to the page at the server's own address. No connection, no answer in 30 seconds, `429` or `503`: rule 8, and nothing is saved or removed | API-177#default (`internal`, `method_not_allowed`), API-178#403 and API-108#403 (`cross_site`), API-178#default and API-108#default (`internal`, `method_not_allowed`) |
| SCR-130#permission | Reading the data: the code's message in the panel: `access_missing` and `access_other_app`. The export or the removal sent without a person's own sign-in: "Only you can do this, signed in yourself." by the act, and nothing is saved or removed (SPEC-116, REQ-293); for the removal, `no_kind`, "This sign-in cannot write here. Check the Access policy."; `access_missing` and `access_other_app` the same way. A sign-in that expired: [rule 7](README.md#every-screen), "Sign in again", which comes back to the same address with the panel; the typed name is not kept | API-177#403 (`access_missing`, `access_other_app`), API-178#403 (`user_only`, `access_missing`, `access_other_app`), API-108#403 (`user_only`, `no_kind`, `access_missing`, `access_other_app`), an `opaqueredirect` reply or a `401` |
| SCR-130#gone | The server no longer holds the project, as after a removal in another tab or a removal sent twice: in the panel, "This project is not on the server.", with "There is nothing to export." or "There is nothing to remove." for the act that found it, and a link to all projects, `/`; the two acts are off | API-177#404, API-178#404 and API-108#404 (`project_not_found`) |

Every state of the stage applies, with three of the panel's own: removal and removal-ready, the confirmation before and after the name is typed, and gone, as on the panels of 0.2 ([choice 2](README.md#choices-this-stage-made)). The panel reads its data when it opens, after an export, when the confirmation opens and when the page comes back into view; it does not update by itself.

## Kinds of cases

| Kind | What the user sees |
| --- | --- |
| Access | Access's own login page or refusal comes before the page; the server's `403` and a sign-in that expired: SCR-130#permission. Either sign-in reads the data; the export and the removal need a person's own: the service token gets `user_only`, so that no session, push job or hub exports or removes a project (SPEC-116, REQ-293) |
| Input | The project's name, typed to confirm a removal: text only, compared exactly with the project's name once the spaces at its ends are left out, so another letter case leaves the button off (SPEC-202). The field turns off the keyboard's capital letters, corrections and suggestions, and takes a pasted name. The name is never sent, kept or shown again |
| Target | A project that the server does not hold: the page's own request is SCR-111#error, with a link to all projects (SPEC-203). One removed while the panel is open: SCR-130#gone. A project without a space: SCR-130#empty |
| State changes | What the removal deletes changed while its confirmation was open, or a newer push: SCR-130#stale |
| Repeats | Export and the removal's button are disabled while they run. A removal sent twice finds no project the second time: SCR-130#gone; it takes no write ID, since the server deletes once and the second request is `404`. Two exports with no change between them hold the same but for their time (SPEC-201) |
| Concurrency | Another tab's or the agent's writes show in the counts when the panel reads again (rule 6). The removal deletes what the server holds at that moment; the confirmation shows what it held when the panel last read, and SCR-130#stale says when that changed |
| Limits | The confirmation lists 20 IDs of each kind, with "{n} of {total}"; counts over 999 show as `999+`; the export has no limit of its own, since the space's limits bound it (REQ-116). A long name or ID breaks rather than widen the panel (rule 1) |
| Outside services | None: the panel's requests go only to the server (REQ-147), and the browser saves the file on the user's own device |
| Data exposure | Counts, IDs and two times; the session's label of the last read, which names no person (SPEC-128), shows here only; no identity but "User" or "Agent" (rule 11). The export holds the comments' and replies' text: it leaves the server only for the user's own browser, under a person's own sign-in, with `no-store` (SPEC-201) |
| Empty and streamed answers | No space: SCR-130#empty. No stream: the page takes the export whole before it hands it to the browser, so a reply that is cut saves nothing |
| Screen states | Every state in grey at 390 and 1,440 pixels, in [revision-wireframes.html](revision-wireframes.html#scr-130); stage 09 draws them in the redesign's look |
| AI answers | None: NEXUS calls no AI model (REQ-121) |

## Layout

| Region | Under 1,024 pixels, drawn at 390 | From 1,024 pixels, drawn at 1,440 |
| --- | --- | --- |
| The panel | A sheet over the tabs, up to 85 per cent of the height, which scrolls inside; the page behind it waits until it closes | Over the stage's column, from the column's top, as wide as the column up to 640 pixels and centred in it, with the rest of the page behind a scrim, waiting until it closes; it scrolls inside |
| The two times | Each a block: its name, then the date and time with how long ago, then the commit or the session's label, and the mark of a long wait on a line of its own | Each a row: its name in a column of 176 pixels, the date and time with how long ago beside it, and the commit or the session's label after them; the mark under the last read |
| The counts | A row for each kind, its name left and its count right | The same |
| The acts | Each a block: its line, then its button across the width, 44 pixels high | Each a row: its line left, its button right |
| The removal's confirmation | In the sheet, in the data's place: what it deletes, then each list of IDs as one paragraph that wraps; the field and the two buttons stay at the sheet's bottom, above the keyboard, each button across the width | In the panel, in the data's place: the lists two by two; the field and the two buttons at the panel's bottom, Cancel left of the removal's button |

On a screen that a finger selects, Close, Export, "Remove this project", "Export first", the field and the confirmation's buttons take a hit area of 44 pixels (rule 14).
