# SCR-101 허브 페이지

[English](SCR-101-hub-page.md)

목적: 사용자는 모든 프로젝트가 어디까지 왔는지를 부분마다의 현재 단계와 다음 행동부터 보고, 거기서 검색하거나 항목을 추적하거나 단계를 열거나 그림 보기나 단계 현황으로 넘어갑니다. (FL-105, FL-113)

경로 `/`. NEXUS 서버가 내주고(API-101), 기기에서는 허브의 `build`가 파일로 만듭니다(API-135). 볼 수 있는 사람: Cloudflare Access가 들여보낸 누구나, 또는 그 기기의 사용자. 1차에서 만들었고, NEXUS 0.2가 부분, 그림 표시, 열린 것의 개수, 기록을 기다리는 확인 지점, 먼저 물을 일, 빈 서버의 설명을 더합니다(SPEC-122\~SPEC-125). [모든 화면](README.ko.md#모든-화면)의 규칙을 따릅니다.

## 자료

| 자료 | 출처 |
| --- | --- |
| 모든 프로젝트와 그 현재 단계와 다음 행동, 13단계와 그 상태, 항목 수, 점검 결과, 그리고 스냅샷마다 언제 어느 커밋에서 만들었는지 | API-101: 페이지 자료 `corthex-hub-page/0.2`의 `projects`. 기기에서는 API-135가 만든 같은 자료 |
| 부분마다 각 단계의 상태, 확인 지점, 다음 행동, 그리고 기록을 어디서 가져왔는지: 저장소의 기본 브랜치 커밋과 그 시각, 또는 기기의 상태 파일 | API-101(`projects`, 스냅샷 0.2) |
| 공간이 있는 프로젝트마다: 그 그림과 그림마다의 커밋과 최신인지, 열린 의견, 제안, 어긋남, NEXUS에서 통과시켜 기록을 기다리는 확인 지점, 그리고 `checkpoint-withdrawn` 경고 | API-101(`spaces`): 프로젝트마다 그림 150개, 확인 지점 100개, 경고 100개까지와 그 전체 수. 기기에서는 없음 |
| 에이전트가 먼저 묻는 일: 10개까지와 남은 수, 그리고 그 목록이 프로젝트의 것인지 프로필의 것인지 기본 목록인지 | API-101(`projects`, SPEC-125) |
| 프로젝트 목록에 있지만 이 기기에 없는 프로젝트 | 기기에서 API-135(`missing`) |
| 페이지의 언어, 그리고 서버가 내준 것인지 기기에서 만든 것인지 | API-101(`lang`, `origin`) |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| ID나 제목의 낱말로 찾기 | 검색 결과 SCR-102, 주소 `#q=` | 빈 글: 검색하지 않음 |
| ID 고르기 | 추적 화면 SCR-103, 주소 `#p=…&id=` | 정의한 항목이 없는 ID: SCR-103#error |
| 프로젝트의 단계 고르기 | 단계 자세히 보기 SCR-104, 주소 `#p=…&s=` | 없음: 페이지가 모든 단계를 담고 있음 |
| 기록을 기다리는 확인 지점 열기 | 그 부분과 단계의 단계 현황 SCR-109 | 단계 현황 자신의 거절(SCR-109#error) |
| 다시 불러오기 | 서버의 지금 자료로 다시 그린 페이지. 기기에서는 허브가 마지막으로 만든 파일 | SCR-101#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이어지는 응답 |
| --- | --- | --- |
| SCR-101#normal | 프로젝트마다 카드 하나: 이름, 팀이나 개인, 스냅샷의 시각과 커밋, 부분마다의 지금과 다음, 13단계와 그 상태와 점검 표시, 그리고 항목·오류·경고·참고의 수. 서버에서는 카드에 열린 의견·제안·어긋남의 수, 그림이 있는 단계의 표시, 기록을 기다리는 확인 지점과 그 단계 현황 링크, 먼저 물을 일과 그 목록의 출처가 더해집니다. 기기에서는 그림과 개수가 서버에 있다고 알립니다. 진행 기록이 없는 프로젝트는 진행을 기록하는 법을 알리고, 스냅샷이 없는 프로젝트는 그 까닭과 함께 단계 없이 늘어놓습니다 | API-101#200 |
| SCR-101#empty | 스냅샷이 없는 서버에서: 허브가 보여 주는 것, 곧 프로젝트마다의 단계, 점검, 그림, 그리고 프로젝트를 올리는 네 단계: corthex 스킬로 등록하고, `nexus.push`에 넣고 `nexus.url`에 서버의 주소를 적고, 서비스 토큰의 환경 변수 두 개 `CORTHEX_NEXUS_CLIENT_ID`와 `CORTHEX_NEXUS_CLIENT_SECRET`을 설정한 뒤, 에이전트에게 미리 보기를 보이고 올리게 합니다(SPEC-124). 프로젝트 구역도, 비밀 값도, 경로도 없습니다. 프로젝트가 없는 기기에서: "아직 프로젝트가 없습니다. corthex 스킬로 프로젝트를 등록한 뒤 허브를 다시 만들어 주세요." | 프로젝트가 없는 API-101#200 |
| SCR-101#stale | 페이지를 내주거나 만든 때의 자료: 맨 위의 "만든 때 {time}", 스냅샷마다의 시각과 커밋, 그리고 저장소에 커밋하지 않은 변경이 있었으면 "커밋하지 않은 변경 있음". 서버에서는 그림이 최신이 아닌 단계가 그렇다고 까닭과 함께 알리고, NEXUS에서 통과시켜 기록을 기다리는 확인 지점이 그 단계의 기록된 상태 옆에 통과한 때와 함께 보이며, `checkpoint-withdrawn` 경고가 그 확인 지점을 적은 기록된 상태 옆에 보입니다(SPEC-140). 다시 불러오면 새 자료가 보이고, 기기에서는 허브가 페이지를 다시 만듭니다 | API-101#200 |
| SCR-101#error | [규칙 9](README.ko.md#모든-화면)의 메시지 페이지: "서버에서 문제가 생겼습니다. 다시 시도해 주세요."와 추적 ID, 다시 불러오기. 자료가 JSON이 아니거나 `corthex-hub-page/0.2`가 아닌 페이지는 1차의 빈 페이지 대신, 서버에서는 "이 페이지의 데이터를 읽지 못했습니다. 페이지를 다시 불러와 주세요.", 기기에서는 "허브를 다시 만들어 주세요."라고 알립니다([고른 것 8](README.ko.md#이-단계가-고른-것)) | API-101#default(`internal`, `method_not_allowed`) |
| SCR-101#permission | 코드의 메시지를 담은 메시지 페이지: 서버의 주인에게 서버를 Access로 보호하거나 그 Access 설정을 확인하라고 알리고, 추적 ID를 보입니다. Access가 들여보내지 않은 사람은 사이트맵 밖에 있는 Access 자신의 페이지를 보고, `401`도 Access의 것입니다 | API-101#403(`access_missing`, `access_other_app`) |

해당하지 않는 것:

- 읽는 중: 페이지는 자료를 담은 문서 하나이고 바로 그려집니다. 문서가 오기 전까지는 브라우저가 자기 읽는 중 표시를 보입니다.

## 경우의 수

| 종류 | 사용자가 보는 것 |
| --- | --- |
| 접근 | 서버에서는 Access 자신의 로그인 페이지나 거절이 페이지보다 먼저 옵니다. Worker의 `403`은 SCR-101#permission입니다. 기기에서는 파일이 그 사용자의 것이고 로그인이 없습니다 |
| 입력 | 검색 칸뿐입니다. 빈 글은 검색하지 않고, 다른 글은 SCR-102의 검색을 돌립니다 |
| 대상 | 페이지에 없는 프로젝트나 단계를 가리키는 주소는 SCR-103이나 SCR-104에 프로젝트 목록으로 가는 링크와 함께 알림을 엽니다 |
| 상태 변화 | 최신이 아닌 그림, 기록을 기다리는 확인 지점, 기록이 적고 있는 철회된 확인 지점: SCR-101#stale |
| 되풀이 | 이 화면에 닿지 않습니다: 아무것도 보내지 않습니다 |
| 동시성 | 이 화면에 닿지 않습니다: 아무것도 쓰지 않고, 다른 기기의 보내기는 다시 불러온 뒤 보입니다 |
| 상한 | 999를 넘는 수는 `999+`로 보입니다(SPEC-123). 프로젝트의 목록은 그림 150개, 확인 지점 100개, 경고 100개에서 멈추고 전체 수를 보입니다. 크기 한도에 닿은 스냅샷은 그 점검을 먼저 보입니다(SPEC-122). 먼저 물을 일은 10개와 남은 수를 보입니다(SPEC-125) |
| 바깥 서비스 | 없음: 페이지는 네트워크에서 아무것도 불러오지 않습니다(REQ-097). 단계의 사람 화면은 그 도구를 여는 링크입니다 |
| 자료 노출 | 스냅샷이 담은 것뿐입니다. 그림 자료도, 의견의 글도, 신원도, 비밀 값도, 로컬 경로도 없습니다(SPEC-124). 기기에서 만든 페이지는 프로젝트 목록에서 빠진 프로젝트를 싣지 않습니다(REQ-104) |
| 빈 응답과 스트림 | 빈 서버나 기기: SCR-101#empty. 진행 기록이나 스냅샷이 없는 프로젝트: SCR-101#normal이 까닭을 알립니다. 스트림은 없습니다 |
| 화면 상태 | 모든 상태를 320과 1440픽셀에서, [와이어프레임](wireframes.html#scr-101)에. 09단계에서 A 방향으로 그린 것은 [목업](../../09-mockup/nexus/mockup.html#scr-101)에 |
| AI 응답 | 없음: NEXUS는 AI 모델을 부르지 않습니다(REQ-121) |

## 배치

| 영역 | 320픽셀에서 | 1440픽셀에서 |
| --- | --- | --- |
| 맨 위 | 제목, 그 아래 "만든 때 {time} · 프로젝트 {n}개", 단계 표시의 설명, 그리고 검색 칸과 그 단추 | 가운데 1,200픽셀 너비의 열에 같은 차례로 |
| 보기 | SCR-102와 SCR-103이 검색 칸 아래, 프로젝트 위에 열립니다 | 같은 자리, 열의 너비로 |
| 프로젝트 | 카드가 하나씩 아래로: 이름, 부분마다의 지금과 다음, 개수, 그리고 세 개씩 줄지은 13단계 | 카드 두 개가 나란히, 13단계는 일곱 개씩 줄지어 |
| 바닥글 | 이 기기의 파일로 만든 페이지인지, 서버의 스냅샷으로 만든 페이지인지 | 같음 |
