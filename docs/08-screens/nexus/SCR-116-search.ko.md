# SCR-116 찾기

[English](SCR-116-search.md)

목적: 사용자는 서버의 어느 페이지 위에서든 모든 프로젝트에서 항목을 그 ID나 제목의 낱말로 찾고, 그 프로젝트 작업 공간의 제자리에서 엽니다. (FL-118)

경로 `{any page}#q={words}`. NEXUS 서버에만 있고, 다시 디자인의 모든 페이지(SCR-110\~SCR-115)의 위 막대에 있는 칸으로 API-156에 묻습니다. 볼 수 있는 사람: Cloudflare Access가 들여보낸 누구나. 2026-11-06 다시 디자인에서 계획하고(SPEC-152) TASK-277이 만든 화면입니다. 1차의 찾기 결과(SCR-102)를 받아들이고, 그 주소 `/#q={words}`는 첫 화면에서 이것을 엽니다(SPEC-154). [모든 화면](README.ko.md#모든-화면)과 [다시 디자인](README.ko.md#다시-디자인의-화면)의 규칙을 따릅니다.

## 자료

| 자료 | 출처 |
| --- | --- |
| 사용자가 치는 대로의 낱말, 두 글자부터 | 칸, 그리고 찾기를 링크로 걸 수 있게 `#` 뒤의 페이지 주소 `q=` |
| 저장된 모든 스냅샷에서 맞는 것 20개까지: 정확한 ID를 먼저, 그다음 ID나 제목이 모든 낱말을 담은 항목. 허브 페이지의 찾기처럼 대소문자를 가리지 않습니다(REQ-094). 저마다 프로젝트, 부분, 단계, ID, 제목과 함께 | API-156 |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 칸에 치기 | 두 글자부터, 250밀리초 쉰 뒤 칸 아래에 맞는 것. 낱말은 주소에 `q=`로 들어갑니다 | SCR-116#short, SCR-116#empty, SCR-116#error |
| 화살표 키로 옮긴 뒤 Enter, 또는 맞는 것 고르기 | 그 항목을 제자리에서: 그 프로젝트 작업 공간의 `/p/{project}/{part}/{stage}#item={id}`(SPEC-149, REQ-232). 아래와 위 화살표는 표시를 옮기고, 마지막에서 처음으로, 처음에서 마지막으로 돕니다. 닫힌 맞는 것에서는 WAI-ARIA의 콤보박스 패턴대로 아래 화살표가 첫째를, 위 화살표가 마지막을 표시한 채 엽니다 | 그 페이지의 SCR-115#gone |
| Escape, 또는 맞는 것 바깥 고르기 | 맞는 것이 표시 없이 닫히고, 낱말은 칸에 남습니다. 칸에 포커스가 오면 맞는 것이 다시 보입니다 | 없음 |
| 맞는 것이 없을 때 전체 점검 | SCR-117 | SCR-117 자신의 상태 |
| 1,024픽셀보다 좁을 때 찾기 단추 | 칸이 자판과 함께 위 막대 위로 열리고, 맞는 것이 그 아래 화면을 채웁니다. 닫기, 또는 맞는 것이 닫힌 뒤의 Escape는 포커스를 찾기 단추에 두고 페이지로 돌아가며, 그 단추는 낱말을 지닌 칸을 다시 엽니다 | 없음 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이어지는 응답 |
| --- | --- | --- |
| SCR-116#loading | 칸 아래에 "찾는 중…". 답이 올 때까지 앞서 맞은 것은 남습니다 | 도는 동안의 API-156 |
| SCR-116#normal | "“{q}” 검색 결과 {n}개", 그다음 맞는 것. 저마다 ID, 원문 그대로의 제목, 그 아래 "{project} · {part} · {stage}". 여러 프로젝트가 담은 ID는 프로젝트마다 한 번씩. 화살표 키가 가리키는 것은 강조색 막대로 표시합니다. 20개일 때: "처음 20개입니다. 낱말을 더하면 좁혀집니다." | API-156#200 |
| SCR-116#short | 한 글자: "두 글자 이상 넣어 주세요."가 보이고 아무것도 찾지 않습니다 | 없음 |
| SCR-116#empty | "“{q}”에 맞는 항목이 없습니다."와, SCR-117을 여는 "전체 점검에서 보기" | 맞는 것이 없는 API-156#200 |
| SCR-116#error | 칸 아래에 코드의 메시지와 추적 ID, 다시 시도. 낱말은 남습니다: `invalid_request`, `internal`, `method_not_allowed`. 연결 없음, 30초 안에 답 없음, `429`나 `503`: 낱말을 남긴 규칙 8 | API-156#400(`invalid_request`), API-156#default(`internal`, `method_not_allowed`) |
| SCR-116#permission | 칸 아래에 코드의 메시지. 끝난 로그인: [규칙 7](README.ko.md#모든-화면), 낱말과 함께 같은 주소로 돌아오는 "다시 로그인" | API-156#403(`access_missing`, `access_other_app`), `opaqueredirect` 응답이나 `401` |

stale을 빼고 단계의 모든 상태가 해당하고, 찾기 자신의 상태 short가 더해집니다. 해당하지 않는 것:

- 최신 아님: 찾기는 낱말이 바뀔 때마다 서버에 묻고, 맞는 것은 링크일 뿐입니다.

## 경우의 수

| 종류 | 사용자가 보는 것 |
| --- | --- |
| 접근 | Worker의 `403`과 끝난 로그인: SCR-116#permission |
| 입력 | 두 글자에서 200자까지. 낱말은 마크업이 아닌 글입니다(REQ-098). 앞뒤의 공백은 뺍니다 |
| 대상 | 그사이 올리기가 그 항목을 지운 맞는 것: 제자리의 SCR-115#gone |
| 상태 변화 | 없음: 낱말이 바뀔 때마다 다시 묻습니다 |
| 되풀이 | 빨리 친 낱말은 쉰 뒤 한 번 묻습니다. 칸에 있는 것보다 오래된 낱말의 답은 버립니다 |
| 동시성 | 없음: 찾기는 읽기만 합니다 |
| 상한 | 맞는 것 20개, 정확한 ID를 먼저. 더 보려면 낱말을 더합니다 |
| 바깥 서비스 | 없음: 찾기는 서버에만 묻습니다(REQ-147) |
| 자료 노출 | 서버의 모든 페이지가 이미 보이는 저장된 스냅샷의 ID와 제목뿐입니다. 단계 원본의 글은 없습니다 |
| 빈 응답과 스트림 | 맞는 것 없음: SCR-116#empty. 스트림은 없습니다 |
| 화면 상태 | 모든 상태를 390과 1440픽셀에서 두 테마로, [redesign.html](../../09-mockup/nexus/redesign.html#scr-116)에 |
| AI 응답 | 없음: NEXUS는 AI 모델을 부르지 않습니다(REQ-121) |

## 배치

| 영역 | 1,024픽셀보다 좁을 때, 390에서 그림 | 1,024픽셀부터, 1,440에서 그림 |
| --- | --- | --- |
| 칸 | 찾기 단추 뒤에. 열면 닫기와 함께 위 막대를 차지합니다 | 위 막대에, 너비 560픽셀, 안내 "ID나 낱말로 찾기 · 예: REQ-107"과 함께 |
| 맞는 것 | 칸 아래, 너비 가득 남은 높이까지. 맞는 것마다 높이 44픽셀 이상 | 칸 아래 칸만큼 넓은 패널, 높이의 70퍼센트까지이고 안에서 스크롤됩니다. 그 뒤의 페이지는 어두워집니다 |

서버는 다시 디자인의 모든 페이지에 칸, 패널, 찾기 단추, 닫기, 어둡게 하는 막을 그립니다. 칸과 단추는 보기의 코드가 돌 때까지 막힌 채 기다리고, 패널은 그 코드가 채웁니다(규칙 15). 칸은 브라우저가 스스로 그리는 지우기 단추를 그리지 않습니다. 그 누르는 영역은 규칙 14에 못 미치고, 휴대폰에서는 닫기 옆에 섰습니다.
