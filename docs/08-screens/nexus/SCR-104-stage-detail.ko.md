# SCR-104 단계 자세히 보기

[English](SCR-104-stage-detail.md)

목적: 사용자는 한 프로젝트의 한 단계를 부분마다 그 상태, 마지막 확인 지점, 다음 행동과 함께, 그 점검 결과와 항목과 함께 보고, 그 사람 화면을 열며, 서버에서는 그 그림 보기와 단계 현황을 엽니다. (FL-105, FL-113)

경로 `/#p={project}&s={stage}`. 허브 페이지(SCR-101)의 보기로 프로젝트 카드 안에 열리고, 서버와 기기 양쪽에 있습니다. 볼 수 있는 사람: Cloudflare Access가 들여보낸 누구나, 또는 그 기기의 사용자. 1차에서 만들었고, NEXUS 0.2는 이것을 부분마다 보여 주며 서버에서는 부분마다의 그림 보기와 단계 현황으로 잇습니다(SPEC-123, SPEC-138). [모든 화면](README.ko.md#모든-화면)의 규칙을 따릅니다.

## 자료

| 자료 | 출처 |
| --- | --- |
| 부분마다 단계의 상태, 마지막 확인 지점, 다음 행동 | 허브 페이지의 자료(API-101) |
| 그 설정: 사람 화면과 그 링크, 어느 쪽이 정본인지, 텍스트 원본과 그 파일과 그 상태, 텍스트 사본의 시각, 메모 | 허브 페이지의 자료(API-101) |
| 그 점검 결과를 수준마다, 그 항목을 종류마다 | 허브 페이지의 자료(API-101) |
| 서버에서 부분마다: 01, 05, 07의 단계 그림과 그 커밋과 최신인지, 그리고 NEXUS에서 통과시켜 기록을 기다리는 확인 지점이나 철회한 뒤 기록이 적은 확인 지점 | 허브 페이지의 자료(API-101, `spaces`) |
| 프로젝트와 단계 | 페이지 주소의 `#p=`와 `&s=` 뒤 |

## 동작

| 동작 | 결과 | 실패 |
| --- | --- | --- |
| 부분의 그림 보기 열기(서버) | 그림 보기 SCR-105 | 그 페이지 자신의 거절(SCR-105#error, SCR-105#permission) |
| 부분의 단계 현황 열기(서버) | 단계 현황 SCR-109 | 그 페이지 자신의 거절(SCR-109#error, SCR-109#permission) |
| 사람 화면 열기 | 설정이 준 링크의 단계 도구(REQ-095) | 그 도구 자신의 것 |
| 항목의 ID 고르기 | 추적 화면 SCR-103 | 정의한 항목이 없는 ID: SCR-103#error |
| 모든 항목 보기 | 처음 몇 개 뒤로 단계의 모든 항목 | 없음 |
| 닫기, Escape, 다른 단계, 브라우저의 뒤로 단추 | 자세히 보기가 닫힌 카드, 또는 다른 단계 | 없음 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이어지는 응답 |
| --- | --- | --- |
| SCR-104#normal | 카드의 단계 줄 아래, 제목으로 단계의 이름과 상태가 포커스를 받고, 그 아래 부분마다 그 상태, 마지막 확인 지점, 다음 행동, 설정의 사실들, 점검 결과(없으면 "점검에서 찾은 것이 없습니다."), 종류마다의 항목. 서버에서는 그림이 있는 단계의 부분마다 "그림"이, 부분마다 "단계 현황"이 있습니다. 기기에서는 그림과 단계 현황이 서버에 있다고 한 줄로 알립니다 | 허브 페이지의 자료(API-101#200) |
| SCR-104#empty | 항목이 없는 단계: 그 상태, 확인 지점, 다음 행동, 그리고 텍스트 원본의 상태로 본 까닭: 없음, 텍스트 원본 없음, 스냅샷을 만든 기기에 저장소 없음, 단계 건너뜀, 설정을 고쳐야 함. 서버에서는 단계 현황 링크가 남습니다 | 허브 페이지의 자료(API-101#200) |
| SCR-104#stale | 최신이 아닌 부분의 그림: 그 링크 옆에 "최신 아님"과 까닭, 곧 스냅샷에 담을 수 있는 크기보다 큼, 원본이 저장소에서 사라짐, 원본이 다른 저장소에 있음. NEXUS에서 통과시켜 기록을 기다리는 확인 지점: 기록된 상태 옆에 "{date}에 NEXUS에서 통과, 기록을 기다림". `checkpoint-withdrawn` 경고: 그것을 적은 기록된 상태 옆에. 사람 화면의 텍스트 사본은 사본을 만든 때를 보입니다 | 허브 페이지의 자료(API-101#200) |
| SCR-104#error | 페이지에 없는 프로젝트나 단계를 가리키는 주소: 1차는 아무것도 보이지 않던 자리에 "이 프로젝트는 이 페이지에 없습니다."나 "13단계에 없는 단계입니다."와 프로젝트 목록으로 가는 링크([고른 것 7](README.ko.md#이-단계가-고른-것)) | 허브 페이지의 자료(API-101#200) |

해당하지 않는 것:

- 읽는 중: 자세히 보기는 요청 없이 페이지가 담은 자료를 읽습니다.
- 권한: 자세히 보기는 허브 페이지가 그것을 연 사람에게 보이는 것을 보입니다. 이것이 잇는 그림 보기와 단계 현황은 자기 접근을 스스로 확인합니다(SCR-105#permission, SCR-109#permission).

## 경우의 수

| 종류 | 사용자가 보는 것 |
| --- | --- |
| 접근 | 자세히 보기에 닿지 않습니다: 허브 페이지의 접근을 따르고(SCR-101), 그 링크는 자기 접근을 확인하는 페이지로 갑니다 |
| 입력 | 자세히 보기에 닿지 않습니다: 어떤 꼴의 주소든 그 단계나 SCR-104#error를 엽니다 |
| 대상 | 페이지에 없는 프로젝트나 단계: SCR-104#error. 페이지를 내준 뒤 지워진 그림: 그림 보기가 그렇다고 알립니다(SCR-105#error) |
| 상태 변화 | 최신이 아닌 그림, 기록을 기다리거나 철회된 확인 지점: SCR-104#stale |
| 되풀이 | 같은 단계를 다시 고르면 같은 자세히 보기를 보입니다 |
| 동시성 | 자세히 보기에 닿지 않습니다: 아무것도 쓰지 않습니다 |
| 상한 | 1차처럼 처음 몇 항목과 "{n}개 모두 보기"가 보입니다. 확인 지점은 허브 페이지의 프로젝트마다 100개에서 멈추고 전체 수를 보입니다 |
| 바깥 서비스 | 사람 화면은 그 도구로 가는 링크이고 따로 열립니다. 자세히 보기의 나머지는 그대로입니다 |
| 자료 노출 | 허브 페이지가 이미 담은 것뿐입니다. 그림 자료는 허브 페이지에 절대 없습니다 |
| 빈 응답과 스트림 | 항목이 없는 단계: SCR-104#empty. 스트림은 없습니다 |
| 화면 상태 | 모든 상태를 320과 1440픽셀에서, [와이어프레임](wireframes.html#scr-104)에. 09단계에서 A 방향으로 그린 것은 [목업](../../09-mockup/nexus/mockup.html#scr-104)에 |
| AI 응답 | 없음: NEXUS는 AI 모델을 부르지 않습니다(REQ-121) |

## 배치

| 영역 | 320픽셀에서 | 1440픽셀에서 |
| --- | --- | --- |
| 자세히 보기 | 카드 안, 단계 줄 아래: 제목과 닫기, 그 아래 부분마다 그 상태, 확인 지점, 다음 행동, 그리고 따로 한 줄에 그 링크 | 1,200픽셀 열의 절반인 카드 안에 같은 차례로, 링크는 부분의 상태 옆에 |
| 사실, 점검, 항목 | 사실마다 이름 위에 값, 그 아래 점검과 항목을 줄로 | 이름 옆에 값, 그 아래 점검과 항목을 줄로 |
