## 크기·담당·완료 규칙

S=집중 작업 약 0.5일, M=1일, L=2일의 초기 추정입니다. 92개(S 29·M 54·L 9), 합계 86.5인일이며 달력 일정이나 AI 세션 소요 시간 보장이 아닙니다. 외부 권한·제공자 대기는 포함하지 않고 첫 전체 플로우 후 재추정합니다. 2일을 넘는 작업은 기존 ID를 보존하며 더 작게 나눕니다. backend·frontend·harness·QA·maintainer는 단일 책임 역할이며 실제 세션 담당은 착수할 때 지정합니다.

## 첫 구현 단위와 병렬 준비

첫 단위는 격리된 개발 환경의 소유자 세션·프로젝트 목록입니다. TASK-321~TASK-326·TASK-330·TASK-332~TASK-337·TASK-386~TASK-387로 원본·스키마·소유 경계·세션·오류·로그인/목록 화면을 연결합니다. 실제 OIDC가 준비되기 전의 픽스처 검증은 실제 로그인 완료로 표시하지 않으며 운영 우회 로그인은 만들지 않습니다. 이후 연결/게시 → 13가지 검토 → 대화/체크포인트 → 이전/전체 QA → 조건부 배포/발표 순서로 진행합니다. 의존성이 없는 준비는 병렬로 할 수 있지만 완료 조건은 넘기지 않습니다.

### 소유자 세션과 프로젝트 연결

격리된 Node 런타임에 소유자 세션, 프로젝트 목록·연결, 단계 개요, 공개 샘플 API를 구현했습니다. 로컬에서 서명한 OIDC 픽스처와 소유자 두 명으로 콜백 재사용, 세션 만료, CSRF, 중복 쓰기와 저널을 HTTP에서 확인했습니다. 개발 환경 Chromium에서 다섯 화면을 네 가지 화면 폭과 두 테마로 확인했고, 로그인 전 접근, 검색, 연결, 다른 소유자의 프로젝트 접근 거부, 로그아웃을 실행했습니다. 나머지 화면 상태와 보호된 제공자 설정은 진행 중입니다.

### 게시와 버전별 원본

게시 자격 증명의 범위, 등록된 기본 브랜치, 커밋 이력, Git blob과 일치하는 원본을 확인한 뒤 게시 요청을 받습니다. 첫 게시 동의, 보유 버전, 수신 결과, 복구 저널을 한 트랜잭션으로 갱신합니다. 지원 형식에서 다이어그램과 추적 ID가 있는 항목을 생성하고, 산출물·이력·미리 보기에서 게시 버전별 출처를 유지합니다. 개발 검사는 GitHub 픽스처를 사용했습니다. 공개 GitHub에서도 읽기 전용으로 기본 브랜치, 이전 main 커밋과의 이력 관계, WBS 원본을 확인했습니다. 운영 설정과 비공개 레포를 대상으로 한 검증은 진행 중입니다.

## 외부 선행 조건과 배포 조건

OIDC와 비공개 레포 읽기 권한은 보호된 환경에서 설정합니다. 사용자님이 세 레포의 Actions 시크릿을 설정한 뒤 TASK-399와 TASK-372를 확인했습니다. 새 Actions 실행의 `sent: true`, 커밋과 버전이 NEXUS 보유 상태와 일치합니다. [corthex](https://github.com/kodonghui/corthex/actions/runs/44227154412), [corthex-nexus](https://github.com/kodonghui/corthex-nexus/actions/runs/44214598862), [marong2](https://github.com/kodonghui/marong2/actions/runs/44219402663). 새 v2 전송과 hub-ref 변경에는 연결된 upstream·제품 PR과 정확한 고정 버전의 계약 검사가 필요합니다.

운영 전환은 실제 API 전체 응답·모든 유저 플로우의 브라우저 에이전트 QA·접근성·성능·악의적 HTML 격리·세 프로젝트 이전·전환 후 쓰기 복구·실제 사용자 체크포인트를 확인한 후에만 합니다. 기존 운영은 그때까지 유지합니다. 소스 재게시만으로 서버 전용 대화와 결정을 복구하지 않습니다. 삭제는 이 계획에 없으며 사용자님만 수행합니다.

## 계획 검사와 다음 단계
