# NEXUS v3: WBS

[English](wbs.md)

10단계는 승인된 기능 명세(04), API 계약(06), 화면 정의(08)를 작업으로 나눕니다. 작업마다 명세 줄, 닿는 오퍼레이션·테이블·화면, 앞선 작업, 담당 하나, 크기, 다른 사람이 확인할 수 있는 끝 조건이 있습니다. 번호는 TASK-413부터입니다(v2가 TASK-412까지 썼습니다).

크기: S는 Claude worker 한 명의 반나절, M은 하루, L은 이틀 정도입니다. 개발은 Claude worker(Opus 5.5 xhigh)가 끝까지 맡고, PR마다 Claude 리뷰를, 병합 직전에 Codex 리뷰를 한 번 받습니다. 관리자 작업은 결정입니다.

## 3. 열린 질문

질문마다 추천안이 있습니다. 1~4는 이 단계의 체크포인트에서 하나씩 물었고 2026-11-23에 저마다 추천안으로 답을 받았습니다. 5~7은 그 작업 때 관리자께 직접 묻습니다.

1. **런타임.** Node 24 LTS의 node:http와 node:sqlite, 런타임 의존성 없음, v2처럼 게이트 뒤. 대안은 Cloudflare Worker와 D1인데, 스키마는 맞지만 서버 옆에 백업 파일을 둘 수 없어요(SPEC-052).
2. **화면.** 서버가 주는 HTML·CSS·JavaScript 모듈, 프레임워크와 빌드 단계 없음(09단계 목업이 그렇게 쓰임). 프레임워크는 빌드 의존성을 더해요. 화면 작업의 "두 너비에서 맞음"은 에이전트의 브라우저 도구로 걸어 보고 PR에 적어요. 테스트에 헤드리스 브라우저를 넣는 것은 개발 의존성이라 먼저 여쭤요.
3. **그림 배치.** 층층 배치를 이 저장소 안에서 작성(TASK-420), 요소 300개까지. ELK나 dagre 같은 배치 라이브러리는 런타임 의존성이라 먼저 여쭤요.
4. **글꼴.** 디자인 토큰이 쓰는 두 글꼴 IBM Plex Sans KR·IBM Plex Mono를 고정한 글꼴 파일 사본과 라이선스(SIL Open Font License 1.1)와 함께 서버에서 내주기. 다른 사이트에서 불러오는 페이지가 없어요. 대안은 시스템 글꼴만 쓰기.
5. **배포 순서.** TASK-463에서 관리자께 직접 여쭤요. 운영 배포는 체크포인트 대리인의 위임 밖이에요. 관리자가 2026-11-24에 답했어요: v3를 새 주소에 먼저 올리고, v3를 확인한 뒤 v2를 꺼요.
6. **v2 데이터.** TASK-465에서 관리자께 직접 여쭤요. 삭제도 대리인의 위임 밖이에요. 관리자가 2026-11-24에 답했어요: v2 데이터는 백업과 함께 두고 아무것도 지우지 않아요. v3가 안정된 뒤 다시 여쭤요.
7. **도구 토큰.** TASK-467이 도구를 읽기 전에 관리자께 직접 여쭤요. Notion·Jira의 읽기 전용 토큰을 만들어 서버 환경에 넣는 일은 대리인의 위임 밖이에요.
