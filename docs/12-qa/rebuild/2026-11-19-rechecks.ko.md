## 인증된 개발 부하와 배포 QA

개발 환경에 배포한 후보는 `39a5a17a449862a00d3c194c0bdb43001ff9185e`입니다. 해당 애플리케이션과 계약에서 v2 테스트 117개, HTTP 동작 36개의 활성 응답 사례 282개를 검증했으며 응답 462건을 관측했습니다. 동일한 PR 코드에서 브라우저 에이전트가 8개 플로우의 사례 422건을 통과했습니다. 운영자 FL-134는 OVH의 보호된 복사본에서 기존 프로젝트 3개의 이전과 확인 응답을 받은 쓰기 2건의 복구를 검증했습니다. main 워크플로의 검사 9개가 모두 통과했습니다. [main CI](https://github.com/kodonghui/corthex-nexus/actions/runs/44383755883)

TC-1890은 실제 Cloudflare Access 개발 주소, 범위가 제한된 Access 쿠키와 서로 독립된 Chromium 컨텍스트 20개를 사용했습니다. 각 컨텍스트는 독립된 애플리케이션 인증 세션을 사용했고, OVH의 격리 SQLite에는 프로젝트 100개와 항목 86,200개를 구성했습니다. 워밍업 후 검토 화면 탐색 200회의 P95는 1,487.06 ms였고 질문 저장 200회의 확인 P95는 599.12 ms였습니다. SQLite를 다시 열어 확인 응답을 받은 기록을 모두 대조했고 자산 조회 400건이 브라우저 캐시를 사용했습니다. Access 인증이 없는 요청은 302를, Access 인증만 있고 앱 세션이 없는 요청은 401을 반환했습니다.

첫 실행은 쿠키 확인 요청에 표준 User-Agent가 빠져 요청 가로채기 방식으로 진행했습니다. 자산을 다시 전송했고 격리 앱에 도달하기 전 503 응답 2건을 받았습니다. 통과한 검토 198건의 P95는 2,893.42 ms였습니다. 쿠키 확인 요청을 수정한 두 번째 실행은 브라우저의 기본 쿠키 인증으로 검토 200회를 완료했고 실패는 0건이었습니다. 두 실행의 근거를 보존했습니다. [개발 NEXUS](https://nexus-dev.corthex-hq.com/)

OVH 리허설에서 프로젝트 범위의 읽기 전용 키로 실제 비공개 GitHub 원본을 검증했습니다. API는 변경된 원본을 거부하고 정확한 main 커밋을 확인했으며 재시도에는 같은 수신 기록을 반환했습니다. 미리 보기 격리, Orca 음성 확인과 실제 Google 소유자 매핑은 각각의 검증 근거를 보존합니다. 해당 후보의 사용자 QA 체크포인트를 NEXUS에서 검토합니다. [QA 단계](https://nexus.corthex-hq.com/p/corthex-nexus/rebuild/12-qa)
