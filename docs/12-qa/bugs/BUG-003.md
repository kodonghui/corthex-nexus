# BUG-003: Project stale test fails across a minute boundary

From: TC-176, SCR-144#stale, SPEC-035. Found on 2026-11-27.

Cause: The test calculates its expected read time after the page read, allowing a minute to turn between the two.

Reproduction: On `fad0adf`, run the stale test in `server/test/project-screen.test.js` with a temporary advancing clock whose reading for the expectation is one minute ahead of the first page read, and restore the first clock before the stale tick. On Linux, Node 24.22.3, the assertion got `09:30에 읽음` and expected `09:31에 읽음`. This is a controlled test, not a real browser walk.

Expected: The expected time is the time of the page read regardless of a minute boundary. Actual: The assertion fails although the page shows the earlier read time. Regression correction is not yet implemented or verified.

Environment: Linux, Node 24.22.3, disposable local test environment.

Trace ID: TC-176, SCR-144#stale, SPEC-035

Evidence: [Run report](../runs/qa-resume-2026-11-27.md) and reproduction above.
