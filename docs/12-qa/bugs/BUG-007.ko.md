# BUG-007: 공유 서버에서 단일 레이아웃 시간 테스트 결과가 달라짐

연결: REQ-070, TASK-420, `server/test/layout.test.js`. 발견일: 2026-11-27.

원인 가설: 테스트는 콜드 `layout()` 호출을 한 번씩 측정해 실제 경과 시간 1초와 비교하므로 서버 스케줄링과 동시 작업의 영향을 받을 수 있다. 원인은 아직 분리해 확인하지 못했으며, 배포된 브라우저의 제품 P95 요구사항은 별도 측정이다.

재현: 공유 Linux 서버에서 Node 24.22.3으로 `server/`의 `node --test`를 실행한다. 고정 PR 검사 중 세 번의 실행에서 300개 요소가 든 dense 그래프의 시간은 테스트 제한 1,000ms보다 긴 1,158ms, 1,034ms, 1,185ms였고 전체 1,035개 중 1,034개가 통과했다. 같은 전체 검사의 다른 실행들은 1,035개가 모두 통과했다. 서버 부하와 동시 검사가 있었으나 그것을 독립 변수로 제어하지는 않았다.

기대: 문서화된 테스트 조건에서 결과가 재현된다. 실제: 같은 테스트가 세 번 실패하고 다른 실행에서 통과했다. 수정과 부하를 제어한 회귀 검증은 아직 남았으며, 이 결과로 배포 환경 P95를 추론하지 않는다.

환경: 공유 Linux 테스트 서버, Node 24.22.3, 고정 PR 167의 `23261b1`/`3083d6c`와 병합 작업 트리, `e95fdbd`와 리뷰 작업 트리.

Trace ID: REQ-070, TASK-420

근거: 1,034/1,035였던 실행 두 번과 세 번째 실패를 위에 적었다. 커밋 `9d4c314`의 [GitHub Actions run 45997924280](https://github.com/kodonghui/corthex-nexus/actions/runs/45997924280)에서는 서버 전체 검사 1,035/1,035가 통과했다. 이는 별도 실행 환경이며 공유 서버의 원인을 입증하지 않는다.
