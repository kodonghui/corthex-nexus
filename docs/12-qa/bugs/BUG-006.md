From: SPEC-014, SPEC-049, API-242, API-243. Found 2026-11-27 on the first-group deployment of commit `c309688` behind Cloudflare Tunnel and an Access Bypass application. The local-only workaround does not let agents on other hosts or the push job send snapshots; severity S2 is proposed pending QA review.

Reproduction reported by the deployment coordinator: issue a live agent credential, send the same credential to API-243 through the public endpoint, then to the server's loopback endpoint. The public request answered 401 `access_missing`, logged as `no_credential`; the loopback request answered 404 `project_not_found`, indicating that admission accepted the credential. Never record the credential, actual addresses or private paths in the evidence.

Expected: the public agent request reaches the server with the credential and API-243 returns its authenticated result. Actual: the public request did not carry the pair as seen by admission. The point and reason for header removal are not yet independently isolated; Cloudflare documentation identifies those names as its own service-token headers but does not establish that Bypass strips them. A routing, proxy or client configuration difference remains possible.

Cause-stage hypothesis: the stage-06 API contract assumes that the selected credential headers reach the origin through the production gate. Confirm this against the gate and correct the earliest affected source before implementation. Do not claim a root cause until a controlled paired test isolates it.

Escape: local pinned-hub integration does not exercise a real Cloudflare Access Bypass path. Add an authenticated external push and a missing, wrong and revoked credential check to deployment QA, including the adjacent owner operations. The stage-12 gate had not been completed before the maintainer's first-group deployment instruction.

Regression: not yet written; require a failing external gate test and passing results on both the public route and loopback, without recording secrets, before marking fixed. A temporary loopback address is limited to agents on the same host and is not a fix for remote agents or CI.
