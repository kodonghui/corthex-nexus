# BUG-006: Single-run layout timing check varies on a shared host

From: REQ-070, TASK-420, `server/test/layout.test.js`. Found 2026-11-27.

Cause hypothesis: the test times each cold `layout()` call once against a one-second wall-clock bound, so host scheduling and concurrent work may affect its result. The cause has not been isolated; the product's deployed-browser P95 requirement is a different measurement.

Reproduction: Run `node --test` in `server/` on the shared Linux host with Node 24.22.3. In two runs during the pin PR checks, the dense graph's 300-element layout took 1,158 ms and 1,034 ms against the test's 1,000 ms limit, and the suite reported 1,034/1,035 tests passing. Other runs of the same suite passed 1,035/1,035. Host load and concurrent checks were present; they were not controlled as an independent variable.

Expected: the test gives a reproducible result under the documented test conditions. Actual: the same test failed twice and passed in separate runs. A correction and a regression check under controlled load remain open; do not infer deployed P95 from these results.

Environment: shared Linux test host, Node 24.22.3, product pin PR 167 on `23261b1`/`3083d6c` and its merge working tree.

Trace ID: REQ-070, TASK-420

Evidence: [Interim release gate PR 168](https://github.com/kodonghui/corthex-nexus/pull/168) records both measurements and the passing rerun; PR 167's review follow-up records them too.
