From: TC-169, SCR-143#stale, SPEC-049, API-279#default. Found 2026-11-24; original evidence and run history are in section 6 of the test plan.

Cause: The test computed the expected read time after the screen's first read, so a minute boundary changed the expected text. The screen showed the correct read time.

Reproduction: On base `fad0adf`, control `Date.now` so the first read occurs at 16:01:59 and the expectation is calculated at 16:02:59. Run `node --test test/projects-screen.test.js` in `server/`. The original assertion failed with actual `16:01에 읽음` and expected `16:02에 읽음`.

Correction: The test fixes the clock before the first read and uses that instant for the expectation. It checks that a failed reread retains rows and the original read time, and that a successful reread clears the error and records a new read time. On the corrected working tree the same controlled boundary passed, with 26 of 26 tests in the file passing on Node 24.22.3 on Linux. At that time the status remained open pending merge.

Status: Fixed by PR 165, merged as c309688.
