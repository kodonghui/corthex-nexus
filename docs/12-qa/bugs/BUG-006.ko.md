연결: SPEC-014, SPEC-049, API-242, API-243. 2026-11-27 Cloudflare Tunnel과 Access Bypass 앱 뒤의 첫 그룹 배포 커밋 `c309688`에서 발견했다. 로컬 우회로는 다른 호스트의 에이전트와 push 작업이 스냅샷을 보낼 수 없으므로 QA 검토 전 심각도 S2를 제안한다.

배포 코디네이터가 보고한 재현: 유효한 에이전트 자격을 발급하고 같은 자격으로 공개 엔드포인트와 서버 루프백 엔드포인트의 API-243에 요청한다. 공개 요청은 401 `access_missing`, 로그 사유 `no_credential`이었고 루프백 요청은 404 `project_not_found`로 자격 검사를 통과했다. 자격, 실제 주소, 비공개 경로는 증거에 기록하지 않는다.

기대: 공개 에이전트 요청이 자격을 서버에 전달하고 API-243이 인증된 결과를 반환한다. 실제: 서버의 인증 검사에는 공개 요청의 자격 쌍이 도달하지 않았다. 어느 지점에서 어떤 이유로 헤더가 사라지는지는 독립적으로 확인하지 못했다. Cloudflare 문서는 해당 이름을 자체 서비스 토큰 헤더로 정의하지만 Bypass에서 제거한다고 명시하지 않으며 경로, 프록시 또는 클라이언트 설정 차이도 가능하다.

원인 단계 가설: 06단계 API 계약은 선택한 자격 헤더가 실제 게이트를 통과한다고 가정한다. 통제된 비교로 원인을 확인하고 구현 전에 영향을 받은 가장 이른 원본을 수정한다.

누락 분석: 고정 hub의 로컬 통합 테스트는 실제 Cloudflare Access Bypass 경로를 거치지 않는다. 배포 QA에 외부 인증 push와 자격 누락·오류·폐기, 인접 소유자 작업 확인을 추가한다. 첫 그룹 배포는 관리자의 지시에 따라 12단계 게이트 완료 전에 진행됐다.

회귀 테스트: 아직 작성하지 않았다. 수정 완료 전에 실제 외부 게이트에서 실패를 재현하고 공개 경로와 루프백의 성공을 비밀 노출 없이 검증한다. 임시 루프백 주소는 같은 호스트의 에이전트에만 적용되며 원격 에이전트나 CI의 해결책이 아니다.
