# NEXUS: test plan

[한국어](nexus.ko.md)

Stage 12 of CORTHEX’s own project. Status: planned on 2026-11-03; no case has run under this plan yet. English is the source and the Notion case database follows it. Inputs are stages 02–09, especially each active SPEC acceptance criterion, named OpenAPI response, hub command outcome and screen state. Phase-② editing/workshop flows FL-115/FL-116 are deferred with SPEC-134/SPEC-142.

## How to read this file

`ID` is permanent, starting at TC-601; BUG starts at BUG-501. `From` is the acceptance criterion, API response, SCR state or REQ under test. `Task` writes/runs the case in its finishing PR. `Runs as` names the actual method. `Steps` describes the fixture/action, `Expected` includes the response and effects and `Last result` names environment, commit and evidence when run. not run means not run. A response example checked only with Prism is counted separately from development evidence.

## Where the cases run

- Server: Node built-in tests with in-memory SQLite/D1, Wrangler local D1, then corthex-nexus-dev behind Access. Contract tools live outside the repository: openapi-spec-validator 0.7.1, Prism 5.16.0, Schemathesis 3.39.16 with experimental OpenAPI 3.1.
- Hub: standard-library unittest, isolated home/project and fake local HTTP; Python 3.8 and latest on Linux/macOS/Windows, including real Git object fixtures.
- Views: Prism first, then the real development Worker; browser agents use Aside CLI where available, otherwise a named host browser tester. Start three isolated browser sessions and measure safe concurrency before increasing. No production writes.
- Every state: 320/1440 pixels, light/dark and English/Korean; page-check.js measurements and separately inspected screenshots.
- Credentials remain in this host’s secret store/environment. Access evidence records presence/empty only. Synthetic data is seeded per role and tester; this repository is never pushed without REQ-107 consent.
