# NEXUS v3 QA: 임시 릴리스 게이트

[English](interim-release-gate-2026-11-27.md)

추천은 첫 그룹을 포함해 **no-go**다. 이는 QA 계획과 로컬 검증의 임시 판정이며 릴리스 커밋의 게이트는 아니다. [QA 초안 PR 166](https://github.com/kodonghui/corthex-nexus/pull/166)의 커밋 `5d7184b`에 있는 계획의 243개 케이스는 당시 pass 206, not run 36, blocked 1이었다. GitHub OAuth의 `workflow` 권한이 추가돼 PR 167의 hub 워크플로 변경을 푸시할 수 있게 됐고 TC-221이 hub `1becbab`을 쓴 NEXUS PR 167 커밋 `6145f53`에서 예비 통과하고 `e95fdbd`와 `fc621d3`에서 다시 통과했다. 이후 PR head `657ef23`의 [GitHub 실행 46012385489](https://github.com/kodonghui/corthex-nexus/actions/runs/46012385489)에서 새 `e6b46ac` 고정의 source-path 검사도 통과했으며 최종 고정 head에서 다시 확인해야 한다. 그 PR이 병합 전이어서 TC-221은 미실행으로 두며 QA PR 166의 커밋 `71bc506` 기준 현재 pass 206, not run 37, blocked 0이다. 다수의 pass는 이전 커밋의 증거이므로 릴리스 커밋에서 다시 확인해야 한다. waiver는 없다. 제안된 S2/P1 BUG-008은 공개 경로 재검증이 통과됐다고 보고됐으며 PR 169의 원본 상태 갱신 전까지 기록상 열려 있다. S3 발견 사항 5건 BUG-002~005와 BUG-007은 [QA 버그 파일](../bugs/)에서 열려 있다. BUG-001은 PR 165에서 수정·병합됐고 QA 초안 커밋 `bc3a3d0`에 반영됐다.

## BUG-008: 재검증 통과, 원본 갱신 대기

[BUG-008](https://github.com/kodonghui/corthex-nexus/pull/169)은 공개 경로의 에이전트 요청이 실패해 S2/P1로 제안됐다. 서버 대체 헤더 수정은 PR 170(`0a6b152`), hub 수정은 [하네스 PR 228](https://github.com/kodonghui/corthex/pull/228)의 `e6b46ac`에 병합됐다. 로컬 자격 회귀는 `71bc506`에서 통과했다. 코디네이터는 2026-11-27 16:10 UTC에 hub `e6b46ac`과 v3 프로필로 공개 경로를 재검증했다고 보고했다. can-send는 true, 서버 보유 커밋 조회는 200, 실제 프로젝트 push는 outcome done과 pushSnapshot 200이었다. 소스 커밋이 이미 최신이라 보유 revision은 1로 유지됐으며, 보고된 추적 메타데이터로 공개 엣지 경로를 확인했다. 이 문서에는 주소·자격 값·프로젝트 식별자를 적지 않는다. 요청된 재검증은 통과했으므로 PR 166 병합 뒤 PR 169에서 12단계 BUG-008 원본을 갱신하고 닫는다. 그 원본 갱신이 병합되기 전까지 정식 기록은 열려 있으므로 임시 게이트를 다시 대조해야 한다. TC-244는 PR 169에 예약됐고 위 243개 집계에는 포함되지 않는다. 원래 헤더 실패의 정확한 원인은 아직 분리되지 않았다.

PR 167은 새 hub 고정을 제안한다. 현재 push 작업은 v2를 위해 기존 CF-Access 헤더 쌍을 유지하며, 나중에 v3로 전환할 때 override를 빼고 URL과 자격 비밀값을 v3 것으로 바꿔야 한다.

## 차단 항목

BUG-008은 PR 169의 원본 종료가 병합되기 전까지 정식 게이트 차단 항목이며, 위 재검증 통과는 종료를 위한 근거다.

게이트 케이스 8개 TC-225, TC-226, TC-227, TC-230, TC-231, TC-233, TC-234, TC-235는 필수 브라우저 흐름 검증이 남았다. 계획에 적힌 화살표·역할·너비별 스크린샷과 데이터 확인이 필요하다. 이 항목들은 첫 그룹도 막는다. 로컬 합성 화면 캡처는 일부 상태만 다루므로 이 케이스들을 끝내지 못한다. 격리된 로컬 환경에는 실제 휴대폰과 실제 Access 로그인·만료 경로가 없었으며 테스트 게이트는 그 결과를 입증하지 못한다.

PR 169에는 화면 흐름 선행 조건 8개가 미완료인 상태에서 별도의 첫 그룹 배포가 보고됐다. 이는 계획에 적힌 게이트 순서와 달랐으며, 이 보고서만으로 그 배포에 대한 별도 승인을 확인할 수는 없다. 최종 게이트 전에 그 경위와 별도 승인이 있었다면 그 내용을 프로젝트 기록에 남겨야 한다. 나머지 게이트 11개 TC-037, TC-038, TC-097과 TC-205~212는 배포 또는 운영 환경에서의 시간이 필요하며 여기서는 아직 검증하지 않았다. 계획대로 다른 차단 항목이 통과하거나 메인테이너가 각 항목의 waiver를 기록한 뒤 첫 그룹에만 go를 물을 수 있다. 이 11개는 첫 그룹 배포에서 실행하며, 각 증거가 통과할 때까지 전체 릴리스는 보류한다. BUG-005에는 TC-212가 기대하는 백업 안내와 화면 정의의 충돌이 기록돼 있어 케이스를 닫기 전에 기대 결과를 정리해야 한다. 이 보고서는 배포, 실제 저장소 업로드 또는 기존 서비스나 데이터 삭제를 승인하지 않는다.

## 알려진 위험

통과하지 못한 비게이트 케이스는 18개다. 각각의 후속 확인은 계획에 남아 있다.

- TC-198, TC-199: 목표 환경의 P95 성능 측정이 필요하다.
- TC-200, TC-201, TC-202: 브라우저 버전·디자인·접근성 범위가 미실행이다.
- TC-213: 실제 읽기 전용 외부 도구 상태는 배포 환경과 적절한 자격이 필요하다.
- TC-221: 이전 `1becbab`과 새 후보 `e6b46ac`의 source-path 예비 검증은 통과했지만 고정 PR은 병합 전이며 최종 고정 head를 확인해야 한다.
- TC-228, TC-229, TC-232, TC-236, TC-237: 해당 흐름 전체 검증이 미실행이다.
- TC-238~242: 화면 상태와 목업 전체 비교가 미실행이며 TC-240도 BUG-005의 백업 안내 기대 결과 충돌이 남아 있다. 일부 로컬 상태 증거는 [실행 보고서](qa-resume-2026-11-27.ko.md)에 있다.
- TC-243: 실제 휴대폰 읽기와 댓글 검증이 미실행이다.

공유 호스트에서 `server/test/layout.test.js`의 단일 콜드 실행 시간 테스트가 제한 1,000ms보다 긴 1,158ms, 1,034ms, 1,185ms로 세 번 실패했고 같은 전체 검사의 다른 실행들은 통과했다. 실패는 PR 167의 `23261b1`과 `3083d6c` 및 병합 작업 트리, `e95fdbd`와 리뷰 작업 트리에서 관찰됐다. 원인은 아직 확인하지 못해 QA PR 166의 [BUG-007](../bugs/BUG-007.ko.md)에 테스트 결함 가설로 기록했으며, 테스트를 완화하거나 제품 결함으로 단정하지 않았다. 이 결과로 목표 환경의 P95를 입증할 수는 없다.

이 보고서는 QA PR 166에 의존한다. 그 계획과 버그 기록이 12단계 원본이며 보고서보다 먼저 병합돼야 한다. 로컬에서 제어한 인증 게이트·API 거절·응답 손실 테스트는 로컬 증거이며 배포된 Access나 외부 제공자 경로의 증거가 아니다. 선택 단계인 AI 탐색 테스트는 실행하지 않았고 게이트 항목이 아니다. go/no-go 판단 전 정확한 릴리스 커밋에서 숫자, 버그 상태, 고정 테스트, 화면 증거와 열린 리뷰 스레드를 다시 확인한다.
