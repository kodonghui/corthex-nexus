# QA 재개: 2026-11-27 로컬 검증

제품 기준은 `fad0adf`이며 새 검증 assertion은 그 기준의 커밋 전 작업 트리에서 실행했다. hub 체크아웃은 정확한 고정 커밋 `e410ce9efac70f7543a8b5cbfe6774c6138133d6`이다. Node 24.22.3 로컬 서버는 loopback에서만 수신했고 임시 저장소와 합성 자격을 썼다. hub 테스트는 로컬 서명 테스트 게이트를 썼다. 브라우저는 허용형 합성 게이트를 썼으므로 Access나 배포 환경의 인증을 검증하지 않는다. 운영 서비스와 데이터는 사용하지 않았다.

이 환경에서 기존 `tests/test_hub_run.py`의 두 테스트가 통과했다. 추가 `tests/test_hub_qa_resume.py` assertion도 통과했다. TC-215의 교환은 양쪽 세션의 409 보유자, 해제, 두 번째 세션의 claim과 reply, 저장된 reply 한 개, 이후 첫 세션의 claim을 확인했다. TC-218은 remove가 미리보기를 돌려준 뒤에도 프로젝트를 읽을 수 있음을 확인했고 탐색 실행에서 스레드 show도 성공했다. 이후 제품 커밋 c9bc63f와 테스트 작업 트리에서 comment, proposal, edit, checkpoint 각각의 show도 통과했고 삭제 후 프로젝트가 그대로 남았다. TC-215와 TC-219의 assertion도 이 커밋에서 재실행해 통과했다. TC-219는 revision 1 미리보기 뒤 revision 2를 보내고 이름만으로 삭제한 다음, --first 없는 재전송은 거절과 404 유지, --first 전송은 revision 1로 재생성을 확인했다. TC-221은 이 검증에서 아직 실행하지 않았으며 TC-221은 별도의 hub 0.6.0 고정이 먼저다.

Orca 브라우저가 `browser_unavailable`을 반환해 기존 Playwright와 Chromium을 사용했고 운영체제 라이브러리는 임시 폴더에 풀었다. `fad0adf`에서 합성 프로젝트와 자격을 임시 데이터베이스에 직접 넣었다. 1440과 360 CSS 픽셀 모두 프로젝트 화면에 해당 프로젝트와 자격이 보였고 프로젝트 API는 revision 1, 통과 단계 0, 할 일 0과 200을 반환했다. 프로젝트와 자격이 각각 하나여서 여러 항목의 정렬을 확인하지 못한 TC-164 부분 증거다. 할 일 API는 항목 없는 200을 반환했고 두 너비에서 빈 메시지와 프로젝트가 보였다. 신규 설치 분기는 보지 않아 TC-160 부분 증거다. 프로젝트 API는 200을 반환했고 두 너비에서 보낸 내용 없는 13단계가 보였다. fixture에는 스냅샷이 있고 별도의 빈 공간 시나리오는 실행하지 않아 TC-173 부분 증거다. [스크린샷 여섯 장](evidence/qa-resume-2026-11-27/)을 참고한다. 부분 증거로 화면 케이스를 새로 통과 처리하지 않는다.

시계를 제어해 서로 다른 stale 테스트의 경쟁 조건 세 개를 재현하고 BUG-002, BUG-003, BUG-004로 기록했다. 테스트 수정과 회귀 검증은 아직 남았다. 이 제어 테스트는 브라우저나 배포 환경의 증거가 아니다. 계획의 나머지 화면 상태, hub 케이스와 릴리스 게이트는 이번 실행에서 아직 확인하거나 판정하지 않았다.
