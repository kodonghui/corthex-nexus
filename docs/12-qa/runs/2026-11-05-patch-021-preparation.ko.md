# NEXUS 0.2.1 준비 시점 기록

[English](2026-11-05-patch-021-preparation.md)

0.2.1 운영 전환 전의 소스 준비 시점 기록입니다. 유지관리자가 패치 출시와 남은 원래 흐름 검사를 승인했고, 2단계는 계속 대기합니다. 앞선 [출시 뒤 마무리](2026-11-05-postrelease-closeout.ko.md)의 실패와 부분 판정은 과거 근거로 보존합니다.

[적용 여부 정정](2026-11-05-api-example-applicability-021.ko.md), 제품 PR [44](https://github.com/kodonghui/corthex-nexus/pull/44)는 원래710건을626통과/66부분/18해당 없음/0실패로 보존하고 별개 실제 HTTP 사례7건을 더했습니다. 이 시점717건의 원장은633통과/66부분/18해당 없음/0실패입니다. 새 브라우저·네이티브 관측은 아직 이 집계에 올리지 않았습니다. WBS도 전체 완료 조건을 판정할 때까지64개 중44완료/20진행입니다.

## 출시와 근거의 경계

이 시점0.2.1은 소스 후보이며 태그와 운영 전환은 아직입니다. 실행 중인0.2.0은 앞서 검토한 제품 런타임과 같습니다. 현재13테이블 SQLite DB가 정본입니다. 패치는 현재 일관 백업을 만들고 같은 서버 안의 복원본으로 두 런타임을 확인한 뒤 실행 파일만 전환합니다. 준비한 복구도 실행 시점의 최신 DB를 보존하며 옛 Worker/D1 스냅샷으로 바꾸지 않습니다.

실제 네이티브 호스트의 명령·파일 편집, 합성 비공개 저장소 한 곳의 형식화된 GitHub 동작, 생성 역할의 Node/SQLite HTTP, Prism 응답, 브라우저 계측, 이미지 검토, 실제 Access 관측은 근거를 구분합니다. 비공개 저장소 식별자·호스트 경로·실행 프로필·인증은 공개 기록 밖에 둡니다. 제공자나 실제 로그인 절은 유지관리자의 명시적 한정 결정 없이 모의 근거로 통과시키지 않습니다. 개발 환경 Access 기간 질문과 남은 제공자 근거 질문은 별개입니다.

## 배포 전 원래 화면 기준의 추가 교정

마지막 TC-1257 걷기에서 기존 SCR-109 정상 상태의 누락 두 곳을 더 찾았습니다. BUG-589는 비어 있지 않은 세 목록 위에 명시된 “What is left”/“남은 것” 제목을 복구합니다. BUG-590은 기록된 각 확인 지점의 필수 `approved`·`by`·날짜와 기존의 안전한 선택 링크를 표시합니다. 이전 렌더러는 이 DTO에 없는 `words`를 읽어 날짜·링크만 보였습니다. 기록은 일반 텍스트로 표시하고 날짜만 있는 원값을 보존합니다. 화면 기준·API/기록 스키마·고정 CSS 바이트는 바꾸지 않습니다.

브라우저의 원래 실패 관측과 고친 소스를 구분합니다. 새 회귀시험은 두 언어, 빈 목록·비어 있지 않은 목록, 복수 확인 지점, 선택 링크와 신뢰하지 않는 승인 내용·작성자 텍스트를 다루며 브라우저 확인은 따로 기록합니다. 먼저 준비한 태그를 이 후속 수정의 운영 반영 근거로 보지 않습니다.

TC-1259는 개요의 그림 링크에 저장된 `not_current` 사유가 빠지는 BUG-591도 드러냈습니다. 크기·원본 사라짐·다른 저장소의 세 상태에 기존 링크용 문구를 해당 링크 옆에 표시하고 최신 그림에는 경고를 붙이지 않습니다. 따로 검증한 그림 보기의 렌더링과 API는 그대로입니다.

TC-1230 전환 검사는 ERD 미리보기의1.25배 확대가1.0배가 되고 소수 확대 비율은 편집기가 나타날 때만 반올림되는 BUG-592를 찾았습니다. SVG 조작과 편집기 이동이 고정된 편집기의 지원 범위0.1~1.5·소수 두 자리 정밀도를 함께 사용합니다. 맞춤·확대 때 최종 지원 비율로 원점을 계산해 화면 중앙 아래의 원본 좌표를 보존하고, 기존 뷰포트 연결은 고정 패키지의 범위 상수를 사용합니다. DDD·사이트맵의 기존 범위·정밀도와 의존 버전·상류 패키지 원본·서버 프로토콜·고정 CSS는 그대로입니다. 원래 카메라 경고와 별도의 편집기 표 너비 관측을 보존하며 표시점의 오른쪽 끝만으로 카메라를 판정하지 않습니다.
