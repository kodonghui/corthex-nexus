## BUG-562 stays open

The historical DDD code response took 56.00534 s from headers to completion on a Brotli HTTP/2 edge HIT. One ERD opening had no completed code response within 90 s. On 2026-11-06 KST, development still ran `906f360` and the D802 browser assets. The 443 asset payloads and the original 300-node Korean sources matched. The new browser batch interleaved six DDD and six ERD openings at 390×844, DPR 2.75, touch, CPU 1× and Fast 4G (165 ms, 8.1/1.35 Mbps). Each opening started with a new profile and incognito context, with browser cache disabled and service workers bypassed. All 12 openings and their 144 measured code requests completed within the 90 s opening limit. [Historical transport record](2026-11-04-transport-investigation.md)

The cache HIT delays show that long body transfer can occur downstream of the origin and Tunnel and outside Chrome. Edge delivery and the client network remain unresolved within that interval. The original 56 s and 90 s outcomes did not recur. The lanes use independent clocks, and the new ranges are diagnostic samples. The origin, Access and cache settings used for the reproduction stay as observed. A product change for BUG-562 needs a verified cause.

## BUG-559 native whole-picture fit

NEXUS lowers the Excalidraw minimum to 0.1% through a source-checked patch to the pinned build and shares the lower limit with the stage camera. The Windows picture suite exercised one root and 299 child screens, a 560×47,800 scene. At viewport widths of 390 and 1440 px the SVG handed off to the native canvas. Whole picture fit at approximately 0.954%, with 24 px above the first node and below the last node in the 504 px frame.

## Windows browser runner

Each run owns its Chrome profile as a direct child of its generated artifact folder. The Windows launcher assigns Chrome to a private Job before resuming it. Cleanup waits until the Job has no active processes and validates the profile path before removal. The first candidate ran the picture suite and stopped at discussion because the report still referenced the previous launcher variable. After correcting those references, Windows Chrome completed 54 checks in all eight suites in 176.026 s. All eight new profiles were removed. [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
