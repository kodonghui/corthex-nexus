# NEXUS 0.2.2 편집기 검증

[English](2026-11-06-patch-022-editor.md)

## BUG-562 조사 계속

과거 DDD 코드 응답 1건은 Brotli HTTP/2 엣지 HIT에서 헤더부터 완료까지 56.00534초가 걸렸습니다. ERD 1건은 90초 안에 코드 응답 완료를 관측하지 못했습니다. 2026-11-06 KST 개발 서버는 같은 `906f360`과 D802 브라우저 자산을 실행 중이었습니다. 자산 443개와 기존 한국어 300노드 그림 원본을 대조했습니다. DDD와 ERD를 6번씩 번갈아 열었으며, 390×844, DPR 2.75, 터치, CPU 1배, Fast 4G(165ms, 하향 8.1Mbps·상향 1.35Mbps)를 적용했습니다. 매번 새 프로필과 시크릿 컨텍스트를 열고 브라우저 캐시를 끄고 서비스 워커를 우회했습니다. 12번 열기와 계측 대상 코드 요청 144건은 모두 열기 한도인 90초 안에 완료됐습니다. [이전 전송 기록](2026-11-04-transport-investigation.ko.md)

Cloudflare 캐시가 응답한 HIT에서도 브라우저 밖에서 코드 본문 지연을 확인했습니다. 엣지 응답 전송과 사용자 쪽 회선 중 어느 쪽인지는 특정하지 못했습니다. 기존 56초·90초 사례는 재현되지 않았습니다. 구간마다 별도 시계로 측정한 진단 범위이며, 제품 변경은 원인이 확인된 뒤에 판단합니다.

## BUG-559 내장 편집기 전체 맞춤

고정 Excalidraw 빌드에 원본 해시를 확인하는 패치를 적용해 최소 배율을 0.1%로 낮추고 단계 화면과 같은 하한을 씁니다. Windows에서 루트 1개와 자식 화면 299개로 만든 560×47,800 그림을 시험했습니다. 390px·1440px에서 SVG가 내장 캔버스로 넘어갔고, 그림 전체 버튼은 504px 프레임에서 약 0.954%로 맞췄습니다. 첫 노드 위와 마지막 노드 아래에 각각 24px이 남았습니다.

## Windows 브라우저 시험

각 실행이 생성한 결과 폴더의 바로 아래에 Chrome 프로필을 만듭니다. Windows에서는 시작을 잠시 멈춘 Chrome을 전용 Job에 넣은 뒤 실행합니다. Job의 모든 프로세스가 종료되고 경로 검증을 통과한 프로필을 정리합니다. 첫 후보는 그림 시험을 마쳤지만 보고서에 이전 실행부의 변수 참조가 남아 토론 시험에서 멈췄습니다. 참조를 고친 뒤 Windows Chrome에서 8개 묶음의 54건이 176.026초에 통과했고, 새 프로필 8개가 모두 정리됐습니다. [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
