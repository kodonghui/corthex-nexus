[한국어](test-plan.ko.md)

Stage 12 turns the approved user flows (03), functional spec (04), API contract (06), screen definitions (08) and non-functional requirements (02) into test cases and records what each case's run showed. This first version maps every case and takes its status from the tests that already run on every pull request, at commit fd85323. At fd85323, the browser walks, the pinned hub runs not yet pinned in a test and the cases on the real server were planned and not run. Later local runs and their limits are recorded below.

### 1.3 How a response counts as fired

Each operation's API test records every answer the real server gives it. Its check, `assertEvery` in `server/test/responses.js`, passes only when every status and every Problem code the operation lists came back and matched the contract's schema. The `default` response (500 `internal`) comes from a store made to fail on purpose: controlled fault injection on a throwaway store. No response is counted from the mock server: mock-only responses, 0. The screen tests replay the real server's answers to the page.

### 1.4 Forced runs

The daily backup and the removal of backups past 30 days (FL-011, SPEC-052) run in the tests with a test clock and by hand. That checks their logic, is marked forced in Run evidence and counts as not run for the gate. Their unforced check is the real server running more than a day (section 2.7).

### 1.5 Roles and data

The roles are the owner (the one user, signed in through the gate), the agent (a hub with a live agent credential), another person (signed in through the gate but not the owner) and no sign-in. The tests make their own throwaway store, sign-ins and credentials; no case uses a real credential or a paid service. NEXUS calls no AI model (section 5 of the functional spec).
