# NEXUS 재설계 워크플로

[한국어](README.ko.md)

사용자님은 2026-11-17에 13단계를 새로 진행하도록 요청하셨습니다. `/corthex:corthex`로 시작하고 아래 표의 스킬로 각 단계를 라우팅합니다. 현재 부분은 `rebuild`이며, `nexus`는 기존 참고 자료입니다. 이 문서는 워크플로 기록이며 10단계 WBS나 체크포인트 생략 허가가 아닙니다.

| 단계 | 라우팅 스킬 | 필수 산출물 |
| --- | --- | --- |
| 01 도메인 탐색 | `corthex-discover` | Miro 이벤트 스토밍, 타임라인·컨텍스트 경계·컨텍스트 표와 맵을 각각 체크포인트에서 검토 |
| 02 PRD | `corthex-define` | 새 도메인 모델에서 도출하고 추적 ID를 부여한 요구사항 |
| 03 유저 플로우 | `corthex-define` | 요구사항과 연결한 모든 유저 플로우와 예외 |
| 04 기능 명세 | `corthex-define` | 기능 동작·권한·인수 기준 |
| 05 ERD | `corthex-contract` | 추적 관계와 마이그레이션 제약을 포함한 데이터 모델 |
| 06 API 계약 | `corthex-contract` | 오류·동시성·버전 동작을 포함한 OpenAPI 계약 |
| 07 사이트맵 | `corthex-screen` | 화면·경로·내비게이션 |
| 08 화면 정의 | `corthex-screen`, `corthex-uxui` | 빈 상태·로딩·오류·권한 상태를 포함한 모든 화면 상태 |
| 09 목업 | `corthex-screen`, `corthex-uxui` | 여러 후보, 선택한 하나의 방향, 라이트·다크 테마, Git에 커밋한 인터랙티브 HTML |
| 10 WBS | `corthex-build` | 자체 체크포인트를 갖는 의존 순서 기반의 새 작업 계획 |
| 11 개발 | `corthex-build` | 승인된 계획·계약에 맞춘 구현 PR |
| 12 QA | `corthex-build` | 브라우저로 모든 플로우 실행, 마이그레이션·복구·남은 한계 기록 |
| 13 발표 | `corthex-present`, `corthex-uxui` | 검증한 제품 동작과 남은 한계에 근거한 발표 |

각 초안 또는 체크포인트 단위는 PR로 커밋하고, 필수 검사 뒤 default branch에 병합한 다음 `hub.py push`로 보내고 `--asks checkpoint`로 검토를 요청합니다. 통과는 사용자님만 NEXUS에서 수행합니다. 단계 내부 체크포인트도 유지합니다. 01단계는 Step 1-b·7·9 뒤에 멈춥니다. 첫 통과 뒤에도 마지막 체크포인트를 기록하기 전까지는 `in_progress`입니다.

새 부분의 단계 소스는 각 단계를 시작할 때 설정합니다. 기존 파일은 참고 자료이며, 경로를 바꿨다고 새 승인 산출물이 되지 않습니다. 새 컨텍스트·용어 ID는 합의했을 때만 기존 ID 다음부터 부여합니다. 과거 결정을 보존하고 대체 관계와 이유를 프로젝트 Notion DB 행에 기록합니다. 비공개 작업 공간 링크는 공개 레포에 넣지 않습니다.

새 제품의 QA와 배포가 끝날 때까지 이번 설계 작업으로 운영을 바꾸지 않습니다. 스냅샷 재게시만으로 서버의 댓글·답변·체크포인트를 복원할 수 없으므로 호환되는 마이그레이션·복구 경로로 보존합니다. 브라우저 자동화로 실제 프로젝트를 삭제하거나 체크포인트를 통과시키지 않습니다. 최초 업로드는 사용자님의 별도 동의가 필요하며 CI가 이를 대신하지 않습니다.

현재 상태: 01단계의 [체크포인트 1 초안](../01-domain/rebuild.md)을 레포에서 검토할 수 있으며, 이후 단계는 `.corthex/stages/rebuild.json`에 `not_started`로 기록했습니다. 기존 단계 기록은 `.corthex/stages/nexus.json`에 원래 이력과 함께 남깁니다. 이 기록으로 런타임·토큰·기존 디자인을 새 아키텍처로 선택하지 않습니다.
